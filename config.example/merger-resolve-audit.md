# 풀이 감사 {lane} — 병합기가 띄움 ({name}, 읽기 전용)

보고는 한국어로. 병합 쪽 에이전트가 rebase 충돌을 풀었다. **풀이만 본다** — 원래 변경 전체는 레인 감사가 이미 봤다. 질문 창을 띄우지 않는다.

- 작업 트리: `{worktree}` · 기준 `{base_sha}` · 원래 제출 `{sub_sha}` · 풀이 `{resolved}`
- 충돌 파일: {conflicts} · 준비 글: `{context}`
- 풀이가 바꾼 것(충돌 표시가 든 자동 합침과 풀이의 차이): `git -C {worktree} diff {auto_tree} {resolved}`

## 할 일
1. 위 diff의 충돌 구간마다: **양쪽의 뜻이 모두 살아 있는가**, **한쪽이 사라지지 않았는가**(기준 쪽 변경 `git log -p {sub_sha}..{base_sha} -- <파일>`과 제출 쪽 변경 `git log -p {base_sha}..{sub_sha} -- <파일>`을 대조).
2. 충돌 구간 밖이 바뀌었으면(자동 합침과 다른 곳) 지적한다 — 풀이 밖을 고치면 안 된다.
3. 시험은 작업 트리를 바꾸지 않는 명령만, 시간 제한을 두고 돌린다. 코드 수정·커밋·push 금지.
4. 등급: 높음(한쪽 뜻이 사라짐·데이터 손실·깨진 동작) · 중간(풀이 밖 변경·빠진 시험·애매한 합침) · 낮음.
5. 보고서는 `{report}`에 쓴다.
6. 마지막에 정확히 이 꼴로 한 줄을 쓴다(숫자만 바꾼다 — 판정 ID `{audit_id}`가 이 감사의 것일 때만 받는다):
   `printf '감사 완료 {audit_id} 높음 <n>·중간 <n>·낮음 <n>\n' >{verdict}`
   높음·중간이 0이면 풀이가 착지 길(검증 맡김)로 가고, 아니면 그 제출은 레인에 돌아간다.
