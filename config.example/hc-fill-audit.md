# 감사 {lane} @{machine} — {sha} (hc-fill 자동, 읽기 전용)

보고는 한국어로. 이 감사는 hc-fill이 띄웠다. 레인 `{lane}`(브랜치 `{branch}`)이 `hc-lane report 완료 {sha}`를 적었다.

- 작업 트리: `{worktree}` (이 터미널의 폴더)
- 감사할 범위: `git -C {worktree} diff origin/{base}...{sha}`
- 원 지시문: `{brief}` — 범위·완료 조건·공통 규칙을 먼저 끝까지 읽는다.

## 2차 이상이면 (이 감사는 {round}번째)
- 앞 차수가 본 커밋 `{prev_sha}` · 앞 보고서 `{prev_report}` · 앞 판정 {prev_verdict} · 지휘 지시 `{coord_notes}` (1차거나 없으면 빈 칸)
- 앞 차수가 있으면 먼저 앞 보고서를 읽고(이 기계에 없으면 `hc-lane audit-report {prev_report}`) `git -C {worktree} diff {prev_sha}..{sha}`로 앞 지적이 고쳐졌는지와 그 고침이 새로 연 길을 본다.
  지휘 지시 파일이 있으면 그 지시가 지켜졌는지 본다. 그다음 아래 할 일로 나머지를 훑는다(앞에서 확인한 곳은 짧게).

## 할 일
1. 원 지시문을 읽고, 위 diff와 바뀐 파일 전체(바뀐 함수를 부르는 곳까지)를 읽는다.
2. 원 지시문의 범위·완료 조건과 대조해 버그·회귀·시험 누락·지시문 위반을 찾는다. 시험·검증은 작업 트리를 바꾸지 않는 명령만 돌린다.
   재현 명령에는 시간 제한을 둔다. 자식 프로세스가 필요하면 시작할 때 `trap`으로 정리를 등록한다. 직접 띄운 프로세스만 종료하고 `wait`로 회수한 뒤 판정을 보고한다.
3. 지적마다 등급을 매긴다.
   - 높음: 데이터 손실·보안·핵심 동작이 틀림 — 착지하면 안 된다
   - 중간: 고쳐야 착지할 수 있는 결함, 빠진 시험, 지시문 위반
   - 낮음: 나중에 고쳐도 되는 것
4. 코드 수정·커밋·push 금지(읽기 전용 감사).
5. 보고서는 `{report}`에 쓴다: 지적마다 등급 · 파일:줄 · 무엇이 틀렸나 · 근거(재현·출력) · 고치는 방향. 지적이 없으면 확인한 것을 적는다.
6. 마지막에 정확히 이 꼴로 한 번 부른다(숫자만 바꾼다. hc-fill이 이 줄로 착지·지적을 정한다 — 차수 ID `{audit_id}`와
   40자 sha가 이 감사의 것일 때만 받는다):
   `hc-lane report 판정 {sha} "감사 완료 {audit_id} 높음 <n>·중간 <n>·낮음 <n>"`
   이 줄이 보고서를 저장소 원격(`refs/hc-audit/<차수 ID>`)에도 올린다 — 다른 기계 레인이 `hc-lane audit-report <차수 ID>`로 읽으니 보고서를 먼저 다 쓴다.
