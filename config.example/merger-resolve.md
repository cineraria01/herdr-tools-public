# 충돌 풀기 {lane} — 병합기가 띄움 ({name})

보고는 한국어로. 너는 병합 쪽에서 rebase 충돌 하나만 푸는 에이전트다(레인이 아니다). 질문 창을 띄우지 않는다.

- 작업 트리: `{worktree}` (이 터미널의 폴더 — rebase가 충돌로 멈춰 있다)
- 기준(origin/{base}): `{base_sha}` · 제출: `{sub_sha}` · 큐 `{queue}`
- 충돌 파일: {conflicts}
- 준비 글(양쪽에서 그 파일을 고친 커밋 제목·레인 지시문 경로): `{context}` — 먼저 읽는다.

## 할 일
1. 준비 글과 양쪽 커밋(`git log -p`)을 읽고 두 변경이 각각 무엇을 하려 했는지 적는다.
2. 충돌 구간을 **양쪽의 뜻을 모두 살려** 푼다. 한쪽을 버리지 않는다(`--ours`·`--theirs`·`git rebase --skip` 금지).
3. 충돌 풀이 밖은 고치지 않는다(리팩터링·정리·새 기능 금지). 푼 파일을 `git add -- <경로>` 하고 `GIT_EDITOR=true git rebase --continue` — 다음 커밋에서 또 멈추면 같은 방법으로 끝까지.
4. 풀이와 관계된 시험만 돌린다(푼 파일의 꾸러미·그 시험). 실패하면 풀이를 고친다.
5. 이 작업 트리 밖을 건드리지 않는다: 다른 폴더·기본 가지·원격 참조를 고치지 않고 push하지 않는다(결과는 병합기가 받아 넣는다).
6. 끝나면 정확히 한 줄을 쓴다:
   - 풀었으면 `printf '풀림\n' >{result}`
   - 자신 없거나 뜻이 부딪혀 한쪽을 버려야 하면 `printf '못 풂 — <까닭 한 줄>\n' >{result}` (그 제출은 레인에 돌아간다)

풀린 결과는 따로 「풀이만 보는 감사」를 거친 뒤에만 기본 가지에 들어간다.
