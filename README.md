# herdr-tools

여러 기계(맥 하나 + 워커 맥·서버)에서 Herdr로 에이전트 레인을 돌리는 운영 도구 모음이다. 개인 값(기계 이름·경로·계정·지침 본문)은 이 저장소에 없고, 따로 둔 **개인 저장소**(설정 폴더 `HERDR_TOOLS_CONFIG`, 기본 `~/.config/herdr-tools`)에서 읽는다. 꼴은 `config.example/`(가짜 값), 규칙은 `CONTRACT.md`.

| 도구 | 하는 일 | 도는 곳 |
|---|---|---|
| `hc-lane` | 레인 작업 트리 만들기·착지(`land`)·정리(`clean`·`gc`)·push 관문(`guard`) | macOS 기계 |
| `hc-fill` | 빈 자리에 기다리는 레인을 바로 띄우기 | 맥 |
| `herdr-sync` | 맥의 실제 파일을 두 저장소와 모든 기계에 맞추기 | 맥 |
| `herdr-settings-merge` | `~/.claude/settings.json`의 정한 키만 3-way로 맞추기(herdr-sync가 부른다) | 모든 기계 |
| `herdr-tools-config` | 개인 설정 읽기·개인 값 검사(`lint`) | 맥 |
| `herdr-tools-publish` | 범용 저장소를 기록 없이 공개 저장소로 내보내기(herdr-sync가 부른다) | 맥 |
| `herdr-balance` | Herdr 창에서 지휘 pane 옆 worker 높이 맞추기(`--watch`) | 맥 |
| `hc-launchd-guard` | launchd 작업을 Herdr 터미널에서 돌리는 지킴이(아래 「launchd 작업」) | macOS 기계 |
| `hc-sweep`, `ovis-split`, `hc-core-relaunch`, `worker-mac-check`·`worker-mac-setup` | 끝난 터미널 정리, Ovis 분할, 코어 다시 띄우기, 워커 맥 점검·설정(`worker-mac-setup mesh`: 워커끼리 ssh·hc 연결) | 맥·macOS 기계 |
| `claude/hooks/` | 같은 작업 트리 동거 편집 가드, 무인 루프 질문 창 막기, `hc-lane wait` 분리(&) 실행 막기, 레인 세션의 셸 파일 고치기·heredoc 커밋·zsh 확장 경로 막기(`lane-no-shell-edit.sh`) | macOS 기계 |

## herdr-sync: 정본은 맥의 실제 파일, 두 저장소는 기록

- 정본은 맥의 `~/.local/bin`, `~/.claude/…`, `~/.agents/skills/…` 같은 실제 파일이다.
- 맥에서 고치고 `herdr-sync`를 돌린다. 맥에서 바뀐 것은 그 줄의 저장소로 모아(**모음**) 저장소마다 따로 커밋·`HERDR_LAND=1` push하고, 모든 기계에 맞춘다.
- 레인이 어느 저장소를 고쳐 착지했으면, 다음 `herdr-sync`가 그것을 맥에 깔고(**깖**) 기계에 맞춘다.
- 무엇을 어디에 맞추는지는 개인 저장소의 `sync.list`가 정한다(꼴 `config.example/sync.list`). 저장소 경로가 `tools:<경로>`면 이 범용 저장소, 그 밖은 개인 저장소 파일이다. 새 파일을 맞추려면 한 줄만 더한다. 설정(`~/.claude/settings.json`)은 개인 저장소 `settings/keys.json`에 적은 키만 맞춘다(꼴 `config.example/settings/keys.json`).
- **개인 값 검사**: 이 범용 저장소로 모을 맥 값이 `herdr-tools-config lint`(개인 저장소 `private-patterns.txt`)에 걸리면 `충돌 저장소 <경로> (개인 값)`을 찍고 아무 데도 쓰지 않고 멈춘다. `--take repo:`로도 넘기지 않는다. 그 값을 범용으로 바꾸거나 그 줄을 개인 저장소로 옮긴다. 개인 저장소에 `private-patterns.txt`가 없거나 패턴 줄이 없으면 검사를 못 하므로 범용으로 모을 값은 모두 `(개인 값 검사 못 함 — …)` 충돌로 멈춘다.
- 처음 한 번은 저장소에서 바로 돌린다: `<이 저장소>/bin/herdr-sync`. 그러면 herdr-sync 자신도 `~/.local/bin`에 깔린다(`sync.list`에 그 줄이 있으면).

### 사용법 (맥에서만)

```sh
herdr-sync --check              # 고치지 않고 모든 기계를 한 표로. 다름·충돌이 있으면 종료 1
herdr-sync                      # 맞춘다
herdr-sync box-1 box-2          # 고른 기계만
herdr-sync --take <기계>:<경로>  # 충돌을 맥 값으로 덮는다 (그 기계에 백업)
herdr-sync --pull <기계>:<경로>  # 그 기계 값을 맥 실제 파일로 가져온 뒤 맞춘다
```

- `--check` 표의 첫 줄은 맥 ↔ 두 저장소다: `맥: 저장소가 새로움 n개 (<저장소 경로> …) — herdr-sync로 깐다`(레인이 착지했는데 맥에 아직 안 깔림), `맥: 저장소보다 새로움 n개 (…) — 커밋 안 됨?`(맥에서 고쳤는데 아직 안 모음), 다 맞으면 `맥: 저장소와 같음`. 기계 줄은 **맥 실제 파일**과 견준 것이라, 맥이 저장소보다 뒤면 기계 줄 끝에 `(맥 판 기준 — 저장소 새 판은 아직)`이 붙는다 — 그때 `같음`은 「맥 옛 판과 같음」이지 「저장소 새 판이 퍼졌음」이 아니다. 착지 뒤 퍼졌는지 볼 때는 맥 줄부터 본다(2026-11-19 착지 직후 `--check`의 기계 줄 `같음`만 보고 「이미 퍼졌다」고 오판했다).
- 경로는 `sync.list`의 맥 경로(`~` 아래)다. 예: `.claude/docs/notes.md`, 지침 본문은 `.claude/CLAUDE.md#body`, Codex 공통 구역은 `.codex/AGENTS.md#codex-shared`, 링크는 `.claude/skills/my-skill@`, 설정 키는 `.model`, 설정 훅은 `hook:PreToolUse:cotenant-guard.sh`(herdr-settings-merge의 판정 이름), 나무 안 파일은 `.agents/skills/my-skill/scripts/run.sh`.
- `<기계>:*`는 그 기계의 충돌 전부, `<기계>:<폴더>/**`는 그 나무 줄의 그 기계 충돌 전부다(`repo:<폴더>/**`도 된다).
- Codex 공통 구역과 설정 키는 `--pull`을 받지 않는다(구역은 맥 지침에서 다시 만들고, 설정은 맥 `settings.json`을 고친다). `--take`를 쓴다.
- 저장소 위치: 범용 `HERDR_TOOLS_REPO`(기본 `~/Documents/app/herdr-tools`), 개인 `HERDR_TOOLS_CONFIG`(기본 `~/.config/herdr-tools`). 둘 다 git·main 브랜치·깨끗함이어야 한다. 개인 저장소(`sync.list`)가 없으면 종료 2, 아무것도 쓰지 않는다.
- 대상 이름: `all`(모든 기계) · `macos`(uname이 Darwin) · `local`(맥만) · 기계 이름을 쉼표로. 옛 이름 `all9`·`mac7`·`mac-only`가 보이면 새 이름을 알리고 종료 2(옛 판은 그것을 기계 이름으로 읽어 아무 데도 안 깔고 「같음」으로 보였다).
- 순서: 두 저장소 `git pull --ff-only` → `sync.list` 읽기 → `--pull` 처리 → 개인 설정 `sync.prebuild`(있으면 `sh -c`로, 예: 맥 지침에서 Codex 공통 구역 다시 만들기. 실패하면 멈춤) → 맥 ↔ 두 저장소 → 기계마다 파일·설정(`~/.local/bin/herdr-settings-merge`)·지울 것 → 마지막에 기계마다 한 줄 `같음` / `다름 (묶음…)` / `충돌 n건`. 저장소에서 지침 본문을 깔았으면 prebuild와 맥 ↔ 저장소를 한 번 더 돈다.
- sh를 못 띄우는 기계(Windows 등, hc 오류 `spawn_failed`·`cannot start `)는 `<기계>: 건너뜀 (sh 없음 — Windows 등)`, uname이 Darwin·Linux가 아닌 기계(Git sh의 `MINGW64_NT-…`·`MSYS_NT-…` 등)는 `<기계>: 건너뜀 (OS <uname>)` 한 줄만 찍고 아무것도 쓰지 않는다(`--take`·`--pull`로 집어도). 둘 다 종료 코드에 넣지 않는다. 진짜 연결 실패·시간 초과는 지금처럼 `다름 (연결)`·종료 1이다.
- 다른 herdr-sync가 돌고 있으면 바로 끝난다(종료 75). 맥이 아닌 곳(`~/Applications/Herdr.app`·`/Applications/Herdr.app`이 없거나 `hc machine ls`에 기계가 없는 곳)에서는 종료 2.
- 설정은 대상 기계의 `herdr-settings-merge`가 `~/.local/share/herdr-sync/keys.json`(개인 저장소 `settings/keys.json`을 깐 것)과 `HERDR_MACHINE`으로 판정한다. 그 도구가 판정 줄 없이 실패하면 `다름 (도구문제:설정)`으로 보인다(충돌과 다르다).
- 저장소에 커밋하지 않은 변경이 있으면 아무것도 하지 않고 멈춘다. 표식 없는 `~/.codex/AGENTS.md`는 충돌로 보이고, `--take`하면 codebase-memory-mcp 블록만 남기고 구역을 넣는다(백업).

### 나무 줄: 폴더 통째로 (스킬 폴더 등)

`sync.list`의 맥 경로를 `<폴더>/**`로 쓰면 그 폴더 아래 모든 층의 파일을 하나하나 파일 줄처럼 맞춘다(저장소 경로는 폴더). 예:

```
스킬   .agents/skills/**             skills/agents/   macos
제외   .agents/skills/app-managed    -                -
```

- 걷지 않는 것: 심볼릭 링크(따라가지 않는다. 링크는 `@` 줄로), 이름이 `.`으로 시작하는 것(`.git`·`.DS_Store` 등), `__pycache__`, `node_modules`, `제외` 줄 아래(앱이 계정으로 맞추는 폴더 등. 지움과 달리 기계에 있는 것을 건드리지 않는다).
- 따로 적은 줄이 맡은 경로는 나무가 맡지 않는다. 대상 기계에만 있는 파일은 건드리지 않는다.
- 그 기계에서 손댄 파일은 충돌이다(덮지 않는다). 내용은 같고 실행 권한만 다르면 씀이다.
- 7MB 넘는 파일은 `건너뜀 <경로> (7MB 넘음)`(hc exec 입출력 한도 8MB 아래로 묶어 보낸다), 저장소 `.gitignore`에 걸리는 파일은 `건너뜀 <경로> (저장소 .gitignore)`, 그 기계에서 링크인 폴더는 `건너뜀 <기계> <경로> (링크 — 따라가지 않음)`.
- 기계마다 hc 호출은 조회 한 번, 그리고 쓰기·충돌 내용 읽기·`--pull` 받기가 7MB 아래 tar 묶음마다 한 번이다(파일 수가 아니라 바이트에 비례, 평소 한 번). 실측(가짜 기계 둘, 파일 2,000개·36MB): 첫 맞추기 약 15초, 다 맞은 뒤 `--check` 약 2.5초.
- 줄을 옮겨도(따로 적은 줄을 지워 나무가 맡게 함, 나무의 저장소 폴더를 바꿈) 맥 파일을 지우지 않는다: repo-base에 저장소 경로를 함께 적어, 경로가 바뀌면 새 자리로 모은다.
- 링크 줄은 가리킬 곳이 그 기계에 없으면 만들지 않고 `건너뜀 <기계> <경로> (가리킬 곳 없음)`. 가리킬 곳을 같은 실행에서 나무로 쓰면 그 뒤에 만든다.

### 충돌과 푸는 법

판정은 파일·구역·키마다 3-way다. 기계마다 `~/.local/state/herdr-sync/base.tsv`에 herdr-sync가 마지막으로 써 준 값의 cksum이 있다.

| 그 기계 값 | 판정 |
|---|---|
| 맥 값과 같다 | 같음 |
| base와 같다 (그 기계가 손대지 않음) | 맥 값으로 씀 |
| 내용은 맥 값과 같고 실행 권한만 다르다 | 씀 (권한만 맞춘다) |
| 그 밖 (그 기계에서 따로 고쳤거나, 처음이라 base가 없는데 다름) | 충돌: 쓰지 않고 `충돌 <기계> <경로> (n줄 다름)` |

- 맥 값이 맞으면 `herdr-sync --take <기계>:<경로>`.
- 그 기계 값이 맞으면 `herdr-sync --pull <기계>:<경로>`. 맥 실제 파일이 바뀌고, 저장소와 다른 기계에도 퍼진다.
- 맥 ↔ 저장소도 같은 규칙이다(base는 맥 `~/.local/state/herdr-sync/repo-base.tsv`, 열쇠는 맥 경로, 셋째 칸은 저장소 경로 — 줄을 옮기면 base 없음으로 본다. 셋째 칸이 없는 옛 base에서 저장소 쪽이 없으면 맥 파일을 지우지 않고 충돌로 멈춘다). 저장소에서 지워진 것은 맥에서 백업으로 옮기고 `맥 지움 <경로> (저장소에서 지워짐)`. 모으다 실패하면 그 저장소에서 이번에 쓴 경로만 되돌리고 멈춘다. 둘 다 바뀌었으면 `충돌 저장소 <경로>`를 찍고 아무 데도 쓰지 않고 멈춘다. 맥 값을 남기려면 `--take repo:<경로>`, 저장소 값을 남기려면 `--pull repo:<경로>`.
- push가 거절되면 멈추고, 다음 실행이 그 저장소의 「지난번 push 못 한 커밋」을 다시 보낸다.
- 덮거나 지운 것은 그 기계의 `~/.local/state/herdr-sync/bak/<YYYYMMDD-HHMMSS>/<경로>`에 남는다.
- 쓰기는 임시 파일에 쓰고 cksum을 맞춘 뒤 바꿔 넣는다. 실행 권한은 맥 값을 따른다.

### 맞추지 않는 것 (기계마다 다른 것)

- 로그인·계정·토큰 파일과 `~/.config/*`
- `~/.claude/rules/<기계>.md` 같은 기계 이름 규칙(맞출 것만 `sync.list`에 적는다)
- `~/.claude/CLAUDE.md`의 `<!-- User customizations -->` 줄까지(그 기계의 머리 블록)
- `~/.codex/AGENTS.md`의 codex-shared 표식 밖
- 셸 rc, launchd 작업(`launchd/`는 손으로 깐다)
- herdr가 관리하는 `~/.claude/hooks/herdr-agent-state.sh`
- settings의 `keys.json` `refs` 키(`--check`에서 「참고」로만 보인다)
- 리눅스 기계는 `all` 묶음만 받는다(도구가 macOS 명령을 전제로 한다).
- 맥에서 지운 파일은 기계에서 저절로 지우지 않는다. 지울 것은 `sync.list`에 `지움` 줄로 더한다.

## 공개 저장소로 내보내기 (herdr-tools-publish)

작업은 이 저장소(비공개)에서 하고, 공개 저장소에는 지금 파일만 기록 없이 내보낸다. 비공개 기록(커밋 메시지·작성자 이메일, 옛 판의 개인 값)은 나가지 않는다.

```sh
herdr-tools-publish --dry-run   # 바뀔 파일 목록(A·M·D)과 검사 결과만. push 없음, publish.dir을 만들지 않음(없으면 임시로)
herdr-tools-publish             # 검사 → 공개 main 위에 커밋 하나 → push
```

- 설정 키(개인 설정 `config`): `publish.repo` 공개 저장소 주소(없으면 종료 2, herdr-sync는 부르지 않는다) · `publish.dir` 공개 쪽 bare clone 자리(기본 `~/.local/share/herdr-tools/public`, 없으면 만든다. 있는데 bare git이 아니거나 origin이 `publish.repo`와 다르면 종료 1) · `publish.author` 공개 커밋 작성자·커미터 `이름 <메일>`(없으면 공개 clone의 git 설정 `user.name`·`user.email`. git이 호스트 이름으로 지어낸 값은 받지 않고, 부른 쪽 환경의 `GIT_AUTHOR_*`·`GIT_COMMITTER_*`·`EMAIL`은 지운다 — noreply 메일을 둔다) · `publish.secrets` 더 막을 비밀 꼴 ERE 하나(여러 꼴은 `|`).
- 하는 일: `git fetch origin main` → `refs/remotes/origin/main`(같은 이름의 로컬 가지에 속지 않게 전체 이름) 트리의 블롭마다 `cat-file`로 `<sha>` 이름 파일에 꺼내 검사(경로대로 디스크에 꺼내지 않는다 — macOS 디스크는 대소문자·정규화를 구분하지 않아 경로가 겹치고 링크를 따라간다. `git archive`는 `export-subst` 같은 attributes로 비공개 커밋 정보를 넣을 수 있어 쓰지 않는다) → 그 트리·블롭 객체만 공개 쪽으로 옮겨(비공개 커밋 객체는 안 옮김, 공개 트리 sha = 비공개 트리 sha — 지운 파일·실행 비트·링크 포함) 공개 main 위에 커밋 하나, 메시지는 `herdr-tools <비공개 짧은 sha> 내보냄` 한 줄 → fast-forward push(강제 push 없음). 공개 main이 없으면 부모 없는 첫 커밋. 트리가 공개 main과 같으면 `같음`, 커밋하지 않는다.
- **막는 것(fail-closed)**: 아래 하나라도 걸리면 아무것도 push하지 않고 걸린 `파일:줄: 까닭`을 찍고 종료 1(비밀 값 자체는 찍지 않는다).
  - 개인 값: `herdr-tools-config lint`(개인 설정 `private-patterns.txt`) — 블롭 내용(이진·UTF-8 아닌 파일도 바이트로), 경로, 링크 대상 글자, 공개 커밋 작성자·커미터. 그 파일이 없거나 패턴 줄이 없거나 lint가 실패하면(못 읽은 파일 포함) 「검사 못 함」으로 종료 1.
  - 비밀 꼴(코드 안 범용 꼴): 개인 키 머리(BEGIN … PRIVATE KEY), GitHub 토큰(`ghp_`·`gho_`… `github_pat_`), `sk-` 키, Slack `xox?-`, AWS `AKIA`, Google `AIza`, 40자 넘는 16진, 32자 넘게 이어지고 대·소문자·숫자가 다 든 base64 꼴 토큰(알파벳 목록 `ABCDEFGH…`·`0123456789`가 든 것은 뺌), 그리고 `publish.secrets`. 내용·경로·링크 대상 글자를 바이트로 본다. 경로가 걸리면 이름은 가리고 폴더와 몇 번째 파일인지만 찍는다.
  - 글이 아닌 블롭: NUL이 들었거나 UTF-8로 안 풀리는 블롭(UTF-16 글·압축·이미지 등 — 바이트 검사가 속을 못 본다). 걸린 경로만 찍는다. 범용 도구 저장소에 이진 파일은 없어야 정상이라 허용 목록은 없다(필요해지면 그때 설정 키로).
  - 받는 항목은 일반 파일·실행 파일·링크 블롭과 비어 있지 않은 하위 트리뿐이다. 빈 하위 트리·하위 모듈·낯선 mode는 막는다(이름은 가리고 폴더만 찍음). 하위 트리 이름도 경로 검사를 받는다(`ls-tree -r -t`).
  - 줄바꿈이 든 경로, 대소문자·유니코드 정규화(NFC)만 다른 경로 쌍(폴더 포함, `n번째·m번째 파일`로 찍음).
  - 공개 커밋 작성자 검사는 커밋을 만들 그 공개 clone에서 한다. push·fetch는 `origin` 설정(pushurl 등)이 아니라 `publish.repo` 주소로 직접 한다. replace ref는 따르지 않는다(`GIT_NO_REPLACE_OBJECTS=1` — 검사한 블롭 = 옮기는 블롭). `--dry-run`은 실제 `publish.dir`에 아무것도 쓰지 않는다(객체는 임시 bare에).
  - 검사 도구(`herdr-tools-config`)가 이 도구 곁에 없으면 종료 1.
- push·fetch는 인증 질문에서 멈추지 않는다(`GIT_TERMINAL_PROMPT=0`, `GIT_SSH_COMMAND`가 없으면 `ssh -o BatchMode=yes`).
- 늘 내보내기: `herdr-sync`가 맥에서 다 맞춘 뒤(`--check`가 아닐 때) `publish.repo`가 있으면 부른다. 실패하면 `!!! … !!!`로 크게 경고하고, herdr-sync 종료 코드는 그대로다(기계 맞추기와 별개).
- 시험이 비밀 꼴을 다룰 때는 조각을 이어 만든다(시험 파일 자체가 검사에 걸리지 않게).

## hc-lane 사건 (report·events·wait — 레인이 적고 지휘는 그것만 읽는다)

화면 글자나 보고 파일 끝 줄을 긁는 감시는 칸이 한 줄이거나 파일 이름이 다르면 완료를 놓친다(2026-11-16 레인이 20분~1시간 20분 놀았다). 그래서 레인이 상태를 사건 파일에 직접 적고, 지휘는 그 파일만 읽는다.

- **Go 판**(2026-11-21 사용자 「모두 고로 옮기고 싶어」): `report`·`events`·`wait`·`watch`·`coord`·`send`·`broadcast`·`early-wait`·`verdict`는 `cmd/hc-lane`(단일 바이너리)이 맡는다 — 이름·인자·출력·종료 코드·상태 파일(events.tsv·seen·sent·coord.*·watch.*·lanes.tsv)은 셸 판과 같아 두 판이 같은 파일을 번갈아 써도 된다. `bin/hc-lane`이 `hc-lane __has <명령> <인자…>`로 물어 Go가 맡으면 exec, 아니면(종료 120 「아직 셸」·도움말) 셸 판(`lib/hc-lane/*.sh`)으로 돈다. 되돌리기 `HC_LANE_IMPL=bash`(전체는 `HERDR_IMPL=bash`), Go 바이너리를 직접 주려면 `HC_LANE_GO_BIN`(`HC_LANE_BIN`은 시험이 포장 경로로 쓴다). 계약 시험은 `tests/hc-lane-go.test.sh`(Go 판)·`tests/hc-lane-bash.test.sh`(셸 판, 본체는 Go 시험 `tests/hclane`) 둘 다 통과해야 한다.

- 레인: `hc-lane report <중간|완료|착지|막힘|판정|제출> [<sha>|-] [<한 줄>] [--to <지휘>,…]`. `--to`는 받을 지휘를 아홉째 칸에 적는다 — 그 지휘들의 watch만 보낸다(레인 주인 판정 대신. hc-fill 놀고 있음 알림이 쓴다). 그 기계 `${XDG_STATE_HOME:-~/.local/state}/hc-lane/events.tsv`에 한 줄을 더한다(지우지 않음). 칸: 시각(UTC `2026-11-16T02:00:00Z`)·기계(`HC_LANE_MACHINE`, 없으면 hostname)·터미널(`$HC_TERMINAL_ID`)·레인·상태·sha·한 줄(탭·줄바꿈은 빈칸)·그때의 hc turn(`hc get`, 터미널 밖이면 `-`. 옛 7칸 줄도 읽는다). 레인 이름은 `--name` → `$HC_LANE` → hc 터미널 이름(`hc get`) → 작업 트리 가지(기본 가지면 `-` — 작업 트리를 지운 뒤 메인 폴더에서 report해도 `main`이 레인이 되지 않게). 화면에도 `<레인> <상태>: <sha> <한 줄>`을 찍는다. `--print-steps`가 쓰기 레인에는 중간·완료·착지·막힘 때, `--read` 레인에는 판정 때(`hc-lane report 판정 - "<판정 한 줄>"`) 부르라는 줄을 넣는다.
- hc-lane이 띄우는 레인은 `HC_LANE=<이름>` 환경과 hc 라벨 `hc-lane=1`을 받는다.
- 지휘: `hc-lane events [--all|--on <기계>…] [--since <시각|30m·2h·1d>]`는 이 기계(와 연결된 기계마다 `hc exec --on` 한 번)의 사건을 시각 순으로 찍는다. 원격 줄의 기계·터미널은 hc 이름(`<기계>/<t…>`)이다. 못 읽은 기계는 `모름 <기계>`. sh를 띄울 수 없는 기계(예: Windows — `hc exec`가 `spawn_failed`·`cannot start sh`)는 레인 기록이 없는 것으로 보고 건너뛴다(events·wait·watch 모두 `모름`·`연결 안 됨` 없음, 쉬는 레인 ps 확인도 같다).
- 지휘: `hc-lane wait [--all] [--timeout <분>(기본 110)] [--state 완료,착지,…]`를 배경으로 건다. 아직 본 적 없는 사건이 생기면 그 줄(들)을 찍고 종료 0, 상한이면 75. 찍은 사건은 이 기계 `…/hc-lane/seen.<$HC_TERMINAL_ID>`(지휘마다 따로, 터미널 밖이면 `seen`)에 적어 다시 알리지 않는다(바꾸는 것은 이 파일뿐). 출력이 `/dev/null`이면 읽을 사람이 없어 seen에 적지 않고 종료 2(배경으로 걸 때는 출력을 파일로 받는다). 새 커서는 `--since`(없으면 2시간 전)부터 본다 — 레인을 띄운 뒤 2시간 안에 첫 wait를 건다. 라벨 `hc-lane=1` 터미널은 그 터미널(주소·레인 이름)의 마지막 사건으로 본다: 착지·판정 그 턴(report turn+1 이하, report turn을 모르면 밖) 밖에서 끝났거나(한 줄 칸 `뜻밖의 종료(<상태>)` — 착지 전인 완료·막힘 뒤와, 착지·판정 뒤 이어 받은 일에서 끝난 것도 알린다. 착지 뒤에 같은 sha의 완료가 같은 턴(같은 turn 값)에만 이어지면 — 착지 뒤 완료를 한 번 더 적는 레인 틀 — 착지로 치고 turn은 그 완료의 것으로 본다. sha가 `-`(판정·sha 없음)이거나, 사이에 turn이 올랐거나, 다른 sha의 완료·중간이 뒤에 오면 새 일. sha는 소문자로 짧은 쪽 길이만큼 앞자리를 견주고, report는 대문자 sha도 소문자로 적는다), 완료·착지·막힘·판정 없이(또는 그 report의 turn+1보다 뒤에 — 이어 받은 일을 report 없이 끝냄) done·idle로 쉬거나, blocked·error면 `멈춤` 사건(한 줄 칸 `<상태> turn <n>` — turn이 바뀌면 다시 알리고, 같은 turn의 done·idle은 한 번). done·idle은 쉰 지 `lane.wait_grace`분(기본 10, `0`이면 끔)이 지나고 배경 작업이 없을 때 멈춤이다. 배경 작업은 프로세스로 본다: `hc get`의 터미널 `pid` 자손 가운데 명령 줄에 `lane.wait_procs` 글자(빈칸으로 나눈 목록, 기본 `shell-snapshots` — Claude Code Bash 도구 셸 `/bin/zsh -c source …/.claude/shell-snapshots/snapshot-zsh-….sh …`)가 든 것이 살아 있으면 배경 작업 중(MCP 서버처럼 늘 사는 자손은 그 꼴이 아니라 안 셈). 이 기계는 `ps`, 원격은 바퀴마다 기계당 `hc exec --on <기계> -- ps` 한 번. 그런 프로세스가 없거나(셸 없는 배경 Agent 등) pid를 모르거나 ps가 실패하거나 `lane.wait_procs`가 빈 값이면 화면 표시도 본다: 화면의 마지막 상태 줄(`lane.wait_line`, 기본 ✻ 턴 끝 줄 — 옛 턴의 줄·본문은 안 봄)에 `lane.wait_busy`(확장 정규식, 기본 `shells? still running|monitors? still running`, 빈 값이면 끔) 표시가 없을 때 멈춤 — 배경 셸이 도는 동안 턴을 끝낸 레인은 스스로 이어 가니 알리지 않는다. 배경 작업이 있어도 쉰 지 `lane.wait_busy_max`분(기본 30)이 넘으면 멈춤(blocked·error·끝남은 바로). 그 바퀴에 events를 못 읽은 기계의 레인은 blocked·error만 그대로 알리고, 사건이 있어야 하는 쉼·끝남은 `연결 안 됨 <기계> <날짜>`(레인마다 하루 한 번)로 알린다 — 다음 바퀴에 다시 읽히면 정상 판정. 줄은 1000바이트 안으로 잘라(끝 반쪽 UTF-8 버림) 여러 레인이 함께 더해도 섞이지 않는다. 바퀴마다(`HC_LANE_WAIT_TICK`초, 기본 60) `hc machine ls`·`hc ls` 한 번과 기계당 `hc exec` 한 번.
- **watch(늘 도는 감시, 지휘가 걸 일 없음)**: `hc-lane watch --to <지휘 주소> [--all]`은 wait와 같은 판정을 `lane.watch_tick`초(기본 30)마다 돌며, 새 사건이 생기면 지휘 터미널에 `hc send <지휘> "hc-lane: <레인> <상태> <sha> <한 줄> (<터미널>) ‖ …"`로 한 번 밀어 준다(지휘가 바빠도 입력에 쌓인다). 커서는 그 지휘의 wait와 같은 `seen.<지휘 주소>`라 둘이 겹쳐 두 번 알리지 않고, hc send가 실패하면 커서에 안 적고 다음 바퀴에 다시 보낸다. 같은 지휘로 하나만(뒤 것은 종료 75, 잠금 `…/hc-lane/watch.<주소>/pid` — 그 pid가 없거나 hc-lane watch가 아니면 넘겨받음). 못 읽은 기계는 `연결 안 됨 <기계>`를 끊길 때마다 한 번 보내고 다음 바퀴에 다시 본다. `hc ls`가 3바퀴 이어 실패하면 그 멈춤 한 줄을 한 번 보내고, 실패가 이어지는 동안은 더 보내지 않으며 되살아나면 `hc ls 회복` 한 번. 보내는 글의 제어 문자는 지운다. 스스로 끝남(종료 0): 지휘 터미널이 3바퀴 이어 `hc get`에 없거나(not_found) 끝남 — 코어 연결 실패·시간 초과는 모름이라 세지 않고 계속 돈다 —, 또는 그 지휘의 살아 있는 레인(라벨 `hc-lane=1`, parent가 그 지휘 — 모르면 그 지휘 것으로 침)도, hc-fill 대기열(`${HC_FILL_DATA:-~/.local/share/hc-fill}/queue.tsv`)에 아직 안 띄운 요청(wait — 받은편지 요청도 hc-fill이 바퀴마다 여기로 옮긴다. up은 세지 않는다: 살아 있는 up 레인은 hc ls가 세고, 끝난 up 줄은 `hc-fill rm` 전까지 남는다)도, 새 사건도 없이 `lane.watch_idle`분(기본 60).
  - **저절로 뜬다**: `hc-lane`이 레인·감사(`--read` 포함)를 띄울 때 지휘(`HC_LANE_COORD`, 없으면 `$HC_TERMINAL_ID`, 둘 다 없으면 건너뜀)의 watch가 돌고 있지 않으면 이 기계에 `hc run --bg --no-notify --rm --name lane-watch-<지휘> --label hc-lane-watch=1 -- hc-lane watch --all --to <지휘>`를 띄운다(지휘 터미널에서 띄우면 그 터미널이 parent라 지휘가 끝나면 같이 끝남). **hc-fill**(launchd라 터미널 밖)은 대기열 줄의 주인 지휘(`hc-fill add`를 부른 지휘)를, 주인이 없으면 `hc-lane coord`가 확인한 지휘 주소를 `HC_LANE_COORD`로 넘겨 같은 길을 탄다.
  - **지휘 정보는 지휘마다**(`…/hc-lane/coord.<주소>`, 「주소<탭>pid<탭>이름<탭>마지막으로 레인을 띄운 시각」): 지휘 주소는 설정에 박지 않는다(코어가 다시 뜨면 주소가 남의 터미널로 간다). 지휘 터미널이 레인·감사를 띄우거나 `hc-lane wait`를 걸거나 손으로 watch를 걸 때(watch 터미널의 parent가 `--to`), `hc-fill add`를 부를 때(`hc-lane coord --set`) 자기 정보를 남긴다 — 레인·감시 라벨 터미널은 안 적는다. watch는 바퀴마다와 **보낼 때마다** 자기 지휘의 정보와 지금 `hc get` pid·이름을 맞춰 보고, 다르거나 없으면 보내지 않고(남의 터미널 send 0) `지휘 없음` 한 줄을 그 기계 `…/hc-lane/watch.log`에 남기고 끝낸다 — 커서에 안 적었으니 사건은 events에 남아 지휘가 돌아와 wait/watch를 걸면 받는다.
  - **사건은 그 레인을 띄운 지휘에게만**: hc-lane이 레인을 띄울 때 레인 기록 `…/hc-lane/lanes.tsv`(「레인 주소<탭>레인<탭>띄운 지휘」)를 남긴다(`HC_LANE_OWNER`가 있으면 그 지휘 — hc-fill이 대기열 주인을 넘긴다 —, 아니면 지휘 터미널에서 띄웠을 때 그 지휘, 주인 없는 hc-fill 줄·터미널 밖은 `-`). 레인 환경에도 `HC_LANE_OWNER`가 들어가, 레인 안에서 hc-lane으로 띄운 하위 레인(감사 등)도 같은 지휘가 주인이다(물려받은 값이 없으면 `-`). 값은 지휘 기계의 주소라 원격 레인에서 `hc send`하려면 `<지휘 기계>/<주소>`. watch는 레인 기록(없으면 `hc ls` parent)의 지휘가 자기면 보내고, 다른 살아 있는 지휘면 보내지 않는다(커서에 안 적어 그 지휘 몫). **주인을 모르거나(`-`) 주인 지휘가 사라진 레인의 사건은 살아 있는 모든 지휘 watch가 보낸다** — 놓치는 것보다 겹치는 게 낫다(2026-11-17: 가장 최근 지휘 한 곳이 넘겨받아 영구 주인이 되어, 대기열에 넣은 다른 지휘가 2시간 못 받음). 아무도 넘겨받지 않고(레인 기록에 안 더함) `sent`에도 안 적어, 지휘마다 자기 `seen.<지휘>`로 한 번씩만 간다. 살아 있는 지휘가 없으면 아무도 안 보내고 events에 남는다. 그래서 새로 뜬 지휘 watch는 커서 바닥(2시간 전)부터 그런 레인의 사건을 한 번에 받는다. 사라진 주인이 같은 주소로 지휘 정보를 다시 쓰면(그 터미널이 다시 레인을 띄우거나 wait를 걸면) 그 레인은 다시 그 지휘 몫이 되고, 그 사이 다른 지휘가 받은 사건을 한 번 더 받을 수 있다(겹침이지 놓침은 아님). 그래서 같은 기계에 지휘가 둘이어도 각자 자기 사건만 받고, 한쪽이 hc-lane을 써도 다른 쪽 watch는 계속 돈다. 레인 기록이 `-`여도 hc parent가 있으면 그 지휘로 본다.
  - **세 줄 규칙**: (1) 「보냄」 표시 `…/hc-lane/sent`는 **watch만** 쓴다 — 끌어오는 wait는 자기 커서 `seen.<지휘>`에만 적고, 남의 지휘 wait는 보기만 한다. (2) 사건의 주인은 그 레인을 띄운 지휘(레인 기록). 주인을 모르거나 주인이 사라진 레인은 아무도 넘겨받지 않고 모든 지휘 watch가 보낸다. (3) watch는 「주인이 나(또는 모름·사라짐) + `sent`에 없음 + 내 `seen.<나>`에 없음」인 사건만 보내고, 보낸 뒤 `seen.<나>`에, 자기가 주인인 사건이면 `sent`에도 적는다(같은 지휘의 wait와 겹쳐 두 번 안 감). 「보낸 것」은 `sent` ∪ 그 레인의 옛 주인(레인 기록에 그 레인 지휘로 적힌 적 있는, 이 watch가 아닌 지휘)의 `seen.<옛 주인>`이다 — 주인이 사라진 사건을 보낼 때 옛 주인이 자기 wait로 본 사건은 받은 것으로 치고 이 watch 커서에 적는다(옛 주인의 seen 파일이 없으면 `sent`만) — 그래서 지휘가 끝나도 그 지휘가 받은 사건은 다시 가지 않고, 아무도 안 받은 것만 간다. hc-lane 띄우기·hc-fill은 대상 지휘가 안 맞으면 watch를 띄우지 않고 `지휘 없음` 한 줄. 그래서 지휘는 wait를 사건마다 다시 걸 필요가 없다(2026-11-16 실측: 다시 걸기를 한 번 빠뜨려 완료를 34·14분 늦게 봄). `hc-sweep`은 `lane-watch-*`를 닫지 않는다.
  - **지휘가 질문·권한 창을 띄운 동안은 보내지 않는다**(watch-hold, 2026-11-19: 창이 떠 있을 때 보낸 알림 글이 그 창의 자유 입력 칸에 들어가 사용자 답으로 제출됐다). 보내기 직전 `hc get <지휘>`의 `status.state`가 `blocked`이거나, status가 `null`(하단 줄 실행기 안의 Claude처럼 상태를 hc에 안 알림)이고 `hc read` 화면 맨 아래 덩어리가 창이면 보내지 않고 커서에도 안 적는다 — 창이 닫힌 뒤 쌓인 사건을 한 번에(`‖`). 화면 판정: 평소 입력 칸(가로줄 `─`·`╌` 바로 아래 `❯` 줄, 그 아래 다시 가로줄)이 보이면 창 아님, 아니면 마지막 가로줄 아래 줄에서만 `lane.watch_dialog` 글자(기본: Claude Code 2.1 질문·권한·계획 창 글자)를 찾는다 — 대화 글에 인용한 창 글자에는 걸리지 않는다. 상태·화면을 못 읽으면 보낸다(알림을 잃지 않는 쪽). status `blocked`가 `lane.watch_hold_max`분(기본 30, `0`이면 막지 않음) 넘게 이어지면 보낸다(hc가 blocked에는 스스로 거절해 — watch는 `--force`를 안 쓴다 — 창이 닫힐 때까지 다음 바퀴에 다시 돈다). 화면으로 잡은 창(status `null` — hc가 막지 않아 창에 답으로 들어간다)은 상한이 지나도 보내지 않고 stderr·`…/hc-lane/watch.log`에 「<지휘> 질문 창 n분째 — 보류 중」 한 줄만 남긴다. 미룬 사건은 커서에 안 적혀 지휘의 `hc-lane wait`로도 받는다. hc에는 대화 입력을 거치지 않는 알림 길이 없다(hc 0.1.21 `hc send --help`).
  - 손으로 띄우려면(레인 없이 감시만): `hc run --bg --no-notify --rm --name lane-watch-$HC_TERMINAL_ID --label hc-lane-watch=1 -- hc-lane watch --all --to $HC_TERMINAL_ID`
- 정리됨: `hc-sweep`이 레인 터미널(라벨 `hc-lane=1`)을 닫을 때 닫기 전에 그 기계 events.tsv에 `정리됨` 한 줄(한 줄 칸 `hc-sweep <규칙>`)을 적는다(`hc-lane events`로 보인다). 그 줄을 못 쓰면 닫지 않는다(닫으면 wait가 reason killed로 보고 조용히 넘긴다). hc-sweep은 닫은 뒤 `hc rm`까지 해 터미널이 목록에서 사라지므로, wait는 이 줄로 판정한다: 그 터미널의 바로 앞 report가 착지·판정이고 정리됨 turn이 그 turn+1 안이면(또는 같은 turn의 쉼으로 이미 알렸으면) 버리고, 아니면 `멈춤`(한 줄 칸 `뜻밖의 종료(정리됨) hc-sweep <규칙>`, 바로 앞 report가 제출이면 정상 정리라 `제출 뒤 정리(정리됨) hc-sweep <규칙>` — 2026-11-21) — wait가 안 돌던 틈에 닫힌 보고 없는 레인도 다음 wait에서 나온다. 쉬는 레인 판정에서는 정리됨이 마지막 report를 가리지 않는다.
- 마지막 보고(2026-11-17): 착지·판정에 더해 `--read`·hc-fill 레인은 `완료`도 마지막 보고다(레인 기록 `lanes.tsv` 넷째 칸 `read`·`fill` — hc-lane이 띄울 때 적는다. 구현 레인은 3칸 그대로라 `완료` 뒤 감사를 기다리다 혼자 끝나면 여전히 `뜻밖의 종료`). 지휘가 `hc kill`로 닫은 레인(`hc ls`의 `reason: killed`)의 끝남은 알리지 않는다 — parent가 없거나(hc-fill 레인, hc-fill이 `HC_LANE_FILL=1`로 띄움) parent가 아직 살아 있을 때만이다. 지휘 칸이 죽어 함께 끝난 레인(die_with_parent도 `killed`)은 그대로 알린다. hc는 원격 레인의 parent를 묻는 쪽 기준 주소로 준다(레인 기계에선 `<지휘 기계>/t7`, 지휘 기계에선 `t7` — 2026-11-17 실측)라 parent는 그대로 이 기계에서 묻고, 그 주소의 기계를 모를 때(machine_unknown — 바꿔 주지 않은 `<이 기계>/t…` 꼴)만 앞부분을 떼고 다시 묻는다. 조용히 넘긴 killed는 커서에 그 멈춤 열쇠로 적어 지휘가 끝난 뒤에도 다시 오지 않는다. 쉬는 레인은 그 작업 트리 경로가 명령 줄에 든 프로세스(떨어져 나간 배경 검증 등)가 살아 있으면 바쁨으로 본다(`lane.wait_busy_max`분까지).
- 열쇠에 기계 이름 없음(2026-11-17): `seen.*`·`sent`의 열쇠는 기계 칸을 `*`로, 주소는 끝의 `t…`만 쓴다. hc 기계 이름을 바꿔도(`old-name` → `new-name`) 본 사건이 다시 나오지 않고, 옛 판이 적은 줄(기계 이름이 든 그대로)도 같은 사건으로 읽는다.
- 지휘별 거름(`--mine`, 기본 꺼짐): 레인의 hc parent가 부른 터미널(`$HC_TERMINAL_ID` — 원격 레인의 parent는 보통 앞부분 없는 꼴이고, `<이 기계>/<t…>` 꼴도 끝으로 맞춤)인 사건만 찍는다. parent를 모르면(`hc ls`에 없음 — 지워진 터미널 등) 보여 준다. 한 기계에 지휘가 여럿일 때만 쓴다 — 지휘가 바뀌었거나(옛 레인의 parent는 죽은 옛 지휘) wait를 따로 `hc run`으로 감싸 다른 터미널에서 부르면 사건이 다 가려진다. 기본은 전부 찍는다(섞이는 것은 거짓 알림 쪽, 가려지는 것은 놓치는 쪽).
- `hc ls`가 3바퀴 이어 실패하면 wait는 `멈춤` 한 줄(`hc ls 실패 n바퀴(<시각>부터) — 레인 멈춤·끝남을 못 봄`)로 끝낸다.
- `lane.notify no`(기본 `yes`): hc-lane이 띄우는 레인·감사(`--read` 포함)에 `hc run --no-notify`를 붙여, hc가 지휘 입력에 넣는 종료·막힘 알림(`<hc>… exited (signal 1)` — hc-sweep이 일 끝난 레인을 닫을 때마다 온다)을 끈다. 그러면 막힘·오류·뜻밖의 종료는 `hc-lane wait`만 알리므로 **지휘에게 `hc-lane watch`가 돌 때만**(레인을 띄우면 저절로 뜬다) `no`로 둔다.
- 대기열 레인은 부모 없이: hc-fill이 `HC_LANE_FILL=1`로 띄우는 레인·감사 줄(`--on` 포함)에 `hc run --no-parent`를 붙인다 — 대기열이 주인이다. hc run 기본값(부모 = 부른 터미널, 부모가 끝나면 함께 끝남)대로면 지휘 터미널에서 돈 `hc-fill add`·`run`이 띄운 레인이 지휘 세션이 닫힐 때(업데이트 재시작 등) 미커밋 일을 둔 채 꺼졌다(2026-11-19 idle-once 레인). 지휘가 `hc-lane`으로 직접 띄우는 레인은 그대로다.
- 주의: hc도 `XDG_STATE_HOME`으로 코어 소켓을 찾는다. 사건 폴더를 옮기려고 그 값을 바꾸면 hc가 빈 코어를 따로 띄워 `hc ls`가 비고(멈춤을 못 봄), 경로가 길면 소켓 길이 제한으로 실패한다.

## hc-lane 띄우기 (지시문 사본·신뢰 질문·시작 확인·fetch)

```sh
hc-fill add --name <레인> --project <프로젝트> --brief <지시문>                            # 쓰기 레인은 대기열로(아래)
hc-lane --direct --on <기계> --brief <지시문> --name <레인> --repo <그 기계 저장소> -- claude … "{brief} 를 읽고 진행하라"
hc-lane --on <기계> --read --brief <감사 지시문> --name <레인> --repo <그 기계 저장소>   # -- 뒤가 없으면 설정 lane.run 틀
hc-lane fetch --on <기계> --repo <그 기계 저장소> [<참조…>]                               # 감사 대상 커밋 받기
```

- 쓰기 레인은 대기열로(2026-11-19 — 지휘가 쓰기 레인을 직접 띄워 hc-fill 대기열이 비고, 자리가 나도 이어 뜰 것이 없었다): 지휘 터미널(`$HC_TERMINAL_ID`가 살아 있고 레인·감시 터미널이 아님 — 레인 주인을 정하는 것과 같은 판정)이 쓰기 레인(`--read`·`--print-steps`·`--dry-run` 아님)을 `HC_LANE_FILL=1`(hc-fill이 띄울 때) 없이 띄우면 아무것도 만들기 전에 `hc-lane: 쓰기 레인은 hc-fill add로 대기열에 넣는다 …` 한 줄과 종료 2. 지금 꼭 이 자리에 띄워야 하면 `--direct`(오류 출력 `대기열 밖에서 띄움(--direct)`, 레인 기록 `lanes.tsv` 넷째 칸 `direct` — 직접 띄운 비율을 셀 수 있게. wait·send는 구현 레인과 같게 본다). 레인 안(`HC_LANE`)·터미널 밖(launchd·cron)·레인·감시 터미널·판정 못 함(`hc get` 실패)은 그대로 띄운다.
- `--brief`: 지시문에 `--print-steps` 착지·정리 절차를 붙인 사본(`--read`는 판정 알림 줄)을 대상 기계에 두고 실행 명령의 `{brief}`를 그 경로로 바꾼다. 자리는 설정 `lane.brief_dir`(그 기계 경로, `~`는 그 기계 집)의 `<레인>-run.md`, 없으면 지시문과 같은 폴더의 `<이름>-run.md`(그 기계에 같은 경로를 쓸 수 없으면 실패하고 `lane.brief_dir`을 알린다). `{brief}`가 없거나 `--brief` 없이 `{brief}`가 있으면 아무것도 만들기 전에 오류.

- rerere(2026-11-19 lane-overlap-guard — 착지를 다시 설 때마다 같은 충돌을 손으로 다시 풀었다): 쓰기 레인 작업 트리를 만들 때 그 저장소의 공용 git 폴더에 `rr-cache`만 만든다 — 저장소 설정에는 아무것도 쓰지 않는다(2026-11-20 overlap-guard-2: 저장소 설정에 `true`를 쓰면 뒤에 뜬 가지의 조건부 `includeIf "onbranch:…"` `false`를 가렸다, 아스트라 2차 중간 7). git은 `rerere.enabled`를 정하지 않은 가지에서 `rr-cache`가 있으면 켜고, 정해 둔 값(사용자가 끈 `false`, 전역·조건부)은 그대로 따른다. `rerere.autoUpdate`를 켜지 않으므로 land는 `Resolved '<경로>' using previous resolution`으로 푼 경로를 스스로 `git add`한다. `hc-lane land`(내장 착지 — `.claude/herdr-land.sh`가 없는 저장소)는 rebase가 멈추면 git 출력(`LC_ALL=C`)을 보고, 커밋 적용 중(`REBASE_HEAD`) **내용 충돌**로 멈췄고 그 충돌 경로가 모두 `Staged '<경로>' using previous resolution`(autoUpdate) 또는 `Resolved '<경로>' …`(git add 한 뒤)이며 미병합(`git diff --diff-filter=U`)과 `git rerere remaining`이 각각 성공하고 비었을 때만 `hc-lane land: rerere가 기록한 풀이로 충돌을 다 풀었다(<경로>) — rebase를 이어 간다`를 찍고 `GIT_EDITOR=true git rebase --continue`(다음 커밋에서 또 멈추면 같은 판정). 일부만 풀렸거나, 지움·이름 바꿈 충돌이거나, 훅 거절 같은 충돌 아닌 중단이면 멈춘 그대로 종료 3 — 미병합이 비었다는 것만으로는 잇지 않는다. 풀이 기록은 클론마다(`.git/rr-cache`)라 같은 기계에서 다시 선 착지에만 듣는다. `.claude/herdr-land.sh`가 있는 저장소는 그 스크립트가 맡는다.
- **레인 임대**(2026-11-20 fill-dup-guard — 같은 이름의 레인이 두 기계에 함께 뜨지 않게, 중복 막기는 띄우는 쪽에서): 쓰기 레인은 `hc run` 직전에 프로젝트 원격에 `refs/hc-lanes/<레인>`(빈 트리 커밋, 제목 `hc-lane lease <레인> <기계> <UTC>`)을 **없을 때만** 만든다(`push --force-with-lease=<ref>:` — 원격이 원자적으로 판정). 이미 있으면 `hc-lane: 이미 돎 …`과 **종료 10**, 조회·push 실패도 띄우지 않고 종료 1(모르면 안 띄움). 둘 다 방금 만든 워크트리를 되돌린다. push 응답만 잃었으면 원격 값이 이 실행의 것인지로 판정한다. 레인 환경 `HC_LANE_LEASE` = 그 값. `--read`와 origin 없음이 확인된 저장소는 임대가 없다. hc-fill은 10을 「못 띄움」으로 읽어 다음 기계로 가고(거기서도 10이면 그 바퀴는 포기), 그래서 응답을 잃고 다른 기계에 다시 시도해도 둘이 뜨지 않는다.
  - 풀기는 둘뿐: `hc-lane land` 성공(아래 표식과 같은 원자 push에서 `HC_LANE_LEASE` 값일 때만 지움)과 `hc-lane clean`. 그 밖(레인이 죽음·지휘가 `hc-fill rm`)에는 임대가 남는다 — **임대가 남아 다시 못 띄우면** `hc-lane lease drop [--on <기계>] --repo <저장소> --name <레인>`(지금 값은 `hc-lane lease show …`). `hc-fill rm`은 임대를 건드리지 않는다. `hc run`이 실패하면 떴는지 몰라 임대를 남기고 그 명령을 알린다.
- **착지 표식**: `hc-lane land`는 main push와 같은 `--atomic` push에 `refs/hc-landed/<레인>/<UTC 초>`(값 = 착지한 커밋, 지우지 않음)와 임대 지우기를 싣는다. 레인 이름은 `HC_LANE`, 없으면 가지 이름(ref에 쓸 수 있을 때만). 표식·임대 쪽으로 push가 통째 거절되면 검증을 다시 돌지 않고 main만 한 번 더 착지하고, 표식은 그 커밋이 `origin/<기본>`에 들어갔을 때 따로 두고, 임대는 놓지 못하면 알리기만 한다. `.claude/herdr-land.sh`에는 `HERDR_LAND_PUSH_EXTRA="HEAD:refs/hc-landed/<레인>/<초> [:refs/hc-lanes/<레인>]"`로 넘겨 그 스크립트가 main push에 싣게 하고, 안 실었으면 착지 뒤 같은 식으로 따로 둔다. 원격 없는 저장소는 임대·표식이 없다(선행 판정은 제목 규칙만). `--direct`로 띄운 쓰기 레인도 임대·표식은 같다. 병합기 안 착지(`HERDR_MERGER=1`)는 push를 병합기 판 그대로 두고(전송 끊김·응답 유실 판정이 그 인자에 묶임) 표식은 착지 뒤 따로 둔다. 병합기의 제출 ID 표식 `refs/hc-landed/<제출 ID>`와 같은 이름 공간이라 레인 이름이 어떤 제출 ID와 같으면 그 레인 표식은 못 둔다(제목 규칙만 — 제출 ID는 `<기계>-<UTC>-<pid>` 꼴).
- 착지 안전(2026-11-20 land-metrics — 아스트라 감사·운영 모델 「레인은 아무 단계에서나 죽고, push 응답은 사라질 수 있고, git은 실패할 수 있다」): 내장 `hc-lane land`가 보내는 것은 **검증한 커밋 그 자체**다. 바퀴마다 기준 SHA를 고정해 그 SHA로 rebase하고, rebase 뒤 HEAD(후보)를 고정한다 — 조회가 실패·빈 값이거나 그 값이 이 저장소의 커밋이 아니면(`git cat-file -e <sha>^{commit}`) 아무것도 보내지 않는다(빈 후보로 push하면 `:refs/heads/<기본>`, 기본 브랜치 지우기). 후보가 기준 그대로면 보낼 것이 없어 push하지 않고 `이미 들어가 있다`·종료 0. rebase 뒤·검증 뒤에 색인·추적 파일이 후보와 같아야 하고(검증이 파일을 고쳐 통과하면 그 수정은 커밋에 없다), 검증하는 동안 HEAD가 바뀌면 보내지 않는다. push는 `git push origin <후보>:refs/heads/<기본>`(원격 이름으로 — 주소를 넘기면 `pushInsteadOf`가 다시 적용되고 추적 ref가 안 바뀐다). 검증 뒤 origin의 push 주소를 다시 읽어 시작 때와 다르면 보내지 않는다. 진단에 주소는 찍지 않는다(인증정보가 든 주소일 수 있다). git 실패는 성공·없음·「아님」으로 읽지 않는다: `git status`가 실패하면 깨끗함으로 읽지 않고 멈추고, push가 실패로 돌아오면 `git ls-remote origin refs/heads/<기본>`에서 둘째 칸이 정확히 `refs/heads/<기본>`인 줄 하나만 받아(없거나 둘이면 모름 — ls-remote는 `refs/archive/refs/heads/<기본>`처럼 이름 끝도 맞춘다) fetch한 뒤 견주고, 후보가 원격 기본에 들어가 있으면(응답만 사라짐) 착지로 끝내며(종료 0), 그 fetch나 견주기(`merge-base` 종료 0·1 밖)가 실패하면 거절로 읽어 다시 하지 않고 `push 결과 모름`으로 멈춘다(다시 하는 것은 사람 — 들어가 있었으면 같은 줄이 `이미 들어가 있다`). 검증·착지 스크립트는 앞에서 돌려 터미널 Ctrl-C(그룹 SIGINT)면 같이 멈춘다 — hc-lane만 죽고 스크립트가 남아 push하는 일이 없다. `git remote get-url origin`은 종료 2(원격 없음)일 때만 원격 없는 저장소로 보고 다른 실패면 멈추며(원격 저장소인데 로컬 기본을 올리던 기존 결함), 원격 없는 착지에서 `git worktree list`가 실패하면 빈 목록으로 읽지 않고 멈춘다(체크아웃된 기본에 `update-ref`해 메인 폴더가 뒤처지던 기존 결함). 체크아웃된 폴더는 `git merge --ff-only --no-squash`로 올린다 — 저장소 설정 `branch.<기본>.mergeOptions=--squash`면 기본은 그대로인데 0이라 착지한 줄 알았다. 한계: origin의 push 주소는 하나만 지원한다 — `git remote get-url --push --all origin`이 두 줄 이상이면(또는 조회가 실패하면) 내장 착지는 시작하지 않는다(한 곳만 받아도 착지로 정하게 되므로). 브랜치별 조건 설정(`includeIf "onbranch:…"`)도 지원하지 않는다 — 하나라도 있거나 설정 조회가 실패하면 시작하지 않는다(HEAD 상태에 따라 push 주소 등이 바뀐다). origin의 fetch 주소와 push 주소는 같은 저장소를 가리킨다고 본다(git의 원격 전제 — 다른 저장소면 원격 이름을 따로 둔다).
- **주차** `hc-lane park [<한 줄>]`(2026-11-20 — 먼저 띄운 레인이 선행을 기다리며 자리를 쥐었다): 레인 작업 폴더에서, 커밋 안 된 변경·진행 중인 rebase가 없을 때 HEAD를 `refs/park/<레인>`(지금 값에 lease — 2026-11-21 hc-lane-go-start: 제출 가지 `lane/<레인>`과 다른 이름이라 병합기·clean이 주차를 제출로 읽지 않는다)에 올리고 이 레인 임대(`HC_LANE_LEASE` 값일 때만)를 같은 `--atomic` push로 놓은 뒤 「주차」 사건. 결과는 원격을 다시 읽어 본다(응답 유실 — 같은 줄을 다시 돌리면 같은 값으로 모인다). 종료 0 주차, 1 실패, 3 원격 없음. 「주차」는 wait·watch에서 착지·제출처럼 정상 끝이다. 뒤의 `hc-lane clean`은 그 가지를 「주차됨」으로 지운다. 띄울 때 `--resume`이면 새 작업 트리를 `refs/park/<레인>`(없으면 옛 판이 주차한 `lane/<레인>`)에서 만들고 upstream을 `origin/<기본>`으로 둔다(없으면 안 띄움). hc-fill이 선행 착지 뒤 이것으로 다시 띄운다(아래 hc-fill 「주차」).
- `fetch`: 맨 `ssh`나 hc 코어 환경에는 git 자격 도우미 PATH가 없어 「could not read Username」이 난다. `--on`이면 `hc exec`로 그 기계 zsh 로그인 셸(`~/.zprofile`)에 `~/.zshrc`까지 읽고 `git fetch origin [<참조…>]`(설정 단계와 같은 셸). 참조는 하나라도 `-`로 시작하면 거절한다(git 옵션 주입).

## hc-lane 병합기 (제출·merger, 최소판)

2026-11-20 사용자 결정 「중앙 병합기, 브랜치만 (추천)」 → 「병합기 최소 버전을 먼저 만들어서 전체 적용시키고 일단 사용부터 할수 있게」. 왜: 레인마다 fetch·rebase·검증·원격 차례·push를 하니 rebase 충돌·차례 다툼·다시 검증으로 착지가 밀렸다. main에 쓰는 프로세스를 하나로 하면 그 다툼이 통째로 없어진다(bors·GitLab 머지 트레인과 같은 단일 작성자). 다만 **정확성은 main CAS — 표식은 길 안내**다(2026-11-20 지휘 t1cj, 아스트라 3차 높음 1·2): 기본 브랜치에 쓰는 push는 모두 fast-forward·lease 조건이라 병합기가 둘이 돌거나 레인이 직접 착지해도 남의 커밋을 덮지 않는다. 켬 표식은 레인이 제출할지 고르는 안내일 뿐 잠금이 아니다(표식 lease·기계 전환 원자화·진행 중 직접 착지 인계는 두지 않는다). `hc-lane land`의 앞머리(제출 분기, `plain "$base"` 줄 바로 다음)만 병합기 몫이고 그 아래 착지 본문(push·검증)은 착지 안전 레인(land-safety) 몫이다(2026-11-20 지휘·t68 경계 — 나중에 착지하는 쪽이 rebase로 맞춘다).

- **MVP-1이 받는 저장소 = 전용 착지 스크립트(`.claude/herdr-land.sh`)가 없는 저장소**(2026-11-20 지휘 t1cj — 아스트라 2차 뒤 「최소판을 더 작게」, 범용: 저장소 이름을 코드에 박지 않음). 곧 기본 `hc-lane land` 길을 타는 저장소 전부다. MVP-1은 한 건씩만 넣는다.
- **2단계 — 전용 착지 스크립트가 있는 저장소도 받는다**(2026-11-20 지휘 t1cj 「병합기 2단계를 지금 바로」): 병합기 안 착지(`HERDR_MERGER=1`)는 기본 브랜치에 `.claude/herdr-land.sh`가 있으면 **방금 받은 기본 브랜치 판**을 임시 파일로 꺼내 `HERDR_LAND_PUSH_EXTRA`와 함께 맡긴다 — 제출 트리 속 판(레인이 고쳤을 수 있음)은 실행하지 않는다(2차 높음 1). 그래서 그 스크립트는 ① 자기 자리(`$0`)를 쓰지 않고 ② `HERDR_LAND_PUSH_EXTRA`를 기본 브랜치 push에 `--atomic`으로 싣고 lease가 바뀌었으면 종료 6이며 ③ 그 값을 검증 자식에 물려주지 않아야 한다. 기본 브랜치에 없는 스크립트를 제출이 새로 들이면 반송(`막힘` 「…들이는 제출」 — 그 스크립트는 레인이 직접 착지해 먼저 넣는다). 착지 중 rebase로 막 생긴 스크립트를 만나면(종료 7) 일시 실패 — 다음 바퀴가 그 판으로 맡긴다. 후보 임시 작업 트리마다 저장소 준비 훅(`.claude/herdr-setup.sh`, `LANE_REPO` = 병합기 클론, `LANE_BASE`)을 먼저 돌린다(실패는 일시 실패). 후보 임시 작업 트리는 클론 옆 `<클론>.merger-wt/c-*`에 둔다 — `.git` 밖이고 점으로 시작하는 마디가 없어야 한다(2026-11-20 한 저장소의 병합기 첫 착지: `.git/hc-merger/wt/.train-c.*` 아래라 Vite의 `server.fs.deny`(`**/.git/**`)·점 폴더 거절로 브라우저 점검이 403). 준비 훅은 코드 색인 도구(`codebase-memory-mcp`)를 PATH에서 뺀 채 돈다(곧 지울 폴더를 후보마다 색인하지 않게 — 준비 훅이 「도구가 없으면 색인 안 함」).
- **받은편지 레인의 회신은 병합기 결과 뒤**(2차 높음 6·2단계): hc-fill은 받은편지 레인의 마지막 사건이 `제출`이면 병합기 기계가 그 제출 ID로 `착지`·`막힘`을 적을 때까지 회신을 미루고, 그 결과를 보고 끝 줄로 붙인다(`착지 <sha> (병합기 <기계>, 제출 ID …)` 또는 `결과: 실패 병합기 막힘 — …`). 사건을 못 읽은 바퀴는 미룬다.
- **켜고 끄기 — 원격 참조 하나**: 원격에 `refs/herdr/merger/<병합기 기계>`(값은 아무 커밋)가 있으면 켜짐 — 켜기 `git push origin <기본>:refs/herdr/merger/<기계>`, 끄기 `git push origin :refs/herdr/merger/<기계>`(기본 브랜치가 아니라 pre-push 관문과 무관). `hc-lane land`는 착지 전에 `git ls-remote` 한 번으로 보므로 레인이 rebase하지 않아도 모든 기계·레인에 바로 먹고, 착지의 fetch 횟수는 그대로다. 개인 설정이 아닌 까닭: 워커 기계에는 개인 설정(`herdr-tools-config`)이 없어 레인이 도는 기계가 읽지 못한다. 저장소 파일이 아닌 까닭: 파일 내용을 보려면 착지마다 fetch를 한 번 더 해야 한다. 원격 없는 저장소는 늘 꺼짐. 그 참조를 읽지 못하면(켜졌는지 모름) 몇 번(`HC_LANE_MGON_WAITS`, 기본 1·2·4초) 다시 보고, 끝내 못 읽으면 착지하지 않고 종료 75 — 「조회 성공 + 표식 없음」일 때만 예전 착지 길(2026-11-20 아스트라 1차 높음 5: 조회 한 번 실패로 큐를 건너뛰어 main을 올렸다).
- **설정 한 줄로 켜기**(아스트라 1차 중간 10 — 지시문 「설정 한 곳」): hc-fill 설정 `hc-fill.tsv`의 `merger <프로젝트> <병합기 기계>` 줄을 hc-fill이 바퀴마다 그 프로젝트 원격의 켬 표식으로 옮긴다(없으면 `+refs/remotes/origin/HEAD:refs/herdr/merger/<기계>` push, 다른 기계 표식은 지움). 줄을 지우면 표식을 지운다 — 손대는 것은 이 설정이 켠 적이 있는 프로젝트뿐(`$DATA/merger.tsv`). 레인 기계는 개인 설정을 못 읽으니 레인 쪽은 원격 표식만 본다.
- **레인 쪽 — 제출**(`hc-lane land`가 켜진 저장소에서): 감사받은 HEAD 그대로(rebase하지 않음 — 병합기가 한 번 한다) 한 번의 `git push --atomic`으로 `refs/heads/lane/<레인>`·큐 표식 `refs/merge-queue/<UTC초>-<레인>`(같은 SHA)·제출 기록 `refs/merge-queue-meta/<같은 이름>`(빈 트리 커밋, 부모 = 원본, 메시지 `lane= id=<제출 ID: 기계-UTC시각-pid> orig= fork=<갈래점> base= host= term= owner=<HC_LANE_OWNER|-> job=<HC_LANE_JOB|->`)을 올리고 같은 레인의 옛 표식·기록은 같은 push에서 지운다(다시 제출하면 새 것 하나만). 기본 브랜치는 건드리지 않아 pre-push 관문과 무관하다. push가 0이어도 원격을 다시 읽어 세 참조가 모두 그 값일 때 제출로 친다(응답이 끊긴 실패도 같은 판정). 그새 병합기가 처리해 세 참조가 없으면 이 제출 기록이 `refs/merge-done/<레인>`(넣음)·`refs/merge-failed-meta/<이름>`(돌려보냄)에 있는지로 접수를 본다(아스트라 1차 중간 1). 이미 기본 브랜치에 든 커밋이면 할 것 없음. 커밋 안 된 변경·무시되지 않은 새 파일(1차 중간 8)·진행 중인 rebase·레인 이름 꼴(`a-z 0-9 - _` 32자)·원격 읽기 실패는 아무것도 안 보내고 종료 1. 선행 `HERDR_LAND_AFTER`는 최소판에서 뺐다 — 주면 제출하지 않고 1(2026-11-20 지휘: 이름만으로는 그 실행의 선행을 못 가린다, 2판에서 작업 ID로. 선행이 아직이면 hc-fill `--after`가 띄우기를 막는다). 접수가 확정된 뒤에만 이 기계 제출 기록 `<공용 git 폴더>/hc-submitted`(레인·SHA·기본 브랜치)에 한 줄과 사건 상태 `제출`(`제출 <sha> <제출 ID> → <큐>` — 2차 중간 14, 3차 중간 10: `hc-lane wait`·hc-fill은 `제출`을 정상 끝으로 보고, hc-fill `ls` 마지막 보고는 병합기 기계가 그 제출 ID로 적은 착지·막힘으로 바꿔 보인다)을 남긴다. 제출 기록 경로(`git rev-parse --git-path`)를 못 읽으면 제출하지 않는다(3차 높음 5 — 모르면 안 함). 같은 SHA가 이미 그 레인 큐에 있거나 `merge-done/<레인>`이 그 SHA를 담으면 다시 보내지 않고 0. 새 큐 이름은 `merge-failed/<이름>`과도 겹치지 않게 고른다. 접수 판정은 이번 push만의 제출 기록 커밋이 큐 기록 자리(또는 `merge-done`·`merge-failed-meta`)에 있는지로 한다 — 병합기의 main push가 큐 표식을 먼저 지운 틈에도 접수다(2차 중간 1). 원격 설정(`git remote get-url origin`)을 읽지 못하면(원격 없음 = 종료 2가 아니면) 켜졌는지 모르니 75(2차 높음 5). 병합기 클론의 가지 이름과 겹치는 레인 이름(기본 브랜치·`main`·`master`·`merge-batch`·`batch`)도 받지 않는다. 끝 줄 `hc-lane land: 제출 <sha> → refs/merge-queue/… — 병합기(<기계>)가 … 넣고 결과를 사건(착지·막힘 --name <레인>)으로 알린다`, 종료 0(제출 로그는 `land-logs/`). `hc-lane clean`은 제출한 가지를 접수 뒤 바로 지워 자리를 비운다(3차 중간 9 — hc-fill 자리 계산은 그대로): 기본 브랜치에 아직 없는 커밋이라도 원격에 **지금**(`git ls-remote 'refs/merge-queue/*'`, 낡은 추적 참조가 아니라) 그 레인의 큐 표식 `refs/merge-queue/<초>-<레인>`이 그 SHA 그대로면 원격이 그 커밋을 쥐고 있으니 「제출됨」으로 지운다(2026-11-21 hc-lane-go-start: 큐 표식만 본다 — 반송돼 `merge-failed`로 옮겨지고 `lane/<레인>`만 남은 제출은 지우지 않는다). 그 표식이 원격에서 지워졌거나 다른 커밋이면 지우지 않고, 원격을 못 읽으면 멈춘다(2차 높음 4). 제출만 한 커밋으로 `hc-lane report 착지 <sha>`를 부르면(`--name`이어도, 지시문 착지 절대로) 적지 않고 안내 한 줄·종료 0이다 — 원격 `lane/<레인>`(추적 참조)이 그 커밋을 담거나 `hc-submitted`에 있고 기본 브랜치에는 없을 때(1차 중간 7). 착지는 병합기가 `--name <레인>`으로 적는다(거짓 착지는 hc-fill 겹침 소유를 풀고 지표에 남는다 — 2026-11-20 감사 중간 1). hc-fill 겹침 가드는 원격 큐에 그 레인 제출(`refs/merge-queue/<초>-<레인>`)이 남았거나 큐를 못 읽으면 쓰기 소유를 쥐고, 레인 터미널이 살아 있어도 병합기 기계(켬 표식의 기계 — 그 기계 사건도 읽는다)가 그 레인 이름으로 그 터미널의 마지막 사건 뒤에, 또는 그 터미널의 마지막 `제출` 사건과 같은 제출 ID로(같은 초여도 — 3차 중간 11) `착지`를 적으면 푼다(1차 중간 5).
- **병합기 — `hc-lane merger --repo <병합기 전용 클론> [--once] [--tick <초>] `**: 큐를 이름(초) 순으로 묶음(아래, 최대 `HC_LANE_MERGER_BATCH`=3)으로. 바퀴마다 켬 표식이 이 기계(`HC_LANE_MACHINE`, 없으면 `hostname -s`)인지 본다 — 표식이 없으면(꺼짐) 큐를 건드리지 않고 쉬고, 다른 기계면 멈춘다(`막힘` 「병합기 멈춤」, 2차 중간 10). 제출을 레인 이름 그대로의 로컬 가지로 꺼내 `HERDR_MERGER=1 HC_LANE=<레인> hc-lane land`(기존 착지 경로 그대로 — 저장소의 `.claude/herdr-land.sh`·검증·문서 접기·공개 선점 기다림까지)를 부른다. 다른 기본 브랜치로 낸 제출(기록의 `base=`)은 건드리지 않는다(1차 높음 7). 레인 이름이 git 가지 이름으로 못 쓰는 꼴인 큐 항목(「-audit」 등)은 그것만 반송한다(2차 중간 13 — 레인 쪽도 첫 글자가 글자·숫자가 아니면 제출하지 않는다).
  - **원자 선점(구조 B — 1차 높음 4)**: 병합기는 그 착지에 담긴 큐 표식마다 `:<큐 참조> --force-with-lease=<큐 참조>:<제출 SHA>`를 `HERDR_LAND_PUSH_EXTRA`로 넘기고, 착지의 기본 브랜치 push가 `git push --atomic origin <C>:<기본> <그 인자들>`로 함께 지운다. `HERDR_LAND_PUSH_EXTRA`는 착지 표식(fill-dup-guard 「`HEAD:refs/hc-landed/<작업 ID>`」)과 같은 이름·꼴이다 — 공백으로 나눈 git push 인자(refspec, 왼쪽 `HEAD`는 기본 브랜치에 넣는 그 커밋, 그리고 `--force-with-lease=<참조>:<SHA>`)를 그대로 싣는다(2026-11-20 지휘 t1cj). 거절 뒤에는 lease 걸린 참조만 다시 본다. 병합기는 같은 push에 완료 표식 `HEAD:refs/hc-landed/<제출 ID>`도 싣는다 — 중단 복구는 이 표식만 본다(3차 높음 4). 큐 참조를 건드리는 원격 쓰기(착지·완료 정리·반송)는 모두 그 큐 참조의 지금 SHA에 lease를 건다(3차 높음 3). 제출 기록에 작업 ID(`job=`)가 있고 원격에 아직 없으면 착지 표식 `HEAD:refs/hc-landed/<작업 ID>`도 싣는다(2차 중간 12). 이 인자와 `HERDR_MERGER`는 착지만 쓰고 검증 자식(저장소 시험이 다시 부르는 `hc-lane land` 등)에는 물려주지 않는다(2차 높음 3 — 큐 삭제 인자가 herdr-tools 자체 시험의 가짜 원격 push에 실려 거절됐다). 레인이 그새 다시 제출해 표식이 바뀌었으면 기본 브랜치도 안 움직이고(전부 아니면 전무) 착지는 종료 6 — 병합기는 그 후보를 버리고 새 제출을 다음에 넣는다. 그래서 큐 표식은 기본 브랜치가 그 후보를 담을 때만 사라진다.
  - **일지 하나(구조 A — 1차 높음 1·2·3)**: 착지를 부르기 **전에** `<git 폴더>/hc-merger/cur`에 「<후보 가지> <기준 B> <후보 C>」 한 줄과 담긴 제출마다 「<큐 참조> <제출 SHA> <레인> <기록 SHA>」를 tmp→mv로 쓴다. 바퀴마다(시작할 때 포함) 새 제출을 고르기 전에 그 일지부터 정리한다: 원격 `refs/hc-landed/<제출 ID>`가 있고 기본 브랜치의 조상이면 그 제출 완료(착지 커밋 = 그 표식), 그 밖이면 후보를 버리고 제출은 큐에 남았으면 처음부터 다시 고른다. 패치 일치(`git cherry`)는 쓰지 않는다(3차 높음 4 — 같은 패치를 다른 레인이 넣었거나 물린 제출을 「착지」로 셌다). 조회가 실패하면 아무것도 안 하고 쉰다. 착지가 0이 아니어도(응답 유실로 1 등) 돌려보내기 전에 원격이 C를 담았는지 먼저 본다. 후보는 매번 병합기 자기 임시 폴더 `<git 폴더>/hc-merger/wt/c.*`에 새 작업 트리로 만들고 끝나면 지운다 — 클론 자체의 HEAD·작업 트리는 건드리지 않고, 바퀴 시작에 남은 임시 작업 트리를 치운다(3차 높음 6). 최신 기본 브랜치에 rebase한 뒤 `.claude/herdr-land.sh`가 생겼으면 착지는 종료 7이고 병합기가 그 제출을 반송한다(3차 높음 7).
  - **잠금(구조 C)**: 잠금 파일 `…/hc-lane/merger.<클론 경로>.lock`을 셸 fd 19로 열고 flock(macOS는 perl의 flock(2)). 준비 훅·착지·빈 바퀴 sleep은 fd 19를 닫고 부른다 — 병합기가 죽으면 잠금도 바로 놓인다(착지나 검증이 남긴 고아가 살아 있어도). 예전엔 자식까지 물려받아 끊긴 착지의 go 시험 고아가 잠금을 쥐고 새 병합기를 75로 막았다(2026-11-20). 살아 남은 옛 착지와 새 병합기가 겹쳐도 기본 브랜치·큐 lease CAS가 지킨다. pid는 보지 않는다.
  - 들어가면 제출 기록을 `refs/merge-done/<레인>`으로 옮기고(제출한 레인의 접수 확인용 — 기록 없는 큐면 C) `lane/<레인>`·기록을 본 값 조건으로 지운 뒤 `착지` 사건(--name <레인>, 제출 ID). 실패(rebase 충돌·검증 실패·그 밖, 또는 0인데 기본 브랜치에 없음)면 표식을 `refs/merge-failed/<이름>`, 기록을 `refs/merge-failed-meta/<이름>`으로 한 번의 원자 push로 옮기고(`lane/<레인>`은 둠) `막힘` 사건(까닭·원본·기준·제출 ID·로그 `…/hc-lane/merger-logs/<레인>-…log`)을 남긴 뒤 다음 제출로 — 한 제출이 큐를 막지 않는다. 옮기다 원격을 못 보면 멈추지 않고 `hc-merger/fail/<이름>`에 적어 다음 바퀴에 다시(그동안 그 제출만 건너뜀 — 1차 중간 3).
  - **사건은 보낼 함을 거친다**(1차 중간 2): 결과 사건을 `hc-merger/out/<이름>`에 먼저 쓰고 보낸 뒤 지운다 — 그 사이에 죽어도 다음 바퀴가 보낸다. 제출 기록에 지휘(`owner=`, `HC_LANE_OWNER`)가 있으면 `--to <지휘>`, 제출한 레인 터미널(`host=`·`term=` — 병합기 기계면 `<터미널>`, 다른 기계면 `<기계>/<터미널>`)이 살아 있고 그 이름이 레인이면 `hc send`로도 알린다(1차 중간 12·2차 중간 15). 알림이 끊기면 보낼 함에 두고 다음 바퀴에 다시(세 번까지), 사건은 한 제출에 한 번만 — 사건·일지 줄의 열쇠(「제출 ID <ID>」, 기록 없는 큐는 「큐 <이름>」)가 `events.tsv`·`merger-journal.tsv`에 이미 있으면 다시 적지 않는다(보낸 표시 파일은 없앴다). 끊긴 뒤 다시 정리해도 사건·일지 줄이 겹치지 않는다(2차 중간 5). `hc send`는 `hc get --json`의 그 주소가 살아 있고(`state: live`) 맨 위 이름이 레인일 때만 보낸다. 제출 기록(meta)을 못 읽으면 완료·반송을 적지 않고 쉰다(제출 ID 없이 끝내지 않게, 3차 중간 7). 착지 뒤 큐·`lane`·기록 참조가 이 제출 값으로 남았으면 착지로 적지 않고 다음 바퀴에 다시(2차 중간 3). 돌려보낼 기록(`hc-merger/fail/<이름>`)은 다 쓴 뒤 바꿔 넣고, 읽은 칸이 꼴에 맞지 않으면 버린다(2차 중간 4).

## hc-lane gc (끝난 레인 정리)

- 무시된 보관물 `.qa/`: `hc-lane clean`은 지우기 전(teardown 전)에 워크트리의 무시된 `.qa/` 파일(어느 깊이든)을 메인 폴더(첫 작업 트리)의 같은 자리로 복사(덮지 않음, `--on`이면 그 기계 안)하고 `옮김 <워크트리>/.qa → <메인>/.qa (파일 N개 — 새로 a, 이미 같음 b)` 한 줄을 찍는다. 메인에 같은 이름의 다른 파일이 있거나 복사가 실패하거나 메인 폴더를 못 찾으면 그 파일 목록과 함께 멈추고 아무것도 지우지 않는다(2026-11-19 — 레인이 gc의 「남김 … 무시된 보관물 .qa」를 보고 손으로 지우다 출력을 잃었다). gc는 `.qa/`가 남은 작업 폴더를 지우지 않고 남긴다 — 손으로 지우지 말고 `hc-lane clean`.

- `hc-lane gc [--on <기계>] --repo <저장소> [--dry-run] [--integ[=<접두>]] [--remote-branches] [--min-age <시간>]`. 먼저 `--dry-run`으로 본다(`origin/<기본>`은 fetch하지 않고 지금 값으로 판정, `--integ` 판정용 커밋 객체만 받는다 — 참조·작업 폴더·index는 그대로).
- 작업 폴더·가지: 메인 폴더가 아닌 연결된 작업 트리마다 HEAD가 `origin/<기본>`에 다 들어갔고(조상이거나 `git cherry`에 `+` 없음 — rebase로 들어간 것도), 깨끗하고(추적 변경·untracked 없음, 무시된 보관물 `.qa/` 없음), 그 폴더를 cwd로 쓰는 hc 터미널이 없고, 마지막 git 활동이 `--min-age`(기본 24h)보다 오래됐고 멈춘 rebase·merge·cherry-pick·bisect가 없을 때만 teardown → `worktree remove --force` → `branch -D`. 하나라도 아니면 `남김 <폴더> <까닭>`.
- 작업 폴더 없이 남은 로컬 가지: 기본 가지·현재 HEAD·작업 폴더에 붙은 가지·설정 `gc.keep_branches`(빈칸으로 나눈 glob 무늬, 기록용 가지)는 빼고, 같은 판정(병합 커밋이 끼면 안 들어감)에 마지막 커밋과 가지 reflog가 `--min-age`보다 오래됐으면 `branch -D`하고 `지움 가지 <가지> <sha>`를 찍는다. 안 들어간 가지는 지우지 않고 `남김 가지 <가지> 안 들어감 <n>개 · 마지막 <날짜>`.
- `--remote-branches`(기본 꺼짐): 원격 `refs/heads/*` 가운데 기본 가지·`gc.keep_branches`를 빼고 같은 판정이면 ls-remote 때 값 그대로일 때만 지운다. 나이는 커밋 시각뿐이라 옛 main 커밋에 방금 만든 원격 가지도 지우고, 로컬 가지의 원격 짝(upstream·PR)도 빼지 않는다. hc-fill의 정리 바퀴는 이것을 켜지 않는다.
- 「들어감」은 커밋마다 공백까지 같은 패치(`git patch-id --verbatim`)가 `origin/<기본>`에 있을 때다. 공백만 다른 변경은 안 들어감.
- `--integ`(기본 접두 `refs/integ/`): 원격 참조마다 커밋이 `origin/<기본>`에 다 들어갔고 커밋 시각이 `--min-age`보다 오래됐을 때만, ls-remote 때 값 그대로일 때만 지우고 `지움 <참조> <sha>`를 찍는다. 메인 폴더·기본 가지·현재 가지·`refs/tags`·`refs/claims`는 건드리지 않는다(원격 `refs/heads`는 `--remote-branches`일 때만).
- 지운 참조 되돌리기: `git push origin <sha>:<참조>`(찍힌 sha 그대로). 지운 가지는 `git branch <가지> <sha>`.
- 마지막 줄 `지움 n · 남김 m`. hc ls·fetch 실패는 아무것도 지우지 않고 종료 1. hc-fill이 설정 `gc` 분마다(기본 60) 부른다.

## hc-fill (빈 자리에 기다리는 레인을 바로 띄우기, 맥)

```sh
hc-fill add --name <레인> --project <프로젝트> --brief <지시문> [--after <레인>,…] [--only <기계>,…] [--coord <지휘>] [--priority <긴급|높음|보통|낮음>] [--no-early] [--no-audit] [--overlap-ok | --solo]   # 대기열 끝에
hc-fill add --name <이름> --project <프로젝트> --brief <지시문> --then <대기 중인 선행>   # 새 줄 없이 선행 레인에 이어 붙임
hc-fill prio <레인> <긴급|높음|보통|낮음>   # 대기 중인 레인의 우선순위 바꾸기(영어 urgent|high|normal|low도 받음)
hc-fill ls                      # 대기 · 떠 있음(hc 상태) · 끝남 · 되돌려줌(받은편지 결과를 보냄) · 주인 지휘 · 우선 · 마지막 보고 · 먼저 띄움(선행 …) · 이어서 <이름>,… · 자동 감사(감사 중·감사 통과/지적 — 수거 기다림·감사 통과 받음·감사 지적 n번째·지휘로 넘김) · 겹침 대기(<앞 레인>: <키>) · 겹침 봄 끔 · 필요 <능력> — 가진 기계 없음
hc-fill run --dry-run           # 무엇을 어디에 띄울지만. --dry-run 없이 한 바퀴 띄운다
hc-fill watch --every 60        # 계속(한 번에 하나만, 이미 돌면 종료 75)
hc-fill rm <레인>               # 대기열에서만 뺀다(떠 있는 터미널은 그대로)
```

- **지시문은 add 때 복사된다**: 내용을 `~/.local/share/hc-fill/briefs/added/<레인>.md`로 복사하고 대기열에는 그 경로를 적는다(launchd로 도는 `watch`는 macOS 개인정보 보호로 `~/Documents` 등을 못 읽는다). 그 뒤 원본을 고쳐도 반영되지 않는다(`rm` 뒤 다시 `add`). 못 읽거나 빈 지시문은 `add`가 거절하고, `run`도 띄우기 전에 실제로 읽어 보아 못 읽으면 「실패 <레인>: 지시문을 읽지 못함(<까닭>)」을 찍고 띄우지 않는다(대기로 남음).
- **주인 지휘**: `add`는 부른 지휘(`--coord`, 없으면 `$HC_TERMINAL_ID`)를 대기열 줄에 적고 `hc-lane coord --set`으로 지휘 정보를 남긴다. 띄울 때 그 지휘가 아직 살아 있으면(`hc-lane coord --check`) 그 지휘를 `HC_LANE_OWNER`(레인 기록 주인)·`HC_LANE_COORD`(watch 대상)로 넘겨, 그 레인의 `hc-lane report`·멈춤 알림은 그 지휘 한 곳에만 간다. local에 띄운 레인도 그 지휘 옆에 붙인다. 지휘 터미널이 아니면(레인 안·터미널 밖) 주인 없이(`-`) 넣고 한 줄 알린다 — 그 사건은 모든 지휘에게 간다. `--coord`로 준 주소가 지휘가 아니면 거절한다. 받은편지 요청은 주인이 없다. 대기열 레인은 `--after` 사슬로 몇 시간 뒤에 뜰 수 있어, 띄울 때 주인 지휘가 사라졌으면 주인 없이(`-`) 띄우고 watch는 `hc-lane coord` 지휘에게 맡긴다(알림 한 줄).
- **`--then`: 같은 일의 앞뒤 단계는 한 레인**(2026-11-19 — 넘길 때마다 맥락이 새고 지시문에 없는 숨은 결정이 부딪힌다. 맥 대기열 25%가 `--after`에 묶여 사슬이 4단까지 갔고, 선행을 5시간 기다리다 끝난 레인도 있었다): `add --then <선행>`은 새 대기열 줄을 만들지 않고 대기(`wait`) 중인 선행 줄의 지시문 사본 끝에 `## 이어서: <이름> (hc-fill add --then, <시각>)` 절(앞 일을 커밋한 뒤 같은 작업 트리에서 이어서, 그 절의 커밋 제목 머리는 `<이름>:` — 그래서 `--after <이름>`을 건 레인도 풀린다. 앞 일의 완료 보고·착지는 하지 않고 이 절까지 끝낸 뒤 한 번만 `report 완료` — 자동 감사가 반쪽을 감사해 통과로 중간 착지하지 않게)과 지시문 본문을 붙이고 `이어 붙임 <이름> → <선행> (새 레인 없음, 선행 지시문 <경로>)`를 찍는다. 이어 붙인 일은 선행 줄의 기계·우선·먼저 띄움·감사·주인을 따른다. 거절(종료 2, 아무것도 안 바꿈): 선행이 대기열에 없음(그 이름이 다른 줄에 이어 붙어 있으면 「<선행>은 <그 줄>에 이어 붙였다 — --then <그 줄>」), 이미 떴음(「--after로 넣거나 그 레인에 hc send」), 상태 안 잡힘으로 남긴 터미널이 있음(옛 run 지시문으로 돌 수 있다), 지시문 칸이 사본 폴더(`briefs/added/`) 밖(사본 기능 전의 옛 줄 — 원본을 고치지 않는다), 받은편지 줄·자동 감사 줄, 프로젝트가 다름, `--after`·`--only`·`--priority`·`--no-early`·`--no-audit`·`--coord`·`--overlap-ok`·`--solo`와 함께, 이름이 대기열에 있거나 이미 어딘가 이어 붙음, 지시문을 못 읽음. run은 지시문을 잠금 밖에서 읽고 띄운 뒤에야 `up`으로 바꾸므로, `--then`은 도는 run 바퀴가 끝나기를 기다렸다가(`run.lock`, 최대 `HC_FILL_THEN_WAIT`초 기본 600 — 넘으면 종료 75) 대기열 잠금 안에서 확인하고 임시 파일 → `mv`로 붙인다. `ls`는 선행 줄 비고에 「이어서 <이름>,…」. 서로 기대지 않는 일, 겹치는 파일 때문에 순서만 필요한 일은 그대로 `--after`다. `--after`에 대기 중인 같은 프로젝트 레인을 주면 넣기는 그대로 하고 `알림: <X>가 아직 대기 중 — 같은 일의 다음 단계면 --after 대신 --then <X>로 한 레인에 이어 붙인다` 한 줄.

  - 지휘의 `hc-lane watch`에는 레인의 `완료`·감사의 `판정`도 그대로 간다(정보) — 지휘는 감사를 따로 띄우지 않고 「지휘로 넘김」 막힘만 판단한다.
- 띄운 뒤 `HC_FILL_WAIT`초(기본 60) 안에 `hc get` status가 안 잡히면 그 기계를 그 레인에서 빼고 다음 기계로 간다. 그 터미널은 끄지 않고 `ls` 비고에 남긴다. 남긴 터미널이 나중에 status가 잡히면 「중복 위험 <레인> <주소>」를 찍고 그 레인은 더 띄우지 않는다(지휘가 하나를 정리).
- 같은 이름 터미널이 어디선가 살아 있으면 띄우지 않고 떠 있음으로 표시한다. 연결 안 된 기계는 건너뛴다. `hc ls`·`hc machine ls`가 실패하거나, `hc ls`에 설정한 `agent` 종류가 하나도 없으면(지휘 자신도 그 종류라 늘 하나는 있다 — 설정 오타·hc 이름 바뀜) 그 바퀴는 아무것도 띄우지 않는다(종료 1). 아무 터미널도 끄지 않는다(자동 감사 터미널도 — 정리할 주소는 지휘에).
- **받은편지**(설정 `inbox` 줄이 있을 때): 바퀴 처음에 그 기계 폴더의 `<이름>.req`(「키<TAB>값」 줄: `project`·`after`·`only`, 없으면 `-`. `priority`는 `긴급|높음|보통|낮음`(영어도 받음), 없으면 높음)를 검사해 대기열에 넣는다. 접수 때 **요청 ID**(`r<UTC 초 36진>-<난수 6자>`)를 한 번 정해 대기열 11칸(`<기계>:<폴더>/done/<이름>.md#<ID>`)·장부·고정본·레인 보고 경로·요청자 표시에 모두 싣는다. 차례(2026-11-20 fill-handoff-integrity — 같은 이름 새 요청을 옛 요청 잔여물로 옮기거나 반쯤 걷힌 요청을 놓치던 것): 그 기계 `<폴더>/.hc-fill/claim/<이름>`(요청 ID·`.req`·지시문 sha256)을 **먼저** → 지시문을 맥 `~/.local/share/hc-fill/briefs/<기계>/<이름>.<ID>.md`로(해시 확인) → 대기열 줄과 장부 `open`(한 잠금) → 지시문 → `taken/<이름>.<ID>.brief.md` → `.req` → `taken/<이름>.<ID>.req` → 접수 표시 지움. 중간에 죽으면 다음 바퀴가 그 표시의 해시가 지금 원본과 같을 때만 같은 ID로 남은 단계를 잇고, 다르면 새 요청이라 옛 접수가 끝날 때까지 손대지 않는다. `.req` 없이 남은 지시문은 옮기지 않는다. 이름 글자·설정에 없는 project·only 기계·after 이름·모르는 priority 값·대기열에 이미 있는 이름·지시문 없음(공백만 든 빈 지시문 포함)은 둘을 `rejected/`로 옮기고 `rejected/<이름>.why`에 사유 한 줄. 실행 명령·경로·모델은 받지 않는다(설정이 정한다). 요청 쪽은 `.brief.md`를 먼저 쓰고 `.req`를 마지막에 `mv`로 둔다. 연결 안 된 기계는 건너뛴다(요청은 그 기계에 쌓여 있다가 다음 바퀴에).
- 받은편지 레인의 run 지시문 끝에는 「끝나면 이 기계 `~/.local/share/hc-fill/reports/<이름>.<요청 ID>.md`에 다른 이름으로 다 쓴 뒤 `mv`로 두고, 마지막 줄은 `결과: 고침 <sha>`·`결과: 넘김 <사유>`·`결과: 실패 <사유>`」 절이 붙는다. 되돌려 주기(2026-11-20 — 결과를 쓴 터미널이 idle로 살아 있거나 착지가 없으면 안 나가고, 원격 쓰기 뒤 로컬 기록이 실패하면 다시 쓰던 것):
  - 고정: 마지막 줄이 그 꼴인 **완성 보고**면(터미널이 쉬든 일하든, 착지가 있든 없든) 그 내용을 고정본 `~/.local/share/hc-fill/replies/<요청 ID>.md`로 배타 생성하고 장부 `deliver`. 터미널이 끝남 확정(`not_found`·`finished`)인데 완성 보고가 없으면 `결과: 실패 보고 없음`(반쪽이 있으면 그 내용 끝에 `결과: 실패 보고 불완전`). 결과든 취소든 먼저 고정된 것이 이긴다.
  - 공개: 요청한 기계에서 대상마다 잠금(`lockf <폴더>/done/.hc-fill/<이름>.lock`) 안에서 표준 입력 크기·sha256을 확인하고(`BADINPUT`이면 공개 안 함, 다음 바퀴에) `done/<이름>.md`에 `mv`, 표시 `done/.hc-fill/<ID>.sent`(해시)·`done/.hc-fill/owner/<이름>`(ID). 같은 ID가 이미 공개됐으면 `ALREADY` — 공개 뒤 로컬 기록이 실패해도 다음 바퀴는 같은 고정본으로 다시 부르고 요청자 파일을 다시 쓰지 않는다. 그 자리에 다른 요청 ID가 소유한 결과가 있으면 내용이 같아도 장부 `held`로 두고 지휘에 한 번 알린다(`hf:<ID>:held`). 소유 표시가 없는 옛 결과는 해시가 같으면 현재 ID를 소유자로 기록한다.
  - 취소: 받은편지 줄을 `rm`하면 결과가 아직 고정되지 않았을 때 `결과: 실패 취소 — hc-fill rm <시각>`을 고정해 요청자에게 보낸다. 결과가 고정된 대기 줄은 띄우지 않고 뺀다.
  - 장부 `~/.local/share/hc-fill/inbox.tsv`(요청ID 레인 되돌릴곳 상태 종류 해시 크기 비고 시각 — `open`·`deliver`·`sent`·`held`). 넘길 것이 남았으면 대기열이 비어도 바퀴를 돈다. 옛 받은편지 줄(11칸에 `#` 없음)은 결정적 ID `rl…`를 받고 장부에 들어간다(이미 떠 있던 줄은 옛 보고 경로 `reports/<이름>.md`).
  - 한계(모델 밖): 요청자의 숨은 폴더 `done/.hc-fill/`을 다른 프로그램·사람이 지우면 공개 표시가 사라진다 — `done/<이름>.md`가 남아 있으면 해시 대조로 `ALREADY`, 그것까지 지우면 한 번 더 공개될 수 있다. 레인 기계나 요청한 기계가 연결 안 됨이면 다음 바퀴로 미룬다.
- 대기열 `~/.local/share/hc-fill/queue.tsv`(`HC_FILL_DATA`로 바꿈). 11번째 칸은 되돌릴곳(`<기계>:<경로>#<요청 ID>`, 손으로 넣은 줄은 `-`), 12번째 칸은 주인 지휘(없으면 `-`), 13번째 칸은 우선순위(`urgent|high|normal|low`), 14번째 칸은 먼저 띄움(`-` 가능 · `no-early` 끔 · `early` 먼저 띄움으로 띄움 · `parked` 주차함 · `resumed` 주차에서 이어 띄움), 15번째 칸은 자동 감사(`-` 정하지 않음 · `no-audit` 끔 · `auto` 감사·착지 절을 붙여 띄움 · `audit=<레인>` 그 레인의 감사 줄). 10~14칸 옛 줄도 그대로 읽는다(주인 없음, 우선 보통, 먼저 띄움 가능, 자동 감사 대상 아님).
- **설정** `${HERDR_TOOLS_CONFIG:-~/.config/herdr-tools}/hc-fill.tsv`: 코드에는 기계·경로·실행기 같은 개인 값이 없고 모두 여기서 읽는다. 저장소의 `config.example/hc-fill.tsv`(가짜 값)를 복사해 고친다. 줄마다 첫 칸이 종류다. 한 값 키(`local`·`agent`·`coord`·`task`·`launch`·`gc`·`early`·`early_wait`·`idle`·`hold`·`audit`·`audit_max`·`audit_final`·`wake_every`·`ack_max`·`overlap`)는 키 혼자면 빈 값이고, 같은 키가 두 줄이면 멈춘다(종료 1).

## launchd 작업: 지킴이(`hc-launchd-guard`)로 Herdr 터미널에서

launchd가 바로 띄운 새 Go 바이너리는 `~/Documents`에 처음 닿을 때 macOS 개인 정보 보호 창(「'hc-fill'이(가) 문서 폴더의 파일에 접근하려고 합니다」)을 띄우고 사람이 누를 때까지 잠든다. Go 바이너리는 빌드마다 서명이 바뀌어 한 번 허용해도 새 판마다 다시 묻는다(2026-11-21 맥 hc-fill 37분 멈춤). Herdr 터미널(herdr-core가 띄움)과 `hc exec`에서는 창이 안 뜬다. 그래서 두 겹으로 막는다.

- **지킴이**: launchd는 `hc-launchd-guard [--log <파일>] <이름> -- <도구> [인자…]`만 띄운다. 이 기계에 `<이름>` 터미널이 살아 있으면 아무것도 안 하고, 없으면 `hc run --bg --no-parent --outlive-parent --rm --name <이름> --cwd $HOME -- env -u HC_TERMINAL_ID -u HC_SCOPE -u HC_TERMINAL_SOCKET <도구> …`로 Herdr 터미널에서 돌린다. 터미널 표식을 지워 도구는 launchd에서처럼 「터미널 밖」으로 돈다(도구가 띄우는 레인이 그 터미널의 자식이 되어 같이 끝나지 않게). `hc ls`(20초)·`hc run`(60초)에는 상한이 있다. 터미널이 살아 있는지 모르면(hc ls 실패·시간 넘김·목록 아님·state 없는 항목) 띄우지 않고 75로 끝나 launchd가 다시 부르게 하고, 모름이 3번 이어질 때만 그 자리에서 셸 판(`HERDR_IMPL=bash`·`<도구>_IMPL=bash`)으로 도구를 돌린다(셈 `~/.local/state/herdr-go/guard-unknown-<이름>`). 옛 plist처럼 bash 포장을 `python3 <파일>`로 넘겨도 해석기를 빼고 돌린다. 상주 작업은 `KeepAlive`+`ThrottleInterval 60`으로 60초마다 지킴이가 다시 불려 죽은 터미널을 다시 띄우고, 주기 작업(`StartInterval`)은 앞 판이 돌면 건너뛴다. 예시 plist `launchd/`(hc-fill·hc-sweep·herdr-balance). 시험 `tests/hc-launchd-guard.test.sh`.
- **공통 실행기**(`lib/go-run.sh`): 스위치가 `auto`인데 launchd 문맥(TERM 없음·`dumb`, `HC_TERMINAL_ID`·`SSH_CONNECTION` 없음, 조상에 herdr-core·sshd 없음 — macOS 27 실측으로 launchd 작업도 `XPC_SERVICE_NAME=0`이라 그것으로는 못 가른다)이면 Go 판을 부르지 않고 셸 판으로 돈다. 안내는 도구마다 처음 한 번(`~/.local/state/herdr-go/launchd-noted-<도구>`). `<도구>_IMPL=go`로 못박으면 그대로 Go 판.
- 지킴이 없이 남은 launchd 작업도 공통 실행기 덕에 창에 멈추지 않는다(셸 판). 지킴이로 옮기면 Go 판이 돈다.

## 설정

개인 값(기계 이름·경로·계정)은 저장소 밖 설정 폴더 `HERDR_TOOLS_CONFIG`(기본 `~/.config/herdr-tools`)에 둔다. 꼴과 키는 `config.example/`(가짜 값)을 본다.

```sh
herdr-tools-config get balance.remote ""   # 값. 키가 없으면 기본값, 기본값도 없으면 종료 3
herdr-tools-config file hc-fill.tsv        # 설정 폴더의 그 파일 절대 경로. 없으면 종료 3
herdr-tools-config lint [--strict] [<파일>…]  # git ls-files(또는 준 파일)에서 개인 값 패턴(private-patterns.txt)에 걸린 줄. 걸리면 종료 1
herdr-tools-config sync-lint <범용 저장소> [<sync.list>]  # lib/<도구>/가 있는 도구의 bin 줄에 같은 대상(또는 all) lib 나무 줄이 없으면 더할 줄을 찍고 종료 1
```

- herdr-sync는 저장소를 pull한 직후 `sync-lint`를 부르고, 걸리면 아무 데도 쓰지 않고 종료 2로 멈춘다(`--check`도). bin만 깔리면 그 도구가 「함수 파일을 못 읽었다」로 모든 기계에서 멈추기 때문이다(2026-11-20 herdr-tools-split 때 개인 sync.list에 lib 줄이 빠졌다).

- `config`는 한 줄에 `<키> <값>`(값은 줄 끝까지), 키 혼자면 빈 값, `#` 줄은 주석. 같은 키 두 번·잘못 부름은 종료 2.
- lint 패턴은 `$HERDR_TOOLS_CONFIG/private-patterns.txt`, 없으면 `~/.local/share/herdr-tools/private-patterns.txt`. 둘 다 없으면 건너뛴다(종료 0). `--strict`면 패턴 파일이 없거나 패턴 줄이 없을 때 종료 3(`get`·`file`의 「설정 없음」과 같은 코드).
- 검증(`.claude/herdr-verify.sh`)은 `lint --strict`를 부른다: 패턴 파일이 빠진 기계에서는 「실패 개인 값 검사」로 착지하지 않는다(herdr-sync로 패턴 파일을 맞춘다). 패턴이 없는 게 정당한 곳(공개 사본을 받아 검증을 돌리는 쪽 — 공개 트리는 이 저장소 트리와 같아 같은 검증이 들어 있다)만 `HERDR_VERIFY_NO_LINT=1`로 건너뛴다(「건너뜀 개인 값 검사」). 레인 안(`HC_LANE`이 있을 때)에서는 이 값을 무시하고 strict로 돈다(「레인 안이라 HERDR_VERIFY_NO_LINT 무시」).
- lint는 이진·UTF-8 아닌 파일도 바이트로 본다(`LC_ALL=C grep -a` — macOS grep `-I`는 그런 파일을 통째로 건너뛰었다). 상대 경로로 받은 파일(인자 없을 때의 `git ls-files` 포함)은 경로 글자도 보고 `파일:0: 경로 <패턴>`으로 찍는다(절대 경로는 임시 파일 자리라 내용만). 못 읽는 파일이 있으면 종료 2(검사 못 함). `git ls-files`에 있지만 작업 트리에서 지운 파일은 뺀다. 패턴은 바이트 단위다(`LC_ALL=C` — 한글 같은 비ASCII 글자에서 `.`은 글자 하나가 아니라 바이트 하나). 대소문자는 무시한다(`-i`, ASCII만 접힘).

## 파일 크기: 기능별 lib와 줄 수 톱니바퀴

- `hc-lane`·`hc-fill`의 함수는 기능별 파일 `lib/hc-lane/*.sh`·`lib/hc-fill/*.sh`에 있고, 본체(`bin/`)는 최상위 흐름(인자·갈래)만 두고 그 파일들을 정한 순서로 `source`한다(2026-11-20 — 2,044·1,271줄 한 파일을 여러 레인이 함께 고쳐 서로 기다리고 부딪혔다). 본체는 자기 실제 자리(링크면 따라간 곳) 옆 `../lib/<도구>/`를 읽는다: 저장소는 `bin/`↔`lib/`, 깔린 곳은 `~/.local/bin`↔`~/.local/lib`. 그래서 `sync.list`에 lib 나무 줄이 있어야 한다(꼴 `config.example/sync.list` 「도구 lib」). 없으면 `함수 파일을 못 읽었다`로 종료 1.
- 새 함수는 맡은 기능 파일에, 새 기능이면 새 파일을 만들고 본체의 `for … in <모듈 목록>`에 더한다.
- 처음 나눈 도구는 `dev/split/hc-split.py`(계획 `dev/split/plan.tsv`): `split`이 함수 단위로 옮기고 `check <원본 rev>`가 함수마다 정확히 한 번·본문 글자 그대로·`declare -f` 같음을 대조한다(나누기 전 한 파일 판에만 쓴다 — 이미 나눈 판에 `split`을 돌리면 lib를 덮는다).
- `tests/line-budget.test.sh`: 시험(`tests/`)·문서(`*.md`) 아닌 추적 파일은 600줄을 넘지 않는다. 이미 넘은 파일은 `tests/line-budget.tsv`에 적힌 줄 수까지만(늘면 실패, 줄면 통과). 레인 안(`HC_LANE`)에서는 예산을 늘리거나 새 줄을 더하면 실패한다(줄이기·지우기만) — 예산 올림은 지휘·사람이 정한다.

hc-lane 시험은 `HC_LANE_BIN`이 없으면 같은 폴더(`tests/`)나 그 위의 `hc-lane`을 찾는다. 이 저장소에서는 `bin/`에 있으니 `HC_LANE_BIN`을 준다(`HC_LANE`은 레인 이름이라 쓰지 않는다).
