# hc-fill: --then (같은 일의 앞뒤 단계는 한 레인)

- **`--then`: 같은 일의 앞뒤 단계는 한 레인**(2026-11-19 — 넘길 때마다 맥락이 새고 지시문에 없는 숨은 결정이 부딪힌다.
  맥 대기열 25%가 `--after`에 묶여 사슬이 4단까지 갔고, 선행을 5시간 기다리다 끝난 레인도 있었다): `add --then <선행>`은 새 대기열 줄을 만들지 않고 대기(`wait`) 중인 선행 줄의 지시문 사본 끝에 `## 이어서: <이름> (hc-fill add --then, <시각>)` 절(앞 일을 커밋한 뒤 같은 작업 트리에서 이어서, 그 절의 커밋 제목 머리는 `<이름>:` — 그래서 `--after <이름>`을 건 레인도 풀린다.
  앞 일의 완료 보고·착지는 하지 않고 이 절까지 끝낸 뒤 한 번만 `report 완료` — 자동 감사가 반쪽을 감사해 통과로 중간 착지하지 않게)과 지시문 본문을 붙이고 `이어 붙임 <이름> → <선행> (새 레인 없음, 선행 지시문 <경로>)`를 찍는다.
  이어 붙인 일은 선행 줄의 기계·우선·먼저 띄움·감사·주인을 따른다.
  거절(종료 2, 아무것도 안 바꿈): 선행이 대기열에 없음(그 이름이 다른 줄에 이어 붙어 있으면 「<선행>은 <그 줄>에 이어 붙였다 — --then <그 줄>」), 이미 떴음(「--after로 넣거나 그 레인에 hc send」), 상태 안 잡힘으로 남긴 터미널이 있음(옛 run 지시문으로 돌 수 있다), 지시문 칸이 사본 폴더(`briefs/added/`) 밖(사본 기능 전의 옛 줄 — 원본을 고치지 않는다), 받은편지 줄·자동 감사 줄, 프로젝트가 다름, `--after`·`--only`·`--priority`·`--no-early`·`--no-audit`·`--coord`·`--overlap-ok`·`--solo`와 함께, 이름이 대기열에 있거나 이미 어딘가 이어 붙음, 지시문을 못 읽음. run은 지시문을 잠금 밖에서 읽고 띄운 뒤에야 `up`으로 바꾸므로, `--then`은 도는 run 바퀴가 끝나기를 기다렸다가(`run.lock`, 최대 `HC_FILL_THEN_WAIT`초 기본 600 — 넘으면 종료 75) 대기열 잠금 안에서 확인하고 임시 파일 → `mv`로 붙인다.
  `ls`는 선행 줄 비고에 「이어서 <이름>,…」.
  착지 뒤 확인(2026-11-28 ht-revive-cmd — 지휘가 이어 붙인 레인에 1단계 완료 보고를 시켜 1단계만 착지하고 뒤 단계가 사라졌다): `run` 바퀴는 착지한 up 줄(그 실행의 마지막 보고 「착지」)의 사본에 「## 이어서: <이름>」 절이 있는데 기본 가지의 접수 뒤 커밋에 제목 머리 `<이름>:`이 없으면(착지 뒤 명령과 같은 판정) 주인 지휘에 막힘 한 번 `<레인> 이어 붙인 단계 <이름,…>이 착지에 없다 — 그 단계가 안 돈 채 레인이 끝났다(새 줄로 다시 넣어라)`(그 이름을 `--after`로 기다리는 줄이 있으면 그 줄 이름도) — 본 줄은 `then.tsv`(「레인 줄ID 결과」)에 적고 파일이 없는 첫 바퀴는 이미 착지한 줄을 「옛」으로만 적는다(`cmd/hc-fill/thencheck.go`).
  서로 기대지 않는 일, 겹치는 파일 때문에 순서만 필요한 일은 그대로 `--after`다.
  `--after`에 대기 중인 같은 프로젝트 레인을 주면 넣기는 그대로 하고 `알림: <X>가 아직 대기 중 — 같은 일의 다음 단계면 --after 대신 --then <X>로 한 레인에 이어 붙인다` 한 줄.
