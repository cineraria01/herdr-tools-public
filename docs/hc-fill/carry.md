# hc-fill: .qa 자료 싣기

- 까닭(2026-11-26 ht-fill-carry-qa): 지휘가 지시문에 지휘 기계 저장소의 `.qa/…`(git이 따라가지 않는 자료)와 지휘 기계 절대 경로를 적었는데, 레인은 다른 기계의 새 작업 트리에서 떠 그 파일이 없어 멈췄다.
- `add`·`edit`(지시문 바꿈)·`--then`은 지시문 사본을 쓰기 전에 본문의 경로를 훑는다.
  - 상대 `.qa/…`가 지휘 기계 그 프로젝트 저장소(설정 `repo <프로젝트> <local 기계>`)에 없으면 「경고: 지시문의 <경로> 가 <저장소> 에 없다 — 레인 작업 트리에 실리지 않는다」.
  - 지휘 기계 저장소의 `.qa` 절대 경로(`~/…` 꼴 포함)는 사본에서 상대 `.qa/…`로 바꿔 쓴다.
  - 저장소 밖 절대 경로의 일반 파일은 「경고: <경로> — 다른 기계 레인은 이 파일을 못 읽는다 — .qa로 옮겨라 (이번에는 사본을 .qa/carry/<이름> 로 실어 보냄)」을 찍고, 그 파일 사본을 `~/.local/share/hc-fill/carry/<레인>/<이름>`에 두고 지시문 사본의 경로를 `.qa/carry/<이름>`으로 바꿔 쓴다(이름이 겹치면 `2-<이름>`…).
  - 싣는 곳은 집 아래와 임시 폴더(`/tmp`·`/var/folders` — 지휘 scratchpad)뿐이다(`/bin/sh` 같은 시스템 파일은 그대로).
  - 저장소 밖이어도 싣지 않는 것: 실행 파일(부르는 도구 경로), 다른 git 저장소 안 파일(그 저장소 일), 경로 마디가 `.`으로 시작하는 파일(설정·비밀 폴더, `~/.claude-tasks`는 [붙이기](go-impl.md) 몫), 비밀 꼴이 든 파일·상한을 넘는 파일(경고만).
  - 원본 지시문은 바꾸지 않는다.
- 조사가 붙은 경로(`.qa/d/sea.mp4를`)는 붙은 꼴이 없으면 조사를 뗀 꼴로 본다(거짓 「없다」 경고 없음).
- 띄울 때도 지시문 사본에 같은 바꿔 쓰기를 한다 — 깔리기 전에 add된 줄(사본이 옛 꼴)도 싣는다. 데이터 폴더에 같은 내용 사본이 있으면 그 이름을 다시 쓴다(없는 `.qa` 경고는 add 때만, 띄울 때는 아래 알림).
- 띄울 때(쓰기 레인, 받은편지 줄 아님 — 같은 기계든 다른 기계든): 본문의 `.qa/…` 자료(폴더면 통째, 링크는 따라가지 않음)를 작업 트리 상대 이름의 tar 한 묶음으로 만들어 `hc-lane --carry <묶음>`으로 넘긴다.
  - `.qa/carry/<이름>`은 데이터 폴더 사본이 먼저, 없으면 저장소의 것이다. 지휘 기계에 없는 자료는 「알림 <레인>: 지시문의 <경로> 가 지휘 기계에 없어 싣지 않음」 한 줄만 찍고 띄운다.
  - 묶음이 7,340,032바이트(hc exec 입력 상한 아래)를 넘으면(파일을 읽기 전에 크기로 먼저 잰다) 「실패 <레인>: 실어 보낼 자료가 상한 …을 넘음 — 레인을 띄우지 않음」과 주인 지휘에 막힘 사건 한 번(키 `hf:<레인>:carry:<까닭 cksum>`), 줄은 대기로 남는다.
  - 묶음 폴더·파일을 못 만들어도 같은 막힘 사건이다.
  - 넘긴 묶음 파일은 hc-lane이 끝나면 지운다.
- `hc-lane --carry <이 기계 tar>`는 작업 트리를 만들고 설정 훅(`.claude/herdr-setup.sh`)을 돈 직후, 임대를 잡기 전에 그 묶음을 작업 트리에 푼다(`--on`이면 `hc exec -i … tar -xf - -C <작업 트리>`).
  못 풀면 방금 만든 작업 트리·가지를 되돌리고 종료 1이다. `--read`와 함께 쓰면 인자 거절이다.
  - 푼 파일 목록(`cksum` 출력·상대 경로)을 그 작업 트리 git 폴더의 `hc-carry`에 적는다.
  - `hc-lane clean`(남은 것 검사·`.qa` 옮기기 전)과 `hc-lane gc`(git status 전)는 그 목록에서 내용이 그대로인 파일을 지우고 빈 위 폴더를 걷는다 — 실은 파일은 레인 산출물이 아니라 `.qa`를 무시하지 않는 저장소에서 정리를 막지 않고, 무시하는 저장소에서 메인 폴더로 옮겨지지 않는다. 레인이 고친 실은 파일과 git이 따라가는 파일(레인이 커밋했거나 기준에 이미 있는 것)은 그대로 두어 지금처럼 다룬다. `--dry-run`은 거두지 않는다.
- 이미 떠 있는 레인에는 손대지 않는다.
