# hc-fill: 받은편지

- **받은편지**(설정 `inbox` 줄이 있을 때): 바퀴 처음에 그 기계 폴더의 `<이름>.req`(「키<TAB>값」 줄: `project`·`after`·`only`, 없으면 `-`. `priority`는 `긴급|높음|보통|낮음`(영어도 받음), 없으면 높음)를 검사해 대기열에 넣는다.
  접수 때 **요청 ID**(`r<UTC 초 36진>-<난수 6자>`)를 한 번 정해 대기열 11칸(`<기계>:<폴더>/done/<이름>.md#<ID>`)·장부·고정본·레인 보고 경로·요청자 표시에 모두 싣는다.
  차례(2026-11-20 fill-handoff-integrity — 같은 이름 새 요청을 옛 요청 잔여물로 옮기거나 반쯤 걷힌 요청을 놓치던 것): 그 기계 `<폴더>/.hc-fill/claim/<이름>`(요청 ID·`.req`·지시문 sha256)을 **먼저** → 지시문을 맥 `~/.local/share/hc-fill/briefs/<기계>/<이름>.<ID>.md`로(해시 확인) → 대기열 줄과 장부 `open`(한 잠금) → 지시문 → `taken/<이름>.<ID>.brief.md` → `.req` → `taken/<이름>.<ID>.req` → 접수 표시 지움. 중간에 죽으면 다음 바퀴가 그 표시의 해시가 지금 원본과 같을 때만 같은 ID로 남은 단계를 잇고, 다르면 새 요청이라 옛 접수가 끝날 때까지 손대지 않는다.
  `.req` 없이 남은 지시문은 옮기지 않는다.
  이름 글자·설정에 없는 project·only 기계·after 이름·모르는 priority 값·대기열에 이미 있는 이름·지시문 없음(공백만 든 빈 지시문 포함)은 둘을 `rejected/`로 옮기고 `rejected/<이름>.why`에 사유 한 줄. 실행 명령·경로·모델은 받지 않는다(설정이 정한다).
  요청 쪽은 `.brief.md`를 먼저 쓰고 `.req`를 마지막에 `mv`로 둔다.
  연결 안 된 기계는 건너뛴다(요청은 그 기계에 쌓여 있다가 다음 바퀴에).
- 받은편지 레인의 run 지시문 끝에는 「끝나면 이 기계 `~/.local/share/hc-fill/reports/<이름>.<요청 ID>.md`에 다른 이름으로 다 쓴 뒤 `mv`로 두고, 마지막 줄은 `결과: 고침 <sha>`·`결과: 넘김 <사유>`·`결과: 실패 <사유>`」 절이 붙는다.
  되돌려 주기(2026-11-20 — 결과를 쓴 터미널이 idle로 살아 있거나 착지가 없으면 안 나가고, 원격 쓰기 뒤 로컬 기록이 실패하면 다시 쓰던 것):
  - 고정: 마지막 줄이 그 꼴인 **완성 보고**면(터미널이 쉬든 일하든, 착지가 있든 없든) 그 내용을 고정본 `~/.local/share/hc-fill/replies/<요청 ID>.md`로 배타 생성하고 장부 `deliver`. 터미널이 끝남 확정(`not_found`·`finished`)인데 완성 보고가 없으면 `결과: 실패 보고 없음`(반쪽이 있으면 그 내용 끝에 `결과: 실패 보고 불완전`).
    결과든 취소든 먼저 고정된 것이 이긴다.
  - 공개: 요청한 기계에서 대상마다 잠금(`lockf <폴더>/done/.hc-fill/<이름>.lock`) 안에서 표준 입력 크기·sha256을 확인하고(`BADINPUT`이면 공개 안 함, 다음 바퀴에) `done/<이름>.md`에 `mv`, 표시 `done/.hc-fill/<ID>.sent`(해시)·`done/.hc-fill/owner/<이름>`(ID).
    같은 ID가 이미 공개됐으면 `ALREADY` — 공개 뒤 로컬 기록이 실패해도 다음 바퀴는 같은 고정본으로 다시 부르고 요청자 파일을 다시 쓰지 않는다.
    그 자리에 다른 요청 ID가 소유한 결과가 있으면 내용이 같아도 장부 `held`로 두고 지휘에 한 번 알린다(`hf:<ID>:held`).
    소유 표시가 없는 옛 결과는 해시가 같으면 현재 ID를 소유자로 기록한다.
  - 취소: 받은편지 줄을 `rm`하면 결과가 아직 고정되지 않았을 때 `결과: 실패 취소 — hc-fill rm <시각>`을 고정해 요청자에게 보낸다.
    결과가 고정된 대기 줄은 띄우지 않고 뺀다.
  - 장부 `~/.local/share/hc-fill/inbox.tsv`(요청ID 레인 되돌릴곳 상태 종류 해시 크기 비고 시각 — `open`·`deliver`·`sent`·`held`).
    넘길 것이 남았으면 대기열이 비어도 바퀴를 돈다.
    옛 받은편지 줄(11칸에 `#` 없음)은 결정적 ID `rl…`를 받고 장부에 들어간다(이미 떠 있던 줄은 옛 보고 경로 `reports/<이름>.md`).
  - 한계(모델 밖): 요청자의 숨은 폴더 `done/.hc-fill/`을 다른 프로그램·사람이 지우면 공개 표시가 사라진다 — `done/<이름>.md`가 남아 있으면 해시 대조로 `ALREADY`, 그것까지 지우면 한 번 더 공개될 수 있다.
    레인 기계나 요청한 기계가 연결 안 됨이면 다음 바퀴로 미룬다.
