# hc-fill: 자리 세기

- **자리 = 대기열이 띄운 것 가운데 지금 일하는 에이전트**(2026-11-27 ht-seat-working-only, 사용자 결정 「일하는 것만 센다」).
  자리 3인 기계에서 감사를 기다리는 done 레인·닫힌 레인·사람이 연 세션이 「에이전트 7/3」을 채워 자동 감사가 30분 못 떴다(같은 「감사 자리 없음」의 첫 고침은 2026-11-24 fill-audit-seat 감사 몫).
  셈은 `countSeats`(run 출력 「자리 <기계> <주소> <이름>: …」 줄) 한 곳이고, 띄우기·상태 한 장·advise·`ls` 기계 줄 「에이전트 n/상한」·빈 자리 알림이 모두 그 결과를 `machRoom`·`agentsOn`으로 읽는다.
- **세는 것**: 대기열이 띄운 터미널이 지금 일하면 센다 — 상태가 done·idle이 아닌 것(working·blocked 등)과 상태 모름(`-`, 막 띄워 뜨는 중).
  쓰기 레인·자동 감사·운영 에이전트가 같은 규칙이고, 이번 바퀴에 띄운 것(`NOW`)은 띄운 순간부터 센다.
  상태 모름이어도 전경이 셸(hc keep이 끝난 에이전트 대신 띄움)이고 그 레인이 끝났으면 — 이 기계 작업 트리가 없어졌거나 이 실행(`try.tsv` 실행 키)의 마지막 사건(정리됨 빼고)이 제출·착지 — `끝난 레인(hc keep이 셸로 바꿈) → 안 셈`이고, 레인상한(lanesOn)에서도 뺀다.
- **세지 않는 것**: done·idle인 대기열 터미널 — 감사·착지·다시 넣기·지휘를 기다리며 쉬는 것(`쉼 → 안 셈`)이고, 감사 지적으로 다시 working이 되면 그때부터 다시 센다.
  대기열이 띄우지 않은 에이전트 — 사람이 연 세션·지휘 세션·`hc-lane`으로 손으로 띄운 레인·루프(`대기열 밖 → 안 셈`).
- **「대기열이 띄운 것」을 아는 법**: 띄울 때 도구가 적은 기록의 「주소 + 이름」만 본다(터미널 이름·폴더로 짐작하지 않는다).
  ① 대기열 줄(`queue.tsv`)이 `up`이고 그 줄의 주소·이름이 터미널과 같다(쓰기 레인·감사 줄).
  ② 대기열 줄 「남긴것」 칸의 `<기계>=<주소>`(띄웠지만 시작 확인이 안 된 터미널 — 이름은 줄 이름).
  ③ 시도 기록(`try.tsv`)의 미확정 시도가 받은 주소(이름은 레인).
  ④ 운영 에이전트 상태 파일의 도는 실행 주소(이름 `hc-fill-agent`).
  ⑤ 병합기 기록 한 장(`hc-merger --state`, run 바퀴가 병합기마다 받아 둠)의 `agents` — 병합기가 띄운 충돌 풀이·풀이 감사 에이전트의 주소·이름([병합기 상태 한 장](../hc-lane/merger-state.md)).
  이름도 같아야 하므로 주소 재사용에 속지 않고, 주소도 모르는 미확정 시도의 터미널은 세지 않는다(시도 확정 바퀴가 그 레인을 다시 띄우지 않게 지킨다).
- **자리 밖도 보인다**(지휘 2026-11-27 — 오늘 「7/3」의 정체를 손으로 세어야 했다): 기계 줄 `자리 2/3 · 빈 1 · 쉼 3 · 대기열 밖 4`, 상태 한 장 `machines[].resting`·`outside`.
  쉼 = 쉬는 대기열 터미널, 대기열 밖 = 대기열 기록에 없는 터미널 가운데 상태를 보내는 것(에이전트 — 셸·병합기 검증 터미널은 상태가 없어 안 셈).
- **유형 모를 터미널**(`hc ls`에 agent 칸이 없음)은 그대로 그 기계를 이번 바퀴 0으로 둔다(모름은 빈 자리가 아니다) — 사람이 연 Claude·Codex 세션은 agent 칸이 있어 여기에 들지 않는다.
- **깨어난 레인의 넘침**: 쉬던 레인이 다시 일하면 잠깐 상한을 넘을 수 있다 — 이미 받아들인 일은 막지 않고, 그동안 새로 띄우지 않을 뿐이다.
  넘침의 끝은 그 기계 레인상한(살아 있는 쓰기 레인 수, 쉬는 레인도 셈 — `lanesOn` 그대로) + 뜬 감사 수이므로, 굳은 동시 수(예: 기계마다 5)를 지키려면 그 기계 레인상한을 그 아래로 두고, 실제 부하는 부하 관문(`load_busy`)·멈춤([부하 보고 고르기](load-steer.md))이 막는다.
  레인상한이 `-`인 기계는 넘침에 끝이 없다 — 쉬는 쓰기 레인이 쌓인 채 한꺼번에 깨어나면 상한을 크게 넘을 수 있으니, 굳은 동시 수가 있는 기계는 레인상한을 꼭 적는다.
- **걷어낸 것**(두 길로 같은 것을 세지 않게): done·idle 레인을 세던 판정 전부(착지함·`hold`분 넘게 쉼·읽기 레인·분리·깨끗 작업 트리·작업 트리 있음/없음·제출함).
  감사를 기다리는 레인의 「감사 몫」 예약(`RSV`·`rsvOn`) — 쉬는 레인은 원래 안 세니 잡아 둘 자리가 없고, 대신 자동 감사 줄은 바퀴 차례 맨 앞이라 같은 바퀴의 대기 레인(긴급 포함)보다 먼저 빈 자리를 쓴다.
  기계 줄 셈 칸 `all`(쉬는 것도 다 셈) — 칸은 읽되 자리 셈에 아무 일도 안 한다.
  `hold` 손잡이와 `held.tsv`는 남는다 — 선행 판정(쉰 앞 레인, [선행 사슬](dep-chain.md))이 쓴다.
- **그대로인 것**: 레인상한·새 쓰기 레인 띄우기 셈(`lanesOn` — 대기열의 살아 있는 쓰기 레인, 쉬는 것 포함), 연결 안 됨·멈춤(조정), 아래 병합기 검증 터미널 안 셈.
- **병합기 검증 터미널**(추측 일꾼 `spec-<아이디>`·착지 실행 `land-<차례>` — 종류 `env`, `hc-lane=1` 라벨 없음)은 손잡이 `merger_gate@<기계>`와 상관없이 자리·레인상한 어디에도 안 든다 — 대기열이 띄운 에이전트가 아니라 위 셈이 줄에 올리지 않는다. 병합 검증 부하는 저장소 검증 잠금(병합 검증 자리는 그 따로 된 잠금, [추측 검증](../hc-lane/merger-spec-verify.md))과 부하 관문(`load_busy`)이 다룬다.
  기계 줄·상태 한 장은 그 수를 「검증 n(병합 g)」·`merge_verifies`로 따로 보인다([부하 보고 고르기](load-steer.md)). 「검증 1 · 빈 자리 0」이면 빈 자리 0의 까닭은 병합 검증이 아니라 에이전트 자리(대기열이 띄운 일하는 에이전트 — 기계 줄 「에이전트 n/m」)나 레인상한이다(2026-11-26 ht-fill-gate-seat — 시험 `TestGateSeatMergerNotCounted`).
