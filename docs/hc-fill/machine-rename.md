# hc-fill: 기계 이름 바꾸기

- `hc-fill machine --rename <옛> <새> [--dry-run] [--json] [--why <까닭>]`은 대기열이 아는 기계 이름을 한 번에 바꾼다(2026-11-24 machine-rename).
- 사용자 지시: 「테일 스케일 컴퓨터 이름들과 동일하게 해서 좀 여러 컴퓨터가 안헷갈리면 좋겠는데」.
- 그 이름은 설정 파일만이 아니라 상태 파일·손잡이·원격 표식에도 적혀 있다. 설정만 고치면 떠 있는 레인·감사·병합기가 「모르는 기계」가 된다.
- 이 명령은 이 기계(대기열을 돌리는 기계)의 설정·상태만 바꾼다. hc 기계 표·SSH 별칭·다른 기계의 설정은 손으로 맞춘다(끝에 「다음:」으로 알린다).

## 차례

1. hc가 그 기계를 새 이름으로 보이게 한다(hc 기계 표·Tailscale·SSH). `hc machine ls`로 본다.
2. `hc-fill machine --rename <옛> <새> --dry-run`으로 바뀔 자리를 본다. 파일마다 줄 수와 본보기 한 줄, 옮길 병합기 켬 표식, 그 기계에 떠 있는 줄이 나온다.
3. `hc-fill machine --rename <옛> <새> --why <까닭>`으로 바꾼다.
4. 병합기를 옮겼으면 `hc-fill merger restart <프로젝트>`로 다시 띄운다. 옛 병합기(`HC_LANE_MACHINE=<옛>`)는 표식이 옮겨져 스스로 멈춘다.
5. 설정 파일을 개인 저장소에 커밋한다. 이 명령은 설정 파일을 고치기만 하고 커밋하지 않는다(「설정 파일을 고쳤다: <경로> n줄 — 커밋은 직접」).

- 되돌리기는 `hc-fill machine --rename <새> <옛>`이다. 일지(`hc-fill journal`)에 누가·옛·새·되돌리는 명령이 한 줄 남는다.

## 바꾸는 자리

- 바꾸는 것은 기계 이름 칸, 쉼표 목록의 항목, 주소 칸의 `<기계>/…` 접두뿐이다. 글 칸(요약·까닭·사건 글)의 같은 낱말은 그대로다.
- 칸이나 항목이 옛 이름과 정확히 같을 때만 바꾼다. 앞부분이 같은 다른 이름(`<옛>-2`)은 그대로다.
- 다른 줄·다른 칸은 바이트까지 그대로다.

| 곳 | 바꾸는 칸 |
|---|---|
| 설정 `hc-fill.tsv` | `local`·`machine`·`machine-has`·`inbox`의 기계 칸, `repo`·`merger`의 기계 칸, `merger_verifiers`의 목록 항목, `coord`의 주소 접두. 주석 줄과 경로 칸은 그대로 |
| `queue.tsv` | 기계 제한(목록), 띄운 기계, 주소, 남긴것(`<기계>=<주소>`), 되돌릴곳(`<기계>:…`), 주인 지휘 주소 |
| `inbox.tsv` | 되돌릴곳 |
| `audit.tsv` | 기계, 부모 주소(지금 꼴 17칸 줄만 — 옛 7칸 줄은 칸 뜻이 달라 안 본다) |
| `try.tsv` | 기계, 주소, 미확정 때 받은 주소 |
| `reject.tsv` · `load.tsv` · `reach.tsv` · `idle.tsv` · `merger.tsv` | 기계 |
| `own.tsv` | 기계, 주소(`pending:<기계>` 포함) |
| `overlap.tsv` | 기계 제한(목록) |
| `merger-alive.tsv` · `seen.tsv` | 기계, 주소 |
| `held.tsv` · `nudge.tsv` · `onland.tsv` · `onland/*.pending` | 주소 |
| `reland.tsv` | 주인 주소, 보냄·다시 냄 줄의 주소(다른 줄의 그 칸은 레인 이름·결과 글이라 그대로) |
| 손잡이 `~/.local/state/herdr-ops/knobs.tsv` | 기계 묶음 손잡이 이름(`seats@<기계>`·`pause@<기계>`·`light_only@<기계>`) |
| 원격 `refs/herdr/merger/<기계>` | 같은 커밋으로 새 이름에 옮긴다 — 새 참조는 없을 때만 만들고 옛 참조는 본 값일 때만 지운다(한 번의 `--atomic` push) |

- 바꾸지 않는 것: `machine.log`(지난 조정 기록), `briefs/<기계>/`(받은편지 지시문 사본 — 대기열의 지시문 경로가 그 폴더를 가리킨다), 사건(hc-lane — 이미 적힌 줄은 그대로).
- 옛 이름 기록 `machine-alias.tsv`(「옛 새 바꾼 초」)에 한 줄을 더한다. 병합기 사건의 기계 칸은 띄울 때 받은 `HC_LANE_MACHINE`이라, 바꾼 순간 병합 중이던(또는 바꾸기 직전에 적고 바퀴가 아직 안 읽은) 결과 사건은 옛 이름으로 남는다.
  바퀴는 하루 동안 그 옛 이름의 사건도 새 이름 병합기의 것으로 친다(받은편지 회신·반송 다시 맞춤·쓰기 소유 풀기 — 이어 바꾼 이름도 거슬러). 되돌리기는 앞 줄을 빼고 반대 줄을 더한다.
- 상태 파일에 새 이름이 기계 칸에 이미 든 줄(설정에서 지운 기계의 묵은 줄)이 있으면 「다음:」에 줄 수를 알린다 — 바꾸면 그 줄과 합쳐진다.
- 추측 검증 표식(`refs/herdr/spec-verifiers`)은 설정 `merger_verifiers` 줄로 다음 바퀴가 다시 올린다.

## 안전

- run 바퀴 잠금과 대기열 잠금을 쥐고 바꾼다. 바퀴가 도는 중이면 기다리고, 못 쥐면 종료 75로 아무것도 안 바꾼다(`HC_FILL_THEN_WAIT` 초, 기본 600).
- 손잡이 저장 파일은 그 잠금도 쥔다(`knob set`과 겹치지 않게).
- 모든 파일을 먼저 읽어 바꿀 내용을 만든다. 하나라도 못 읽거나 원격 표식을 못 읽으면 아무것도 안 바꾼다.
- 파일마다 임시 파일 → rename으로 쓴다. 도중에 하나라도 못 쓰면 앞서 쓴 파일을 원본으로 되돌린다.
- 원격 표식 push가 실패하면 앞서 옮긴 다른 프로젝트 표식과 파일을 모두 되돌린다. 되돌리지 못한 것은 손으로 고칠 명령과 함께 알린다.
- 떠 있는 레인·감사가 있어도 된다. 그 줄의 기계·주소 칸이 함께 바뀌어 다음 바퀴가 그 터미널을 그대로 이어 본다(다시 띄우지 않고 끝난 것으로 치지 않는다). 감사 줄은 새 이름 기계에 놓인다.

## 거절

- 이름 꼴이 틀림(`a-z 0-9 _ -`, 32자 안, `-`로 시작 못 함 — 추측 검증 기계 이름 검사와 같다), 옛 이름과 새 이름이 같음: 종료 2.
- 옛 이름이 설정 `machine` 줄에 없음, 새 이름이 설정의 어느 기계 칸에 이미 있음: 종료 2.
- 새 이름의 병합기 켬 표식이 원격에 이미 있음: 종료 1.
- 잠금을 못 쥠: 종료 75.
