# hc-fill: 줄 고치기 (edit)

- **줄 고치기는 `edit`** (2026-11-22 — 지휘가 주차 줄의 선행을 바꾸려고 `rm` → `add`를 해 주차 표식이 풀려 준비 커밋을 버리고 새로 뜰 뻔했다): 대기열 잠금 안에서 선행(4)·기계(5)·지시문(3)·우선(13) 칸만 바꾼다.
  `-`는 비우기.
  `--brief`는 대기(`wait`, 주차 포함) 줄만 — 새 사본을 `briefs/added/<레인>.md`에 두고, `--then`으로 「## 이어서:」가 붙은 지시문은 거절.
  `--priority`는 `prio`와 같다(떠 있고 이미 병합기 큐에 냈으면 큐 메타도).
  없는 레인·잘못된 값은 종료 2, 대기열 그대로.
  run 바퀴가 도는 동안은 기다린다(`--then`처럼 run.lock, 상한 `HC_FILL_THEN_WAIT`초·기본 600, 넘기면 종료 75·대기열 그대로) — 바퀴가 지시문 사본을 뜬 뒤 up으로 바꾸기 전에 고치면 대기열은 새 지시문인데 레인은 옛 사본으로 떴다(재감사2 fill/R-208).

## 겹침 검사·먼저 띄움 (2026-11-24 fill-edit-hands)

- 왜: 지휘가 문서 파일 하나 겹침으로 30분 기다린 줄의 겹침 검사를 끄려고 `rm` 뒤 `add --overlap-ok`로 다시 넣었다 — 줄 ID가 바뀌고, 뜨기 직전이면 run과 경합한다.
- `--overlap-ok` | `--overlap-check`: 겹침칸(16)을 `overlap-ok` | `-`로. `--early` | `--no-early`: 먼저 띄움 칸(14)을 `-` | `no-early`로. 다른 칸·줄 ID는 그대로, 옛 짧은 줄은 16칸까지 채운다.
- 다음 바퀴부터 먹는다 — 바퀴가 띄울 때 그 줄의 칸으로 겹침을 보고(`overlap-ok`면 겹침 대기 없음), 선행에만 묶인 줄의 먼저 띄움 칸이 `-`일 때만 먼저 띄움 후보다.
- 아직 안 뜬 줄(대기·주차)만. 거절(종료 2, 대기열 그대로): 이미 뜬 줄(겹침·먼저 띄움은 띄울 때 한 번 본 것), 끝난(되돌려줌) 줄, 감사 줄, 단독(`--solo`) 줄의 겹침, 주차 줄의 먼저 띄움(이미 먼저 띄워 준비 커밋이 있다).
- 같은 칸의 반대 인자를 함께 주면 거절(종료 2). 일지의 되돌리는 명령은 반대 인자다.

## 멈춘 레인 다시 굴리기 (nudge, 2026-11-24 fill-edit-hands)

- 왜: 레인 터미널이 API 일시 오류로 턴을 끝내고(에이전트 CLI가 「메시지를 다시 보내라」, hc 상태 `error`) 멈췄는데 정해진 명령이 없어 지휘가 손으로 `hc send`를 썼다.
- `hc-fill nudge <레인> [<글>] [--why <까닭>]` — 대기열 줄이 떠 있음(up)이고, 그 줄의 주소에 같은 이름의 살아 있는 터미널이 상태 `error`·`done`이며, 그 실행(주소·시작 시각)의 마지막 레인 보고가 없거나 `중간`일 때만 글 하나를 `hc send`로 보낸다.
- 기본 글: 「일시 오류로 턴이 끊겼다 — 작업 트리 상태를 확인하고 지시문의 남은 단계부터 이어서」.
- 한 레인에 손잡이 `nudge_every`분(기본 10, `0`은 막지 않음) 안에 한 번 — 보낸 시각은 `<hc-fill 상태 폴더>/nudge.tsv`.
- 안 보냄(종료 1, 까닭 한 줄): 대기열에 없음·떠 있지 않음, 터미널 없음(끝남), 주소는 같은데 이름이 다름(주소 재사용), 상태가 working·idle·blocked, 그 실행이 이미 완료·막힘·제출·착지·주차를 보고함, 간격 안, 터미널·사건을 못 읽음(모름).
- 보낸 것·보내기 실패는 [운영 일지](../ops/journal.md)에 남는다. 레인의 일을 대신하지 않고, 프로세스를 끄지 않는다 — 한 줄을 보낼 뿐이다. 그 뒤에도 멈춰 있으면 지휘가 들여다본다.
