# hc-fill: PR 거울

- 2026-11-24 pr-surface — 사용자 「우리 전체 Pr 로 전환해서 각 워커가 자기 할일이 끝나면 pr 을 열어서 올리고 지휘 컴퓨터가 코드 리뷰 받은것이나 이런것들을 가지고 … 충돌 머지 병합 하는 병합기는 어때?」.
- 뼈대는 이미 같다(완료 보고 = 제출, 자동 감사 = 리뷰, 감사 통과 = 확인, 병합기 = 머지). 바꾼 것은 흩어진 기록(가지·워커 기계의 감사 보고서·사건 글·병합기 일지)을 **레인마다 PR 한 장**에 모으는 것이다.
- **대기열이 원본, PR은 거울(한 방향).** 대기열·감사·병합기의 상태·판정·차례는 그대로이고, 도구가 그 결과를 PR에 써 준다. PR에서 읽어 판단하는 것은 없다(사람 댓글·보류 표시 읽기는 다음 레인).
- 병합 엔진(검증한 그 트리만 넣는 관문·묶음·미리 검증·patch-id 대조)은 한 줄도 바꾸지 않았다.

## 켜는 법

- `hc-fill knob set pr <프로젝트>[,<프로젝트>…] --why <까닭>` — 다음 바퀴에 먹는다. 기본 `-` = 끔(설정 줄 `pr`도 된다).
- 끄기: `hc-fill knob unset pr`. 꺼져 있으면 gh를 한 번도 부르지 않고 파일·출력·사건이 바이트까지 같다.
- 대기열 기계에 `gh`가 로그인돼 있어야 한다(댓글·커밋 상태·리뷰·닫기).
- PR 작성자를 다른 계정(워커 전체가 쓰는 봇 계정 등)으로: 설정 `pr_token_cmd <명령>` — 토큰을 표준 출력 첫 줄로 내놓는 명령(예: 키체인에서 읽는 명령). 바퀴마다 `sh -c`로 한 번 부르고, 그 토큰은 **PR 열기와 머리 가지 만들기에만** 쓴다(`GH_TOKEN`). 값은 로그·사건·일지·오류 글 어디에도 찍지 않는다. 없으면 기본 gh 로그인, 명령이 실패하면 기본 로그인으로 열고 운영 사건 한 번.
- 손잡이: `pr_inbox`(완료 없이 제출하는 레인도 SHA가 든 첫 보고로 PR을 연다, 기본 1 — 0이면 그 레인은 완료에서만), `pr_max`(바퀴당 gh 호출 상한, 기본 20 — 넘으면 다음 바퀴에), `pr_fail`(gh 실패가 이만큼 바퀴 이어지면 운영 사건, 기본 3), `pr_timeout`(호출 하나의 상한 초, 기본 20). 설정 `pr_context`: 커밋 상태 이름 머리(기본 `herdr` → `herdr/audit`·`herdr/verify`).

## 무엇이 언제 PR에 쓰이나

| 때 | PR에 | 쓰는 쪽 |
|---|---|---|
| 대기열 레인의 첫 완료 보고 | 레인 기계가 그 커밋을 숨은 참조 `refs/herdr/pr-src/<레인>`으로 올리고(그 기계의 git 로그인 — 토큰을 워커 기계로 보내지 않는다), 대기열 기계가 머리 가지 `pr/<레인>`을 그 커밋으로 만든 뒤 PR을 연다 — 제목 「<레인> — <요약>」, 본문 = 요약·지시문 제목·「이 PR은 도구가 관리한다 — 여기서 손으로 머지하지 않는다」 | hc-fill(작성자 인증) |
| 받은편지·`--no-audit` 레인(감사 칸이 `auto`가 아님 — 「완료」 없이 「중간 <sha>」 → 「제출」)의 커밋 SHA가 든 첫 보고(중간·완료·제출) | 위와 같이 PR을 연다(제목의 요약 = 그 보고 글, 무늬 가리기 그대로). 작업 트리가 이미 정리된 제출 보고는 레인 기계의 저장소 폴더에서 원격을 읽고, 커밋은 제출 참조로 이미 원격에 있으니 숨은 참조를 못 올려도 그 커밋으로 머리 가지를 만든다. 손잡이 `pr_inbox 0`이면 이 레인들도 완료에서만 연다 | hc-fill |
| 그 레인의 뒤 보고 | 같은 SHA(「중간 <sha> 감사 완료」 등)는 아무것도 안 씀 · SHA가 바뀐 중간·완료 = 다시 완료(아래) · 열린 PR의 제출은 SHA가 바뀌었어도(rebase) 머리 가지를 옮기지 않는다(글은 「제출됨」) — 병합기는 바퀴 머리에 본 머리 값으로 lease하고 끝 커밋을 제출 SHA의 신원으로 찾으니, 옮기면 lease가 깨져 Merged 대신 닫힌다 | hc-fill |
| 받은편지 레인의 제출 | 「제출됨」 댓글 뒤 자기 감사 리뷰 한 번: 그 실행(같은 터미널)이 PR을 연 뒤 제출 전에 적은 마지막 「감사 완료·통과」 보고 글 + 「보고서는 레인 기계 <기계>」 — 글에서 「높음 0」·「중간 0」이 읽히고 작성자가 다른 계정이면 승인 리뷰, 같으면 댓글. 높음·중간 0을 못 읽으면 승인 없이 그 글을 댓글로. 감사 글이 없으면 「자기 감사 판정을 대기열 기계에서 못 읽음」 댓글. `--no-audit` 레인은 리뷰 없음 | hc-fill |
| 착지가 PR보다 먼저(제출 뒤 바퀴 하나 안에 병합기가 넣음, 또는 gh가 「No commits between」) | PR을 열지 않는다 — 바퀴 로그 「PR 없음 <레인> — 착지가 먼저」 한 줄, 운영 사건 없음. 같은 바퀴에서 받은편지 회신이 먼저 끝나 줄이 `sent`가 됐으면 로그 줄도 없다(PR을 안 여는 결과는 같다) | hc-fill |
| 다시 완료(고침 바퀴) | 머리 가지를 새 커밋으로, 댓글 「다시 완료 <sha8> — <요약>」 | hc-fill |
| 다시 맞춤 레인(`<레인>-reland…`, 원래 이름으로 낸다)·`--pr-of` 레인의 완료 | 원래 PR을 이어 쓴다(새 PR 없음, 머리 가지는 `pr/<원래>`). 원래 이름은 `--pr-of` 기록(`pr-of.tsv`)을 먼저, 다음 다시 맞춤 기록(`reland.tsv` 「넣음」 줄), 없으면 꼬리를 뗀 이름. 원래 PR이 열려 있을 때만 — 없거나 닫힘·Merged면 새 PR(`--pr-of`면 「PR 거울 <레인>: --pr-of <원래> 의 PR이 없거나 이미 닫힘·Merged — 새 PR로」 한 줄, 닫힌 PR을 다시 열지 않는다). 레인 기계가 짝 참조 `refs/herdr/pr-of/<레인>/<원래>`도 올린다 | hc-fill |
| 감사 판정(차수마다 한 번) | 커밋 상태 `herdr/audit`(통과 success · 지적 failure, 설명 「높음 0·중간 0·낮음 2 · 1차」) + 판정 줄과 보고서 본문(길면 앞 6만 자와 「나머지는 <기계>:<경로>」). PR 작성자가 기본 로그인과 다른 계정이면(토큰으로 엶) **진짜 리뷰** — 통과 = 승인, 지적 = 변경 요청. 같은 계정이면 댓글(자기 PR은 승인할 수 없다 — 거절되면 댓글로 바꾼다) | hc-fill(기본 로그인) |
| 제출 | 댓글 「제출됨 — 병합기 줄에 넣음(제출 <ID>, <sha8>)」 | hc-fill |
| 병합 쪽 풀이(시작·감사 통과·못 풂) | 병합기 사건 글 그대로 댓글 | hc-fill |
| 돌려보냄 | 커밋 상태 `herdr/verify` failure + 댓글(까닭·대기열에 들어간 다시 맞춤 레인 이름) | hc-fill |
| 착지 | 병합기가 기본 가지를 올리기 **직전** 묶음 구성원마다 rebase된 그 커밋을 머리 가지에 올린다(본 값 lease) → GitHub가 **Merged**로 표시. 커밋 상태 `herdr/verify` success(설명 = 착지 글의 검증 길) + 착지 댓글. 병합기 글이 「PR 머리 … 들어감」이면 gh로 그 PR의 **실제 상태**를 한 번 읽는다: MERGED면 merged, CLOSED면 pr.tsv closed·바퀴 로그 「PR #n 착지 <레인> — 닫힘(GitHub가 Merged로 표시하지 않음)」·댓글 「착지 <sha8> — 변경은 기준 가지에 들어갔다(표시만 Closed)」, OPEN·못 읽음이면 다음 바퀴에 다시 | 병합기(기본 로그인) · hc-fill |
| 착지했는데 머리 가지를 못 올림 | 댓글 「착지 <sha8> — 가지 갱신 실패로 Merged 표시 없음」 뒤 닫는다 | hc-fill |
| 대기열에서 뺌(`hc-fill rm`) | 까닭 댓글 뒤 닫는다 | hc-fill |

- 보이게: `hc-fill status` 단계 뒤 「 · PR #n」, `hc-fill state`의 레인 줄 끝과 `--json`의 `lanes[].pr`(「PR #n <주소>」), 바퀴 로그의 「PR #n 열음 …」·「PR #n 닫음 …」.
- 개인 값 가리기: PR에 올리는 글(제목·본문·댓글·리뷰·상태 설명)은 `herdr-tools-config lint`와 같은 무늬 파일(`private-patterns.txt`)로 걸린 곳을 「‹가림›」으로 바꾼 뒤 올린다. 무늬를 못 읽으면 올리지 않는다(운영 사건 한 번).
- 두 번 쓰지 않게: 댓글·리뷰마다 숨은 표식 `<!-- hc-fill-pr <사건 열쇠> -->`. 부르기 전에 그 열쇠를 「시도」로 적고, 응답 없이 끝났으면 다음 바퀴에 표식을 먼저 찾아 있으면 단 것으로 본다. 기록 `<DATA>/pr.tsv`(레인·프로젝트·저장소·번호·주소·상태·연 때·작성자·머리)·`pr-sent.tsv`(열쇠).

## 다른 이름으로 다시 내는 레인 (--pr-of)

- 2026-11-24 fill-polish-1124 — 지휘가 다시 내는 레인을 `…-fix`로 넣어 새 PR이 열렸고, 승인까지 붙은 원래 PR은 손으로 닫아야 했다(감사 이력이 두 PR로 갈렸다).
- `hc-fill add … --pr-of <원래 레인>`(또는 `hc-fill edit <레인> --pr-of <원래>|-`)이 `<DATA>/pr-of.tsv`에 「레인 원래」 한 줄을 적는다. 같은 이름을 `--pr-of` 없이 다시 넣으면 그 줄을 지운다. `rm`의 되돌리는 add 줄에도 붙는다.
- 그 레인의 사건(완료·감사 판정·제출·착지·돌려보냄)은 제 PR이 없고 원래 PR이 열려 있으면 원래 PR에 쓴다. 제 PR을 이미 연 레인은 그 PR 그대로.
- 병합기는 묶음 구성원의 머리 가지를 `pr/<레인>` → 없으면 짝 참조 `refs/herdr/pr-of/<레인>/<원래>`의 `pr/<원래>`로 찾는다(`HERDR_LAND_PR_HEADS`의 레인 칸이 `<원래>` — hc-lane은 그 이름으로 머리를 올린다). 착지 사건 글의 「PR 머리 …」도 그 머리를 본다 → 원래 PR이 Merged.
  꼬리 `-reland` 다시 맞춤 레인도 같은 길이다(전에는 병합기가 `pr/<레인>-reland`를 찾아 원래 PR이 Merged가 되지 않았고, 착지 사건도 원래 PR에 쓰이지 않았다 — 작업 중 발견해 함께 고침).
- 착지 관문·판정은 그대로다. 거울이 꺼져 있으면 기록만 남고 아무것도 안 한다.

## Merged가 되는 까닭

- GitHub는 PR 머리 커밋이 기준 가지에 들어가면 그 PR을 Merged로 표시한다. 병합기는 rebase한 새 커밋을 넣으니 원래 머리는 들어가지 않는다 — 그래서 기본 가지를 올리기 직전에 머리 가지를 그 rebase된 커밋으로 옮긴다(지휘가 실제 원격에서 확인: 머리 force-push 뒤 기본 가지 fast-forward → 몇 초 안에 MERGED).
- 머리와 기본 가지는 **따로**, 머리를 먼저 올린다. 같은 push에 넣으면 GitHub가 그 PR을 Closed로 닫는다(2026-11-24 실측 — 착지 스크립트 저장소의 PR 넷).
- 머리 가지를 레인 가지 `lane/<레인>`과 따로 두는 까닭: 착지 push가 `lane/<레인>`을 제출 SHA lease로 함께 지운다 — 그것을 머리로 옮기면 그 lease가 깨져 착지가 거절되고, 지우면 GitHub가 Merged가 아니라 닫힘으로 본다.
- 끝 커밋은 착지 후보에서 신원(작성자·작성 시각·메시지 — rebase가 지키는 것)으로 찾는다. 기준이 안 움직여 rebase가 없었으면 머리가 이미 그 커밋이라 다시 올리지 않는다.
- 착지 뒤 병합기는 머리가 착지 커밋에 들었는지 착지 사건 글 끝에 적는다(「 · PR 머리 <sha8> 들어감」 · 「 · PR 머리 안 들어감(가지 갱신 실패 — Merged 표시 없음)」). 머리 가지가 없으면 글이 전과 같다.
- 착지 판정·관문(「rebase한 트리 = 통과 기록의 트리」, patch-id 대조)은 그대로다. 더한 것은 push 하나와 그 실패 처리뿐이고, 머리 push가 실패해도 착지는 한다.
- 저장소 착지 스크립트(`.claude/herdr-land.sh`)에 맡기는 병합기 안 착지는 머리 가지를 그 스크립트가 올린다 — 아래 계약. 계약을 구현하지 않은 스크립트면 머리가 들지 않아 그 PR은 지금처럼 「Merged 표시 없음」 댓글 뒤 닫힌다. 병합기 밖 착지(레인이 직접 `report 착지`)도 「Merged 표시 없음」이다.

## 착지 스크립트 계약 (PR 머리)

- 2026-11-24 pr-land-hook — 사용자 「피알 열기랑 승인 머지도 … 다 되어야 하고 병합기 지휘도 … 다 되어야해」. 끝 커밋은 스크립트가 자기 rebase(문서 번호 고치기 등) 뒤에야 정해지므로 머리 refspec은 스크립트 안에서 만든다.
- 병합기 안 착지(`HERDR_MERGER=1`)가 스크립트에 맡기면 hc-lane은 받은 `HERDR_LAND_PR_HEADS`를 그대로 넘긴다(꼴이 맞는 항목만). 병합기 밖 착지와 내장 길의 검증 자식에는 넘기지 않는다.
- 값의 꼴: `<레인>=<제출 SHA>=<본 머리 값>`을 빈칸으로. 머리 가지가 있는 묶음 구성원만 들어 있다.
- 머리 가지는 `refs/heads/pr/<레인>`. 구성원의 끝 커밋 = 착지할 커밋의 기록에서 신원(작성자 이름·주소·작성 시각·메시지)이 제출 SHA와 같은 가장 새 커밋. 못 찾으면 그 구성원은 건너뛴다.
- 본 값 lease로 올린다: `<끝 커밋>:refs/heads/pr/<레인> --force-with-lease=refs/heads/pr/<레인>:<본 머리 값>`(병합기는 머리 가지가 있는 구성원만 넘겨 본 값이 늘 있다 — 스크립트가 다른 데서 본 값이 비면 `--force-with-lease=refs/heads/pr/<레인>:`, 없을 때만 만들기). 끝 커밋이 이미 본 값이면 올리지 않는다.
- 기본 가지 push **앞에 따로** 올린다. 같은 push에 넣으면 GitHub가 그 PR을 닫는다(Closed, Merged 아님) — 2026-11-24 실측: 같은 push의 `head_ref_force_pushed`와 `closed`가 같은 초(앞서 「한 번의 atomic push도 된다」고 적었던 것을 바로잡음). 거울은 착지 뒤 PR의 실제 상태를 읽어 Closed면 그대로 적는다.
- **PR 머리 때문에 기본 가지 착지가 막히면 안 된다**: 머리 쪽 lease가 거절되면 머리 인자 없이 다시 push한다(`HERDR_LAND_PUSH_EXTRA`의 lease 거절 — 종료 6 — 과 가려서).
- 이 값을 검증 자식 등 자식 프로세스에 물려주지 않는다(`HERDR_LAND_PUSH_EXTRA`와 같다).
- 도우미: `hc-lane land-prheads [<착지 후보, 기본 HEAD>]`가 내장 길과 같은 판정으로 구성원마다 위 push 인자 한 줄을 찍는다(못 찾은 구성원은 오류 출력에 한 줄, 후보·기록을 못 읽으면 종료 1 — 그때는 머리 없이 착지). 스크립트가 직접 구현해도 된다.
- 착지 뒤 병합기 `done`은 원격을 다시 읽어(`ls-remote`의 `pr/<레인>`) 머리가 착지 커밋에 들었는지 보므로 판정·사건 글은 내장 길과 같다.

## 꺼짐·실패 때

- 거울은 최선 노력이다: gh가 느리거나 실패해도 대기열·감사·병합·착지는 한 줄도 달라지지 않는다. 호출마다 시간 상한(`pr_timeout`), 바퀴당 호출 상한(`pr_max` — 레인 기계의 커밋 올리기도 한 번으로 센다), 실패는 다음 바퀴에 다시.
- 시간 넘김(gh·레인 기계)이 한 번이라도 나면 그 바퀴의 거울은 거기서 멈춘다 — 느린 gh가 바퀴를 `pr_timeout`보다 오래 묶지 않는다(감사 1차 중간 1). 단계마다 해낸 것(커밋 올리기·머리 가지)은 열쇠로 남아 다음 바퀴는 남은 단계만 한다.
- gh가 없는 기계는 바퀴 머리에서 멈춘다(레인 기계에 커밋을 올리지 않음). 거울이 늦어 PR을 열기 전에 이미 착지했으면 열지 않는다.
- 운영 사건 `hc-fill-pr`(한 까닭에 한 번, [운영 사건 목록](../ops/events.md)): gh 실패가 `pr_fail`바퀴 이어짐 · gh 없음 · 원격 주소에서 GitHub 저장소를 못 읽음(그 프로젝트는 조용히 건너뜀) · 무늬를 못 읽음 · `pr_token_cmd` 실패. 성공한 바퀴가 지난 알림을 지워(토큰 실패 빼고) 다시 실패하면 또 한 번 알린다.
- 실제 PR은 시험에서 열지 않는다(가짜 gh·가짜 원격 — `cmd/hc-fill/pr_test.go`·`tests/merger/prhead_test.go`). 실제 확인은 지휘가 켠 뒤 한다.

## 아직 없는 것 (다음 레인)

- PR에서 읽기: 사람 댓글·보류 표시를 대기열 판단에 넣기.
- 「제출됨」 댓글의 병합기 줄 차례(지금은 `hc-fill status`에만).
- 착지 뒤 남은 `pr/<레인>`·`refs/herdr/pr-src/<레인>` 정리(`hc-lane gc`).
- 「정리」로 끝난 레인(착지 없이 `정리됨`, `hc-fill rm` 안 함)의 PR 닫기 — 지금은 `rm`만 닫는다. `정리됨`은 터미널을 닫는다는 뜻이라(제출 뒤 정리도 같다) 착지 없이 끝났는지를 그것만으로 가를 수 없어 뺐다.
- GitHub가 아닌 원격(주소 꼴만 맞는 다른 호스트)에도 숨은 참조를 먼저 올린다 — gh 호출에서 실패해 운영 사건으로 보인다.
