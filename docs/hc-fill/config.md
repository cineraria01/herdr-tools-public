# hc-fill: 설정

- **설정** `${HERDR_TOOLS_CONFIG:-~/.config/herdr-tools}/hc-fill.tsv`: 코드에는 기계·경로·실행기 같은 개인 값이 없고 모두 여기서 읽는다.
  저장소의 `config.example/hc-fill.tsv`(가짜 값)를 복사해 고친다.
  줄마다 첫 칸이 종류다.
  한 값 키(`local`·`agent`·`coord`·`task`·`launch`·`gc`·`early`·`early_wait`·`idle`·`hold`·`audit`·`audit_max`·`audit_final`·`wake_every`·`ack_max`·`overlap`·`lows`·`lows_hour`·`lows_min`)는 키 혼자면 빈 값이고, 같은 키가 두 줄이면 멈춘다(종료 1).

| 줄 | 칸 | 뜻 |
|---|---|---|
| `local` | 이름 | 이 기계(`--on` 없이 띄우는 기계)의 이름 |
| `agent` | 종류 | 셀 에이전트(`hc ls --json`의 `agent`, 기본 `claude-code`) |
| `coord` | 주소 | 지휘 터미널. 주인 없는 줄을 local에 띄울 때 그 옆에 붙인다(`HC_FILL_COORD`가 앞선다, 주인 지휘가 있으면 그 옆). 없으면 붙이지 않는다 |
| `task` | 문장 | 첫 지시. `{run}` 자리에 run 지시문 경로 |
| `launch` | 명령 틀 | `hc-lane … --` 뒤 실행 명령(셸 문법으로 나눈다). `{task}` 자리에 첫 지시가 한 인자로. 모델·추론·실행기를 여기에 |
| `gc` | 분 | 끝난 레인 정리 간격(기본 60, `0`이면 끔). 처음 깔 때는 `gc 0`으로 두고 `hc-lane gc … --dry-run`을 본 뒤 켠다. run 바퀴 끝에 그 간격마다 한 번, `repo` 줄의 기계·저장소마다 `hc-lane gc`(연결 안 된 기계는 건너뜀), `--integ`는 local 기계 저장소에서만. 정리는 **배경**에서 돈다 — 바퀴는 띄우고 바로 끝나며(정리 한 번이 9분 넘게 걸려 감사 수거·띄우기가 멈췄다, 2026-11-21), 앞 정리가 아직 돌면(잠금 `gc.lock`, 프로세스가 끝나면 풀림) 그 바퀴는 띄우지 않는다. 출력은 `~/.local/share/hc-fill/gc.log`, `--dry-run`은 지금처럼 바퀴 안에서. 시각(띄울 때 적음)은 `~/.local/share/hc-fill/gc.last` |
| `early` | 개수 | 먼저 띄움 상한: 살아 있는 먼저 띄움 레인 수. 키 혼자·빼면 남은 자리 전부, `0`이면 끔 |
| `early_wait` | 시간 | 먼저 띄움 레인의 선행 기다림 기한(기본 5) |
| `idle` | 분 | 놀고 있음 알림: 자리가 이만큼 이어서 비면 지휘 watch에 사건(기본 10, `0`이면 끔). 대기열에 띄울 것 없음이면 비기 시작한 뒤 한 번만, 먼저 띄움 상한 사유면 계속 비는 동안 30분 간격으로 세 번, 그 뒤 2시간마다 |
| `idle_empty` | 분 | 「대기열에 띄울 것 없음」 놀고 있음 알림 간격 — 그 간격에 한 번, 빈 기계를 묶어서. 빼거나 `0`이면 안 보냄 |
| `rest_min` | 초 | `watch` 바퀴 사이 최소 쉼(기본 5). 쉼은 `--every` − 바퀴에 든 시간이고, 바퀴가 주기를 넘기면 이만큼만 쉰다. `watch`가 바퀴마다 설정 파일을 다시 읽어 바로 먹는다 |
| `hold` | 분 | 작업 트리가 남은 done·idle 레인도 이만큼 이어서 쉬면 자리를 안 센다(기본 60, `0`이면 끔 = 늘 셈). 위 「자리 세기」 ② |
| `audit` | 경로 | 자동 감사 지시문 틀(맥 경로, `~` 펼침. 예시 `config.example/hc-fill-audit.md`). 없거나 빈 값이면 끔. 위 「자동 감사」 |
| `audit_max` | 횟수 | 감사 지적 뒤 고침 바퀴 상한(기본 2). 넘으면 주인 지휘에 막힘 |
| `lows` | 프로젝트…·`*` | 낮음 후속(2026-11-22 go-lows-followup): 자동 감사가 통과(높음·중간 0)인데 [낮음]이 있으면 그 보고(감사 기계 `reports/audit-<차수>.md`)에서 낮음 원문을 뽑아 `<레인>-lows`를 넣는다 — 같은 프로젝트·주인, 선행 `<레인>`(착지 뒤에만 뜸), 우선 낮음, 먼저 띄움 끔, 자동 감사는 다른 레인과 같다. 지시문 = 낮음 원문 + 「지적마다 고치거나, 고칠 필요가 없으면 까닭 한 줄」 + 원 레인 지시문 자리. 주인 지휘에 「후속 넣음 …」(빼려면 `hc-fill rm`). 받은편지·자동 감사 끈 줄·이미 `-lows`인 레인은 안 넣고, 뽑은 수가 판정 줄 낮음 수와 다르면 안 넣고 주인에 한 줄. 기록 `~/.local/share/hc-fill/lows.tsv`, 차수 줄 16칸 `lows=<n>`·`lowsq`(넣음)·`lowsx`(안 넣음). 빼면 끔 |
| `lows_hour`·`lows_min` | 개수 | 낮음 후속 시간당 상한(기본 3, `0`은 상한 없음 — 넘으면 다음 바퀴)·낮음 최소 개수(기본 1) |
| `audit_final` | 안내 한 줄 | 자동 감사 뒤 최종 감사가 따로 있을 때(2026-11-20 — 레인이 hc-fill 「감사 통과」만 보고 착지했다). 있으면 run 지시문 감사 절 3번이 「`hc-lane verdict` 출력이 감사 통과여도 착지하지 않는다 — 최종 감사(<안내>) 통과 알림 뒤에만」, `ls` 비고가 「감사 통과 받음(최종 대기)」. 없으면 통과 = 착지 |
| `wake_every` | 분 | 판정을 둔 뒤 레인이 수거(`hc-lane verdict`)할 때까지 다시 깨우는 간격(기본 10). 깨우기는 여러 번 가도 무해 |
| `ack_max` | 분 | 수거를 기다리는 상한(기본 30, 기계가 연결된 동안만 셈). 넘으면 주인 지휘에 한 번(기다림은 계속) |
| `overlap` | `warn`·`block`·`off` | 겹침(위 「겹침」). 기본·키 혼자·모르는 값은 `block`(예약끼리 겹치면 대기), `warn`은 띄우고 경고만 |
| `overlap_ignore` | 프로젝트 glob… | 겹침으로 안 셀 경로(저장소 상대 glob, `*`는 `/`도 넘음). 여러 줄 가능, 기본 없음 |
| `machine` | 이름 상한 레인상한 셈 | 위에서부터 차례. 그 기계의 자리를 차지한 `agent` 수가 상한 **미만**일 때만 띄운다. working·blocked는 늘 차지하고, 상태 훅을 아직 안 보낸 hc-lane 레인(라벨 `hc-lane=1`, `hc ls`에 agent가 실행 명령 첫 낱말 — 예 `env` — 이고 status 없음)도 차지한다(2026-11-19 — 워커 기계의 감사 레인 둘을 안 세어 「자리 빔」으로 알렸다. 라벨 없는 다른 종류는 그대로 안 셈). done·idle은 hc-lane 작업 트리(`<저장소>.wt/…`)가 그 기계에 남은 쓰기 레인(감사·착지 기다림)만 차지한다 — 읽기 전용 레인·작업 트리가 정리된 레인·착지한 레인·`hold`분 넘게 쉰 레인은 아니다(판정은 run 출력 「자리 …」 줄). 레인상한은 hc-fill이 띄워 살아 있는 레인 수의 상한(`-`는 없음) — 다른 일이 먼저인 기계를 조금만 쓸 때. 셈이 `all`이면 done·idle도 다 센다(쉬는 동안 done으로 보이는 루프가 있는 기계) |
| `machine-has` | 기계 능력,… | 그 기계가 가진 능력(a-z 0-9 _ - 낱말, 여러 줄이면 합침). 위 「기계 능력」. 빼면 능력 없음 |
| `repo` | 프로젝트 기계 경로 | 그 기계의 저장소. 경로가 없는 기계에는 그 프로젝트를 띄우지 않는다. local 기계 경로로 선행 판정 |
| `inbox` | 기계 폴더 | 받은편지를 걷어 올 기계와 그 기계의 폴더(`~/`는 그 기계 HOME). 여러 줄 가능, 없으면 받은편지를 보지 않는다 |
