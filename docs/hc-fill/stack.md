# hc-fill: 쌓아 띄움 (쌓은 PR)

2026-11-27 사용자 「쌓은 PR 그 방식으로 하자」(업계 이름 stacked PR·stacked diffs). 48시간 실측에서 레인이 기다린 가장 큰 몫이 선행 사슬 대기 7,771 레인-분이었고, 선행은 감사를 통과한 뒤에도 병합 줄에서 평균 50분(느린 10% 111분)을 더 섰다. 뒤 레인은 그동안 [먼저 띄움](early.md)으로 준비만 했다.
쌓아 띄움은 먼저 띄움의 한 갈래다 — 새 대기열·새 승인 체계는 없다. 선행이 **감사를 통과해 제출된 커밋** 위에서 뒤 레인을 띄워 본 일·감사·제출까지 앞당기고, 병합기는 선행 → 뒤 차례만 지킨다.

## 완성된 모습

```
대기(wait) ─ 선행 아직 ─▶ 먼저 띄움 준비(early) ─▶ 주차(parked)
                                                      │ 선행이 감사 통과·제출됨
                                                      ▼
                     쌓아 띄움(stacked, 기준 = 선행 승인 커밋 P) ─▶ 감사(P..HEAD) ─▶ 제출(쌓임 — 선행 A@P)
                                                                                     │
               ┌─────────────────────── 병합기 ──────────────────────────────────────┤
               ▼ 선행 듦(같은 묶음에서 앞이거나 이미 착지)                         ▼ 선행 반송·거둠
       뒤는 P..뒤 커밋만 기본 위에 얹어 듦                     뒤 제출 주차(refs/merge-parked) — 실패 아님
                                                                                     │ 선행이 새 커밋 P'로 다시 제출·착지
                                                                                     ▼
                                     다시 쌓기: P..뒤 를 P' 위로 — 깨끗(자기 patch-id 같음) → 승인 그대로 줄에
                                                                  충돌 → 그 레인 다시 띄워 풀고 다시 감사
                                     선행 지움(rm) → 기본 가지 위로 옮기고 주인 지휘에 알림
```

## 합격 기준
- 손잡이를 켠 프로젝트에서 선행 A가 「감사 통과·제출됨」이 된 바퀴에 뒤 B가 A의 승인 커밋 위에서 뜬다(A 착지를 기다리지 않음).
- B의 감사 범위·승인 patch-id는 `P..HEAD`(자기 커밋만)다. A의 커밋이 감사·승인에 섞이지 않는다.
- 병합기에서 B가 A보다 먼저 드는 길이 없다(묶음 줄이기·범인 가르기·옆으로 빼기·긴급 우선·거둔 뒤 다시 넣기 모두). A가 반송·거둠이면 B는 주차되고 반송 횟수·범인 후보에 들지 않는다.
- 손잡이를 끄면 오늘 동작과 한 글자도 다르지 않다(시험 ⑧).
- 지휘가 착지·켠 뒤 48시간: 선행 사슬 대기 4,000 레인-분 이하 · 쌓인 제출이 선행보다 먼저 든 일 0 · 선행 반송으로 뒤가 「실패」로 돌아온 일 0.

## 언제 쌓나 (hc-fill run)
- 손잡이 `hc-fill knob set stack <프로젝트>[,…] --why …`(기본 `-` 끔). 줄마다 끄는 인자는 지금 있는 `add|edit --no-early` — 그 줄은 먼저 띄우지도 쌓지도 않는다(오늘 그대로).
  따로 `--no-stack` 칸은 두지 않았다: 14칸은 띄움 상태(early·parked·stacked …)로 바뀌어 덮이니 줄 성질을 담을 수 없다(구현 결정 2026-11-27).
- 쌓는 줄: 아직 안 들어간 선행이 **같은 프로젝트의 대기열 줄 하나**(나머지 선행은 다 들어감)이고, 그 선행의 마지막 감사 차수가 통과이고, 원격 `refs/merge-queue/<초>-<선행>`이 그 승인 커밋 P를 가리킬 때. `--then`으로 이어 붙인 이름은 품은 줄로 읽는다.
- 서로 잇지 않은 선행 둘·다른 프로젝트 선행·대기열 밖 선행(제목 규칙만)·감사 전·지적 고치는 중인 선행은 오늘 그대로(먼저 띄움·주차).
- 사슬 깊이: 손잡이 `stack_depth`(기본 2) = B 아래 아직 안 든 조상 수의 상한. 근거: 병합기 묶음 기본 3(`HC_LANE_MERGER_BATCH`)이라 A·B·C 세 겹이 한 묶음에 든다. 넘으면 오늘 그대로 기다린다.
- 떠 있는 먼저 띄움 레인은 건드리지 않는다 — 준비를 마치고 주차하면 다음 바퀴에 쌓아 이어 띄운다(이어 가기 길을 그대로 쓴다).
- 띄움: 대기·`parked`·`bounced` 줄을 hc-lane에 환경 `HC_LANE_STACK=<선행>@<P 40자>`로 — hc-lane이 원격 `lane/<선행>`을 `refs/hc-stack/<레인>`으로 받아 P인지 보고 거기서 작업 트리를 만든다(아니면 거절 — 다음 바퀴에). `--resume`(주차 가지)이면 주차 가지에서 만들고 레인이 절대로 `git rebase P`. upstream은 `origin/<기본>` 그대로. 14칸 `stacked`, 기록 `<상태 폴더>/stack.tsv`(레인·줄 ID·선행·P·선행 큐 이름·상태·시각 — 쌓지 않고 다시 띄우면 지운다).
- 지시문 끝 블록(먼저 띄움 블록 자리) 「## 쌓아 띄움 — 기준은 선행 <선행> <P 8>(아직 기본 가지에 없음)」: 본 일을 끝까지 하고 완료 보고, 자기 범위는 `P..HEAD`, 선행 파일은 고치지 않는다(고칠 것이 나오면 막힘), `git rebase origin/<기본>` 하지 않는다.

## 기록 칸
| 자리 | 값 |
|---|---|
| 대기열 14칸 | `stacked` 쌓아 띄움 · `no-stack` 줄 끔 |
| 레인 환경 | `HC_LANE_STACK=<선행>@<P>` — 자동 제출(`HC_LANE*`를 옮김)·감사·verdict·land가 읽는다. 없으면 오늘 길 |
| 제출 기록(메타) | `stack=<선행>@<P>` 한 칸 더 · `fork=<P>` |
| 병합기 주차 | `refs/merge-parked/<이름>`·`refs/merge-parked-meta/<이름>`(큐·기록 그대로 옮김, 원자 push·lease) + 사건 「주차(선행 반송) <선행>」 — 막힘이 아니라 중간 |
| hc-fill | `stack.tsv` 상태 `up`(띄움 — 제출 여부는 병합기 줄이 말한다)·`parked`·`restacked`·`relaunch`·`rebased-main` |

## 감사·제출
- 감사 지시문의 `origin/{base}` 자리를 P로 바꾼다(`audit.go` 한 곳) — 감사가 `P..<sha>`를 본다.
- `hc-lane verdict`·`land --verdict`의 승인 patch-id는 `merge-base(sha, 기본)` 대신 P부터(`lpatch(P, sha)`).
- 제출 때 충돌 판정(긴 검증 뒤 반송될 것을 미리 거르는 싼 사전 검사)은 쌓인 제출이고 P가 아직 기본 가지에 없으면 하지 않는다(2026-11-27 지휘 안 A — 선행 없이 견주는 판정은 두 번 틀렸다). P가 들었으면 오늘 판정 그대로(갈래점이 P라 자기 커밋만 견준다). 한 곳 `cmd/hc-lane/stack.go` `stackSkipConflict`.
- 그 충돌은 병합기가 후보를 지을 때 본다: 쌓인 맨 앞은 늘 병합기가 `--onto <기준> P`로 자기 커밋만 얹고, 부딪히면 검증을 맡기기 전에 그 제출만 반송(사건 「쌓인 제출 — 선행 <이름> 위에 자기 커밋을 얹다 충돌: <파일>」과 다시 맞추는 법 `git rebase --onto origin/<기본> <P>`). 묶음 뒤쪽 구성원이 부딪히면 그 바퀴 묶음에서 빠져 큐에 남고 맨 앞이 되면 같은 길. 선행·같은 묶음의 다른 구성원은 반송·횟수에 들지 않는다.

## 병합기 규칙 넷
1. **차례**: 쌓인 제출은 선행 제출이 들었거나(`refs/merge-done/<선행>`의 원본 = P, 또는 기본 가지가 P를 담음) 같은 묶음에서 선행보다 뒤일 때만 고른다. 우선·이름 순보다 앞서는 걸림이라 묶음 줄이기·범인 가르기 앞 무리·옆으로 빼기·긴급·다시 넣기 모두 같은 고르기 함수를 지난다 — 선행이 빠진 무리에는 뒤도 없다.
2. **선행이 빠지면 주차**: 선행 큐가 없고 듦도 아니면(반송 `merge-failed`·지휘 거둠) 쌓인 제출을 `merge-parked`로 옮긴다. 반송 횟수·범인 후보·다시 맞춤·반송 다시 띄우기에 들지 않는다.
3. **자기 커밋만 얹음**: 후보를 지을 때 쌓인 구성원은 `git rebase --onto <앞 후보> P <제출>` — 선행이 다시 쓰인 sha로 들어갔어도 P..제출 만 얹는다. 승인 대조(`approved`·`applied`)의 갈래점은 P다. 그 뒤는 오늘의 「기준만 움직임」 길.
4. **추측 사슬**: 앞 무리 추측(기본+A, 기본+A+B)은 오늘 길 그대로 — 1·3이 구성원 목록과 얹기만 바꾼다.

## 다시 쌓기 판정 (hc-fill 바퀴 `stackTick`, 14칸 `stacked`·떠 있음 줄에 원격 `refs/merge-parked/<초>-<레인>`이 있을 때 — `restack.go`)
- 선행이 감사 통과 제출 P'로 다시 줄에 서면 P' 위로, 선행이 들었거나(착지 판정) 대기열에서 빠졌으면 기본 가지 위로: 임시 작업 트리에서 `git rebase --onto <새 기준> P <뒤>`. 깨끗하고 `patch-id(새 기준..새) = 기록의 patch=`이면 기록의 `orig=`·`fork=`·`stack=`만 바꾼 새 기록으로 새 큐 이름에 다시 넣는다(주차 둘 지움·큐 둘·`lane/<레인>` — 한 번의 원자 push, 모두 lease). 판정·patch는 그대로라 병합기가 그 patch-id를 다시 대조한다.
- 충돌이거나 patch-id가 다르면 주차 참조를 `refs/hc-restack/<이름>`으로 옮기고(다음 바퀴가 다시 보지 않게) 그 줄을 반송 다시 띄움 대기(14칸 `bounced`)로 — 절 「다시 쌓기」가 그 커밋으로 옮겨 새 기준 위로 풀고 다시 감사받게 한다. 선행이 아직 줄에 있으면 띄울 때 다시 쌓아 띄움이 붙는다.
- 선행이 아직 고치는 중(줄에 없고 들지도 않음, 대기열 줄은 있음)이면 기다린다. 선행 줄이 대기열에서 빠졌으면 결과와 함께 주인 지휘에 중간 한 줄.

## 먼저 띄움과 달라지는 점
| | 먼저 띄움 | 쌓아 띄움 |
|---|---|---|
| 기준 | `origin/<기본>`, 선행 착지 뒤 rebase | 선행 승인 커밋 P |
| 선행 전 할 일 | 준비만 → 주차 | 본 일·감사·제출까지 |
| 선행 반송 | 영향 없음(아직 안 함) | 뒤 제출 주차 → 다시 쌓기 |
| 켬 | `early` 손잡이 | `stack` 손잡이(프로젝트별) + `early` |

## 보이기
- `ls`·`status`: 「쌓아 띄움(선행 <선행> <P 8> 제출됨)」·「쌓아 띄움 — 주차(선행 반송)」·「다시 쌓음」. 병합기 일지 까닭에 「쌓임 <선행>」, 상태 기록 구성원에 `stack`.
- `advise`의 「선행 대기」는 `stacked` 줄을 기다림으로 세지 않는다.
- PR 거울: 이번 판은 바꾸지 않았다 — 쌓인 레인 PR도 바탕이 기본 가지라 선행이 들기 전에는 선행 커밋이 PR 차이에 함께 보인다(병합·감사 범위와 무관한 표시). 바탕을 `pr/<선행>`으로 두고 선행이 들면 기본 가지로 옮기기는 ghpr에 바탕 바꾸기와 PR 기록 칸이 필요해 다음 단계 후보.

## 되돌리기
`hc-fill knob set stack - --why …` — 다음 바퀴부터 새로 쌓지 않는다. 이미 쌓인 제출은 병합기 규칙 1~3으로 끝까지 간다(끄더라도 선행보다 먼저 들지 않음). 코드 되돌림은 이 레인 커밋들을 revert(대기열·메타 칸은 없으면 오늘 길로 읽는다).

## 하지 않는 것
감사·승인·착지 관문을 약하게 하지 않는다. 겹침 대기(선행으로 적지 않은 같은 파일 레인)를 쌓기로 바꾸는 것은 다음 단계 후보.
