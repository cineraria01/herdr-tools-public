# hc-lane gc (끝난 레인 정리)

- 무시된 보관물 `.qa/`: `hc-lane clean`은 지우기 전(teardown 전)에 워크트리의 무시된 `.qa/` 파일(어느 깊이든)을 메인 폴더(첫 작업 트리)의 같은 자리로 복사(덮지 않음, `--on`이면 그 기계 안)하고 `옮김 <워크트리>/.qa → <메인>/.qa (파일 N개 — 새로 a, 이미 같음 b)` 한 줄을 찍는다.
  메인에 같은 이름의 다른 파일이 있거나 복사가 실패하거나 메인 폴더를 못 찾으면 그 파일 목록과 함께 멈추고 아무것도 지우지 않는다(2026-11-19 — 레인이 gc의 「남김 … 무시된 보관물 .qa」를 보고 손으로 지우다 출력을 잃었다).
  gc는 `.qa/`가 남은 작업 폴더를 지우지 않고 남긴다 — 손으로 지우지 말고 `hc-lane clean`.
  gc도 clean과 같은 탐색(어느 깊이든 `.qa` 폴더 + `git check-ignore`)을 써서 무시된 폴더 안(`build/.qa/`)도 본다.
  탐색이 실패하면 그 작업 폴더를 남기고 종료 1이다(R-3A20).

- `hc-lane gc [--on <기계>] --repo <저장소> [--dry-run] [--integ[=<접두>]] [--remote-branches] [--min-age <시간>]`. 먼저 `--dry-run`으로 본다(`origin/<기본>`은 fetch하지 않고 지금 값으로 판정, `--integ` 판정용 커밋 객체만 받는다 — 참조·작업 폴더·index는 그대로).
- 작업 폴더·가지: 메인 폴더가 아닌 연결된 작업 트리마다 HEAD가 `origin/<기본>`에 다 들어갔고(조상이거나 `git cherry`에 `+` 없음 — rebase로 들어간 것도), 깨끗하고(추적 변경·untracked 없음, 무시된 보관물 `.qa/` 없음), 그 폴더를 cwd로 쓰는 hc 터미널이 없고, 마지막 git 활동이 `--min-age`(기본 24h)보다 오래됐고 멈춘 rebase·merge·cherry-pick·bisect가 없을 때만 teardown → `worktree remove --force` → `branch -D`. 하나라도 아니면 `남김 <폴더> <까닭>`.
- HEAD가 커밋을 가리키지 않는 작업 트리(지워진·태어나지 않은 가지, `worktree list`의 HEAD `0000…`)는 그 가지가 정말 없을 때(`rev-parse --verify` 종료 1) `남김 깨진 작업 트리 <폴더> — HEAD가 없는 가지 <이름>을 가리킴(사람이 본다)`으로 남긴다 — 지우지 않고(커밋 안 된 작업이 있을 수 있다) 오류로도 세지 않는다(그 줄만이면 종료 0). 가지 조회가 실패하면 지금처럼 「들어갔는지 확인하지 못함」·종료 1(small-usage-fixes 2026-11-23 — 한 워커 기계에서 hc-fill의 시간당 gc가 사흘 내내 종료 1이었다).
- `--on`에서 hc 자신이 실패하면(모르는 기계 등) 그 한 줄(`hc exec 실패(<kind>, …)`)로 끝내고 「git 저장소가 아니다」를 잇지 않는다(종료 1 그대로, clean·띄우기 `--read`도 같다).
- 「그 폴더를 cwd로 쓰는 터미널」(gc·clean)은 이 기계면 글자가 아니라 디스크로 본다(`hcjson.Uses` — 작업 폴더를 stat하고 cwd에서, 또 cwd의 심볼릭 링크를 푼 실제 경로에서 위로 올라가며 `os.SameFile`, stat·링크 풀기가 「없음」 말고 다른 오류면 쓰는 중. 2026-11-23 gofix5 lane/R-4A02: macOS 기본 파일 시스템은 대소문자·한글 정규화를 가리지 않아 다른 철자로 띄운 터미널을 놓쳤다). `--on`은 그 기계 경로를 여기서 stat할 수 없어 글자로만 견준다(한계).
- 띄운 폴더(`hc ls` cwd)로 아무도 안 쓰면 대상 기계의 나머지 터미널마다 `hc get`(상한 10초, 한 목록에 한 번 — gc는 작업 트리마다 다시 묻지 않고 지우기 직전 새 목록에서 다시)으로 지금 폴더(`foreground.cwd`)도 본다 — 그 폴더(아래)면 쓰는 중(`<주소> <폴더>(지금 폴더)`), 못 얻으면 `<주소> ?(지금 폴더 모름: …)`으로 남긴다(2026-11-23 cwd-now-inuse — `hc ls` cwd는 띄울 때 폴더라 띄운 뒤 `cd`로 들어온 지휘를 놓쳤다).
  메인 폴더 앞당김(`mainbusy`)도 띄운 폴더가 딴 곳인 일하는 터미널의 지금 폴더를 보고, 모르면 건너뛴다.
- 작업 폴더 없이 남은 로컬 가지: 기본 가지·현재 HEAD·작업 폴더에 붙은 가지·설정 `gc.keep_branches`(빈칸으로 나눈 glob 무늬, 기록용 가지)는 빼고, 같은 판정(병합 커밋이 끼면 안 들어감)에 마지막 커밋과 가지 reflog가 `--min-age`보다 오래됐으면 `branch -D`하고 `지움 가지 <가지> <sha>`를 찍는다.
  안 들어간 가지는 지우지 않고 `남김 가지 <가지> 안 들어감 <n>개 · 마지막 <날짜>`.
- `--remote-branches`(기본 꺼짐): 원격 `refs/heads/*` 가운데 기본 가지·`gc.keep_branches`를 빼고 같은 판정이면 ls-remote 때 값 그대로일 때만 지운다.
  나이는 커밋 시각뿐이라 옛 main 커밋에 방금 만든 원격 가지도 지우고, 로컬 가지의 원격 짝(upstream·PR)도 빼지 않는다.
  hc-fill의 정리 바퀴는 이것을 켜지 않는다.
- 「들어감」은 커밋마다 공백까지 같은 패치(`git patch-id --verbatim`)가 `origin/<기본>`에 있을 때다.
  공백만 다른 변경은 안 들어감.
- `--integ`(기본 접두 `refs/integ/`): 원격 참조마다 커밋이 `origin/<기본>`에 다 들어갔고 커밋 시각이 `--min-age`보다 오래됐을 때만, ls-remote 때 값 그대로일 때만 지우고 `지움 <참조> <sha>`를 찍는다.
  메인 폴더·기본 가지·현재 가지·`refs/tags`·`refs/claims`는 건드리지 않는다(원격 `refs/heads`는 `--remote-branches`일 때만).
- 지운 참조 되돌리기: `git push origin <sha>:<참조>`(찍힌 sha 그대로).
  지운 가지는 `git branch <가지> <sha>`.
- 마지막 줄 `지움 n · 남김 m`. hc ls·fetch 실패는 아무것도 지우지 않고 종료 1. hc-fill이 설정 `gc` 분마다(기본 60) 부른다.
