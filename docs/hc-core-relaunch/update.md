# hc-core-relaunch: 코어 판 맞추기 (--update)

2026-11-24 core-update-cmd. 기계마다 hc 코어 판을 맞추는 손 절차(업데이트 → 맥 계열은 코어가 SSH 문맥으로 떠 키체인이 막히니 다시 띄우기 → 코어 문맥·키체인 확인)를 한 명령으로 했다.
왜: 예전 `hc-core-relaunch`는 ssh 종료 코드만 보고 점검 줄은 찍기만 했다 — SSH 문맥으로 뜬 코어를 「성공」으로 넘기면 레인이 키체인에서 오래 멈춘다(52분 멈춘 일이 있었다).

## 쓰는 법

- `hc-core-relaunch --update [--dry-run] [--busy skip|wait|go] [--timeout <초>] <기계>…` — 그 기계들만.
- `hc-core-relaunch --all [그 옵션들]` — `hc machine ls`의 모든 기계(`--all`은 `--update`를 뜻한다).
- 기준 판은 이 기계의 hc(`hc -V`)다. 판이 같은 기계는 아무것도 하지 않는다(「같음」).
- 예전 꼴 `hc-core-relaunch [--timeout <초>] <기계>…`(판과 상관없이 다시 띄우기)도 그대로다. 다만 이제 아래 점검 판정과 전체 상한을 함께 받는다.

## 차례 (기계 하나)

1. 하기 전에 `-- 상태` 표: 기계마다 판·연결·도는 터미널(레인)·병합기 터미널(`merger-*`)·병합기 검증 터미널(라벨 `hc-merger-spec=1`, 「검증 중」). 판단은 부르는 쪽(지휘)이 이 표를 보고 한다.
2. 판을 모르면 실패: 목록에 없음·연결 안 됨·OS를 모름(`hc exec --on <기계> -- uname -s`가 Darwin·Linux가 아님).
3. 검증 중인 기계는 손잡이 `--busy`: `skip`(기본 — 손대지 않고 「건너뜀」), `wait`(검증 터미널이 없어질 때까지 다시 봄, 간격 `HC_CORE_RELAUNCH_POLL`초·기본 15, 전체 상한 안에서), `go`(그대로 한다). 늘 떠 있는 병합기 터미널 자신은 「검증 중」으로 세지 않는다(코어를 다시 띄워도 도는 프로그램은 살아 있다).
4. 그 기계의 살아 있는 터미널 목록을 적어 두고 `hc machine update <기계>`.
5. macOS면 다시 띄우기(예전 꼴과 같은 `remote.sh` — gui 도메인 launchd 작업으로 `herdr-core server restart --fresh`). 리눅스는 업데이트만.
6. 뒤 확인: 먼저 그 기계가 다시 `connected`가 될 때까지 본다(간격 `HC_CORE_RELAUNCH_POLL`, 전체 상한 안 — 끝내 안 붙으면 「다시 연결되지 않음」 실패. 붙기 전 목록은 그 기계 터미널이 비어 모두 사라진 것처럼 보인다).
   그다음 끝난 것까지(`hc ls --all`) 받아, 전에 살아 있던 터미널이 없어졌거나 `live`가 아니면(`finished` 등 — hc는 끝난 터미널을 목록에 남긴다) 실패다. 스스로 끝났는지 재시작에 죽었는지 가릴 수 없으니 실패로 알리고 판단은 부르는 쪽이 한다. `hc machine ls`의 판이 기준과 다르면 실패.
7. macOS면 `worker-mac-check <기계>`의 「코어 문맥(Aqua)」·「키체인(hc 문맥)」 줄이 둘 다 「통과」여야 성공이다 — 실패·모름·줄 없음은 실패. 「brew PATH(hc 문맥)」 줄은 찍기만 한다. 키체인은 열리는지만 본다(암호·항목을 다루지 않는다).

## 결과와 종료 코드

- 끝에 `-- 결과` 표: `<기계>\t<같음|성공|할 일|건너뜀|실패>\t<까닭>`.
- 종료 0 모두 같음·성공(dry-run은 할 일) · 1 실패가 하나라도 · 3 실패는 없고 건너뛴 기계가 있음 · 64 사용법.
- `--dry-run`: 상태 표와 할 일만 — 업데이트·다시 띄우기·점검을 하지 않는다(읽기: `hc -V`·`hc machine ls`·`hc ls`·`uname -s`).
- `--timeout <초>`(기본 1800): 전체 상한. 넘기면 하던 단계는 무리째 거두고 그 기계는 실패, 남은 기계는 「손대지 않음」으로 실패 — 성공으로 치지 않는다.

## 실패 때 볼 것

- 「점검 키체인(hc 문맥) 실패」·「코어 문맥 실패」: 코어가 여전히 SSH 문맥이다 — `hc-core-relaunch <기계>`로 다시 띄우고 `worker-mac-check <기계>` 전체를 본다(GUI 로그인 세션이 없으면 그 맥에 로그인부터).
- 「사라지거나 끝난 터미널」: 그 기계에서 `hc ls --all`로 그 주소를 찾는다 — `finished`면 그 프로그램이 스스로 끝났는지(레인 완료 등) 재시작에 죽었는지 본다. 코어 재시작 뒤 주소가 바뀐 경우도 「없어짐」으로 걸린다(안전 쪽 — 손으로 확인).
- 「다시 연결되지 않음」: 그 기계 코어가 뜨지 않았을 수 있다 — `hc machine ls`, 그 맥 화면·ssh로 `herdr-core` 확인.
- 「업데이트 뒤에도 판 …」: `hc machine update <기계>` 출력(결과 위 줄)을 본다.
- 「연결 안 됨」: `hc machine login <기계>` 또는 Tailscale·ssh부터.
- 「건너뜀 병합기 검증 중」: 검증이 끝난 뒤 다시 부르거나 `--busy wait`·`--busy go`.
