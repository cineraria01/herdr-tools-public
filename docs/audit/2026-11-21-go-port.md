# Go 전환 전체 감사와 고침 (2026-11-21~22)

herdr-tools를 Go로 옮긴 뒤(사용자 「모두 고로 옮기고 싶어」) 한 첫 전체 감사와, 그 지적을 고친 레인 여섯의 기록이다. 재감사(go-reaudit)가 아래 「재감사 결과」 칸을 채운다.

## 첫 감사

| 항목 | 값 |
|---|---|
| 기준 커밋 | `07b04ea` |
| 영역 | lane · merger · fill · hooks · ops · base |
| 감사 1 | 아스트라 6.2 max — 높음 52 · 중간 61 |
| 감사 2 | Fable 5.2 xhigh — 높음 3 · 중간 29 |

두 감사의 지적은 겹친다(같은 결함을 둘 다 적은 것은 고침 레인 표에서 `A-F01 + Fb-F2`처럼 한 줄). 고침 레인은 지적마다 「모델 안」(Go 판이 새로 만든 결함)·「기존」(셸 판부터 있던 결함)을 나눠 셌고, 감사가 본 「모름을 없음·성공으로 읽기」의 같은 뿌리를 따라가 감사 밖의 같은 꼴도 함께 고쳤다. 그래서 아래 고친 수의 합이 첫 감사 지적 수보다 크다.

## 고침 레인

숫자는 각 레인이 마지막으로 낸 집계다(커밋 메시지의 처리 표와 레인 완료 보고). 「재현 안 됨」은 지금 main에서 다른 레인의 고침이 이미 막고 있어 회귀 시험만 더한 것, 「넘김」은 다른 영역·다른 레인 몫으로 넘긴 것이다.

| 레인 | 맡은 곳 | 고침 높음 | 고침 중간 | 재현 안 됨 | 넘김 | 재감사 결과 |
|---|---|---:|---:|---:|---:|---|
| gofix-core | merger · base 공통(`internal/proc`·`atomic`·`events`·`pyjson`·`toolcfg`·`clitest`, `lib/go-run.sh`, launchd 지킴이) | 20 | 26 | 0 | 9 | |
| gofix-ops | ops(`herdr-sync`·`herdr-settings-merge`·`herdr-tools-publish`·`herdr-tools-config`) | 27 | 16 | 0 | 2 | |
| gofix-fill | fill(`hc-fill`) | 10 | 10 | 2 | 3 | |
| gofix-util | base 작은 도구(`hc-sweep`·`herdr-balance`·`ovis-split`·`worker-mac-*`, 검증) | 19 | 13 | 4 | 1 | |
| gofix-lane | lane(`hc-lane`) | 11 | 17 | 2 | 1 | |
| gofix-hooks | hooks(`claude/hooks`, `cmd/herdr-hooks`) | 11 | 16 | 0 | 2 | |
| **합계** | | **98** | **98** | **8** | **18** | |

- gofix-core: 높음 20은 모델 안 15·기존 5, 중간 26은 모델 안 20·기존 6.
- gofix-ops 넘김: `internal/toolcfg` ERE 공개, `internal/proc` 바깥 무리 등록.
- gofix-fill 재현 안 됨: A-F04(고아 기록·거둠)·A-F08(umask) — gofix-core가 막음.
- gofix-util 재현 안 됨: B13·O01(`internal/pyjson`)·B20(`internal/workermac`)·B24(이미 Windows 빌드 됨). 넘김: B32(`internal/argp`의 `--` 단독).
- gofix-lane 재현 안 됨: L06·L19(gofix-core가 막음). 넘김: L15(go-run·herdr-sync 릴리스 세대).
- gofix-hooks: 커밋 메시지 표는 넘김 1(Fable L1 `lib/go-run.sh`의 `<도구>_BIN`)이고, 다시 제출 때 `internal/proc` `-race` 부하 실패 한 번(단독 세 번·재실행 통과)을 넘김에 더해 2.
- 지적별 처리 표: 각 레인 커밋 메시지(gofix-hooks는 「gofix-hooks 보고」 커밋, gofix-util은 마지막 커밋).

## 착지

gofix-core·ops·fill·util이 먼저 착지했고, gofix-lane·gofix-hooks는 그 사이 바뀐 공통 파일(README 등) 때문에 rebase 충돌로 한 번 반송된 뒤 양쪽을 살려 다시 제출해 착지했다(main `b3da41e`). gofix-integrate는 그 main에서 `go vet ./...`와 저장소 검증 `.claude/herdr-verify.sh` 전체(개인 값 검사·`tests/*.test.sh` 13개)를 다시 돌려 합침이 깨뜨린 것이 없음을 확인하고(모두 통과, 고칠 것 없음) 이 문서를 더했다.

그 뒤 main에 함께 들어온 것:

- go-linux-dist(`5221ec0`): herdr-sync 릴리스에 linux/amd64 — 리눅스 기계도 해시 확인 뒤 받아 쓴다.
- verify-go-timeout(`e0173a5`): 저장소 검증의 느린 `go test` 꾸러미를 따로 1200초로, cotenant calm 예산을 두 판 공통·기한 절반으로.
- proc-race-flaky(`c92dfac`): `internal/proc` 시험의 시간 기댐을 이벤트·넉넉한 기한으로 — 앞 판 gofix-integrate를 반송한 `-race` 부하 흔들림을 고쳤다. `go test` 실패 때 시험 이름·출력을 남긴다.
