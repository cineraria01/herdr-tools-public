# herdr-sync: 배포 기록·상태·되돌리기·착지 뒤 배포

2026-11-24 deploy-log-rollback — 사용자 「자동 배포를 위해 배포 기록, 되돌리기도 만들자」, 「배포나 설계를 지휘에서 자동 조정 바로바로 … 에이전트 스타일로」.
도구는 재는 것(`--status`·`--log`)·손잡이(`--auto`)·알림(착지 뒤 사건)을 주고, 배포할지·되돌릴지는 지휘가 정한다.

```sh
herdr-sync --status [<기계>…]        # 기계마다 깔린 판·origin/main과의 차이·병합 줄·도는 배포 (고치지 않음)
herdr-sync --log [<n>]               # 배포 기록 마지막 n줄 (기본 20)
herdr-sync --at <커밋> [--check]     # 올려 둔 그 커밋의 릴리스 바이너리만 깐다 (되돌리기)
herdr-sync --auto [on|off]           # 착지 뒤 스스로 배포 손잡이 (기본 끔)
herdr-sync --auto-publish [on|off]   # 스스로 배포가 공개 단계까지 하나 (기본 끔)
herdr-sync --landed                  # 착지 뒤 명령 — hc-fill land-every가 부른다
```

## 배포 기록

- 배포(`--check` 아님 — `--take`·`--pull`·`--at` 포함)마다 끝날 때 `~/.local/state/herdr-sync/deploy.tsv`에 한 줄을 붙인다: 시각 · 종류(배포|되돌림) · 종료 코드 · 범용 커밋 12자 · 소스 판 · 개인 커밋 12자 · 부른 곳 · 기계별 결과.
- 기계별 결과는 `같음`(쓴 것 없음) · `씀`(무엇이든 쓰거나 받거나 지음) · `충돌` · `실패`(다름·연결·바이너리 못 깖) · `건너뜀`(sh 없음·다른 OS)이다.
- 실패·부분 실패·도중 멈춤(`die`)·신호로 멈춘 배포도 적고, 닿기 전에 멈춘 기계는 칸이 없다.
- 기계 맞추기(되돌리기는 깔기)에 들어서기 전에 아무것도 쓰지 않고 멈춘 거절(더러운 저장소·옛 묶음 이름·저장소 충돌·개인 값·없는 판 등)은 적지 않는다(「아무 데도 안 씀」 계약).
- 부른 곳은 `HERDR_SYNC_BY`(스스로 배포는 `스스로`), 없으면 hc 터미널 ID(`HC_TERMINAL_ID`), 없으면 `-`.
- 도는 동안 `~/.local/state/herdr-sync/deploying`(pid·시작 초·종류)이 있다 — `--status`의 「지금 도는 배포」.
- 소스 판 칸은 기계의 `bin.tsv` 셋째 칸과 같은 값이라 `--status`가 기계의 판을 커밋으로 풀어 읽는 짝이다(`bin.tsv` 꼴은 그대로).
- 이 기록이 생기기 전에 깐 판은 `모름 (배포 기록 전 판)`이다 — 한 번 배포하면 풀린다.
- 같은 배포는 [운영 일지](../ops/journal.md)에도 한 줄(누가·왜·되돌리는 `--at` 명령·이 기록의 요약)이고, `--why <까닭>`이 그 왜 칸이다(권함).

## 상태 (`--status`)

- 범용 저장소 `origin/main`을 fetch한 뒤(실패하면 있는 참조로 판정하고 그렇다고 적는다) 한 화면에 보인다: `origin/main <커밋> · 지금 도는 배포 …`, `배포할 것 <k>커밋: <제목 머리들> · 병합 줄 <n>건 남음 (맥 기준)`, 기계마다 `<기계>: <커밋> · 뒤 <k>커밋`, 마지막 배포, 스스로 배포 켬·끔.
- 기계의 판은 그 기계 `bin.tsv`(도구·sha·소스 판)에서 읽는다 — 도구마다 판이 갈리면 `섞임 (…)`, 본체 sha가 기록과 다르면 `따로 바뀜 <도구>(따로바뀜|없음)`.
- 닿지 못하거나 출력이 끝까지 오지 않으면 `모름 (닿지 않음·읽지 못함)`이다(같음·최신으로 읽지 않는다).
- 병합 줄은 origin의 `refs/merge-queue/*` 수이고, 읽지 못하면 `모름`.
- 맥보다 옛 판인 워커가 있으면(반쪽 배포) 기계 줄 다음에 `맥만 새 판 <커밋> — 워커 <n>대 옛 판 (<기계>…) · herdr-sync로 맞춘다`가 붙는다 — 배포 끝 요약에도 같은 줄이 맥은 새 판을 깔고 바이너리를 못 깐 워커가 있을 때 붙는다.
- 스스로 배포가 공개 단계까지 켜져 있으면 끝에 `스스로 배포가 공개 단계까지 한다 (…)` 한 줄.
- 이 기계에 옛 판·판 모름으로 도는 상주가 있으면(hc-sweep 상주 판 점검 결과 한 장) 기계 줄 다음에 `맥 옛 판으로 도는 상주: … — 다시 띄우기: <명령>` 줄이 있을 때만 붙는다 — 배포가 그 프로세스에 닿지 않았다는 뜻이다([상주 판 점검](../hc-sweep/resident.md)).
- 잠금을 쥐지 않고(도는 배포를 막지 않는다) 기록·기계 파일을 쓰지 않는다 — 쓰는 것은 범용 저장소의 `origin/main` 참조뿐이다.

## 되돌리기 (`--at <커밋>`)

- 이미 올린 릴리스 `bin-<커밋 12자>`의 바이너리를 맥과 기계마다 깐다(표는 맥 줄 먼저).
- 범위는 **도구 바이너리만**이다 — 파일·나무·설정·지움은 건드리지 않고 저장소도 당기지 않는다.
- 개인 저장소 쪽 지침·설정은 git으로 되돌린 뒤 보통 배포로 맞춘다.
- 올려 둔 판만 깐다 — 받지 못하면 그 자리에서 옛 소스를 짓지 않고 `<도구> 바이너리를 깔지 못했다: … · 되돌리기는 올린 판만 깐다(짓지 않음)`.
- 그 판 릴리스에 없는 도구(뒤에 더한 도구)와 herdr-sync 자신은 `건너뜀`이다(되돌린 옛 herdr-sync가 다음 배포를 맡지 않게).
- 깐 본체의 sha와 소스 판 `at:<커밋>`을 그 기계 `bin.tsv`에 적는다 — 다음 보통 배포는 그 본체를 「마지막으로 깔아 준 판」으로 알아봐 `따로 바뀜` 충돌 없이 새 판으로 바꾼다.
- 손으로 되돌린 본체(기록과 다른 sha)는 지금처럼 충돌이고 `--take`로 덮는다.
- 없는 판이면 `그 판의 릴리스가 없다 (bin-<커밋>) — 올린 판만 깐다. 올린 판: …`(gh release list), 모르는 커밋이면 `커밋을 모른다`, 둘 다 종료 1.
- 범용 저장소에 없는 커밋도 12자 이상 16진이면 릴리스로 찾는다.
- `--check`와 함께면 `<기계> 다름:바이너리 <도구> (…)`로 무엇이 바뀔지만 보인다 — `--take`는 받고 `--pull`은 거절한다.
- 받는 것은 `gh release view`·`download`(SHA256SUMS)·`list`뿐이다 — 공개 저장소에 아무것도 올리지 않는다.

## 착지 뒤 알림과 스스로 배포

- 개인 설정 `hc-fill.tsv`에 `on-land deploy <범용 저장소 프로젝트> herdr-sync --landed`와 `land-every deploy`를 두면(꼴 `config.example/hc-fill.tsv`) 범용 저장소의 착지마다 hc-fill이 `herdr-sync --landed`를 돌리고 그 끝 줄을 사건으로 지휘에 보낸다([착지 뒤 명령](../hc-fill/on-land.md)).
- 잇단 착지는 한 번으로 합쳐진다.
- `--landed`는 맥에 깔린 판(맥 `bin.tsv`)과 `origin/main`을 견줘 `배포할 것 <k>커밋: <제목 머리들> · 병합 줄 <n>건 남음`(없으면 `배포할 것 없음 …`)을 찍는다.
- 스스로 배포가 꺼져 있으면(기본) 거기서 끝(종료 0)이고, 지휘가 보고 `herdr-sync`로 배포한다.
- **스위치** `herdr-sync --auto on|off`는 표식 파일 `~/.local/state/herdr-sync/auto-deploy` 하나다(있으면 켬, 내용은 켠 시각·부른 곳).
- 다음 `--landed`부터 바로 먹고 설정 파일을 고치지 않으며, 범위는 이 herdr-sync가 맡는 범용 저장소(`HERDR_TOOLS_REPO`) 하나다.
- 뒤 레인(ops-knobs·knobs-migrate)이 이 표식을 공통 손잡이 저장으로 옮긴다.
- 켜져 있으면 병합 줄이 빌 때까지 미룬다 — 상한 `HERDR_SYNC_AUTO_WAIT`(초, 기본 1800), 틈 `HERDR_SYNC_AUTO_POLL`(초, 기본 30), 상한이 지나면 `기다림 상한 — 지금 배포한다`.
- 그다음 **깔 수 있는지 본다**(sync-auto-fix, 2026-11-24 — 첫 실행이 맥만 깔고 워커 여덟 대가 옛 판에 남았다): 워커는 바이너리를 그 커밋의 릴리스로 받는데, 릴리스는 공개 단계(검사한 커밋으로 지어 공개 저장소에 올림)와 한 덩이다.
  공개 단계가 꺼져 있으면(기본) `origin/main` 커밋의 릴리스 `bin-<커밋>`이 올라 있을 때만 배포한다.
  없거나 있는지 모르면 맥에도 아무것도 깔지 않고 끝 줄 `스스로 배포 못 함: 이 커밋의 릴리스가 없다 (bin-<커밋>) — herdr-sync로 배포하거나 herdr-sync --auto-publish on · 배포할 것 …`, 종료 1(hc-fill 막힘 사건 한 번).
  이 확인과 배포 사이에 릴리스 없는 착지가 끼어도 배포 쪽이 바이너리를 깔기 전에 같은 까닭으로 멈춘다(종료 1).
  `publish.repo`가 GitHub 저장소가 아니면(릴리스 길이 없음) 기계가 각자 짓는 보통 배포와 같다.
- **손잡이** `herdr-sync --auto-publish on|off`(표식 `~/.local/state/herdr-sync/auto-publish`, 기본 끔): 켜면 스스로 배포가 보통 `herdr-sync`처럼 공개 내보내기·릴리스 올림까지 하고 모든 기계가 그 릴리스를 받는다.
  켜고 끄는 것은 운영 일지에 남는다(`--why`).
  `--auto`가 꺼져 있으면 아무 일도 하지 않는다.
- 그다음 보통 배포를 한 번 돌리고(다른 herdr-sync가 돌면 상한까지 다시) 그 종료 코드로 끝난다.
- 0이면 끝 줄 `스스로 배포 끝 — …`, 아니면 `스스로 배포 실패 (종료 n) — …`이고 hc-fill이 막힘 사건으로 보낸다.
- 결과는 배포 기록에 부른 곳 `스스로`로 남는다.
- 기본값은 안전 하한만이다: 알림은 놓치지 않고(착지마다, 합쳐서), 스스로 배포는 끔.

## 바깥으로 내보내는 것 (공개)

| 단계 | 무엇이 어디로 | 보통 배포(사람·지휘가 부름) | 스스로 배포(`--landed` + `--auto on`, 기본) | 스스로 배포 + `--auto-publish on` | `--at` · `--status` · `--log` · `--check` |
|---|---|---|---|---|---|
| 공개 내보내기 | `herdr-tools-publish`가 범용 저장소를 기록 없이 공개 저장소(`publish.repo`)로 push | 함(설정 `publish.repo`가 있을 때) | **안 함** | 함 | 안 함 |
| 릴리스 올림 | 맥에서 지은 바이너리·SHA256SUMS를 공개 저장소 릴리스 `bin-<커밋>`에(`gh release create·upload`) | 함(내보내기가 검사한 커밋으로) | **안 함** — 그 커밋 릴리스가 이미 있으면 받기만, 없으면 배포하지 않는다 | 함 | 안 함 |
| 릴리스 받기 | 공개 저장소 릴리스를 읽음(`gh release view·download·list`, 기계의 `curl`) | 함 | 함(없으면 배포하지 않음) | 함 | `--at`만 |

- 릴리스 올림만 따로 할 수는 없다: 릴리스는 공개 내보내기가 개인 값·비밀 꼴을 검사하고 내보낸 바로 그 커밋으로 짓고 같은 공개 저장소에 올린다(검사하지 않은 판의 바이너리를 공개하지 않게).
- 스스로 배포(기본)는 `HERDR_SYNC_NO_PUBLISH=1`로 보통 배포를 부르고, 그때 herdr-sync는 `공개 건너뜀 — …` 한 줄을 찍고 위 두 올리는 단계를 부르지 않는다(승인 밖 공개를 도구가 스스로 하지 않게).
- 공개가 필요하면 사람·지휘가 `herdr-sync`를 부르거나, 지휘가 `--auto-publish on`으로 스스로 배포에 맡긴다.
