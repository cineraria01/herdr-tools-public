# 지금 손댈 것 (hc-fill advise)

- 놀고 있는 자리·풀 수 있는 대기·한 줄 사슬·멈춘 레인·굶는 감사·병합기·밀린 배포·옛 판 상주를 **사람이 묻기 전에** 한 목록으로 낸다(2026-11-24 ops-advise).
- 왜: 사용자 「워커들 놀지 말고 다 쉬는것 없이 다 돌려서 그 시간이야 ?」 — 워커 여섯 대 가운데 넷이 노는데 남은 레인이 한 줄 사슬이었고, 지휘는 사람이 물은 뒤에야 사슬을 풀었다.
  이 판단들은 도구가 이미 아는 사실(자리 수·부하·대기 줄의 까닭·터미널 상태·깔린 판·병합 줄)의 조합인데, 묶어 내는 곳이 없었다.
- 항목마다 **무엇 · 근거(잰 값) · 놓치면 드는 것 · 다음 명령(그대로 칠 수 있는 줄, 여럿이면 차례로) · 확신**.
- 읽기만 한다. 조치는 사람이나 지휘 에이전트가 「다음 명령」을 쳐서 한다(사람과 에이전트가 같은 명령).
- 재료는 [상태 한 장](state.md)과 같다(바퀴 기록 재사용, 원격 호출을 늘리지 않는다). 상태 한 장의 「눈에 띄는 것」은 이 목록의 요약 한 줄씩이다 — 같은 판정을 두 군데 두지 않는다.

## 쓰는 법

- `hc-fill advise` 사람용, `hc-fill advise --json` 압축 json 한 줄. 항목이 없으면 「손댈 것 없음」 한 줄(json `items: []`).
- 확신 `확실`은 그대로 쳐도 된다는 뜻이고, `판단 필요`는 근거·놓치면을 읽고 정한다. `사람이 정한다`는 다음 명령을 내지 않는다
  (그대로 칠 줄을 모르거나, 되돌릴 수 없는 명령·남의 프로세스를 끄는 명령이라서).
- 모름은 모름이다 — 재료를 못 읽으면 「판정 못 함: <무엇>」 항목이 나온다(손댈 것 없음으로 읽지 않는다).

## 항목

| 종류(`kind`) | 상황 | 판정 | 다음 명령 | 확신 |
|---|---|---|---|---|
| `free-wait` | 풀 수 있는 대기(겹침) | 빈 자리가 있는 기계(저장소 있음·`--only` 안·멈춤 아님)에서 대기 줄이 겹침만으로 `idle`분 넘게 기다림 | `hc-fill edit <레인> --overlap-ok --why …`(줄 ID·주차 표식·다른 칸 그대로 — `rm` 뒤 `add`는 add가 실패하면 줄이 사라지고 `--solo` 등 옵션이 안 돌아왔다) | 문서·시험 한 파일이면 확실, 꾸러미(폴더)·코드 파일이면 판단 필요, 단독이면 사람이 정한다(명령 없음 — 겹침을 꺼도 안 풀린다) |
| `free-wait` | 풀 수 있는 대기(선행) | 빈 자리가 있는데 대기 줄이 떠 있는 레인(선행)을 `idle`분 넘게 기다림 | `hc-fill edit <레인> --after - --why …` | 판단 필요(선행의 산출물이 필요한 레인이면 못 푼다) |
| `chain` | 한 줄 사슬 | 대기 줄이 대기 줄을 기다려 하나씩만 돌 수 있고 빈 자리가 있다(사슬 2줄부터) | 머리 다음 줄마다 `hc-fill edit <레인> --after - --why …` | 판단 필요 |
| `rejected` | 띄우기 거절로 멈춘 줄 | 대기 줄에 띄우기 거절 기록 | `hc-fill retry <레인> --why …`(까닭을 고친 뒤) | 판단 필요 |
| `lane-error` | 멈춘 레인 | 터미널 상태 error | `hc read <주소>` · `hc-fill nudge <레인> --why …`(맨 `hc send`가 아니라 — 주소의 터미널 이름 대조·이미 보고한 실행 거절·`nudge_every` 되풀이 막기를 거친다) | 판단 필요 |
| `lane-blocked` | 답을 기다리는 레인 | 터미널 상태 blocked(물음·권한 창) | `hc read <주소>` | 판단 필요 |
| `lane-done` | 끝났는데 보고 없음 | 터미널 상태 done인데 마지막 사건이 완료·착지가 아님 | `hc read <주소>` | 판단 필요 |
| `lane-escalated` | 막힌 레인 | 단계가 막힘(감사·도구가 지휘로 넘긴 것) | `hc read <주소>` | 판단 필요 |
| `audit-starve` | 굶는 감사 | 단계 「감사 대기(자리 없음 N분)」에서 N이 `advise_wait` 이상 | `hc-fill machine <기계> --seats <지금+1> --for 60 --why …` | 판단 필요 |
| `lane-long` | 같은 단계에 오래 | 터미널이 살아 있는(또는 모르는) 레인이 같은 단계에 `state_stage`분 — 터미널이 끝난 줄(완료로 보고하고 스스로 착지·정리한 레인, 착지 없는 검토 레인)은 자리를 안 잡아 빼고, 완료 뒤 멈춤은 `done_stall` 사건이 본다 | `hc read <주소>` | 판단 필요 |
| `merger` | 병합기 없음 | 병합기 살아 있음이 alive가 아님(gone) | `hc-fill merger restart <프로젝트> --why …` | 줄이 차 있으면 확실, 비었으면 판단 필요 |
| `merge-stall` | 병합 줄이 안 움직임(맡긴 검증 대기 등) | 줄에 선 가장 오래된 제출이 `advise_wait`분 넘게 서 있고, 그 제출이 들어온 뒤 병합기 일지에 그 프로젝트 줄이 `advise_wait`분 동안 없음(조용한 시간 = 가장 오래 나이와 일지 마지막 줄 나이 가운데 짧은 것 — 일지는 일이 있을 때만 줄이 생겨, 비었다가 방금 찬 줄을 「마지막 바퀴 40분 전」으로 울렸다). 일지를 못 읽는 다른 기계 병합기는 정하지 않는다 | `hc-lane logs` · `hc-fill status` | 판단 필요 |
| `merge-slow` | 병합 줄이 느림 | 이 기계 병합기가 지금 착지 중(병합기 클론의 착지 자식 기록 `<git-path hc-merger>/child`의 pid가 그 시작 시각으로 살아 있음)이고 그 착지가 `advise_merge_slow`분 넘음 — 착지 중이면 `merge-stall`은 내지 않는다. 레인·시각은 그 병합기 pid로 끝나는 착지 로그 가운데 가장 늦은 것의 이름(바퀴 시작이라 후보 만들기 몇 초가 들어가 「n분째」가 조금 길다), 없으면 레인 「모름」·자식 기록 시각 | `hc-lane logs` · `hc-fill status` | 판단 필요 |
| `deploy` | 밀린 배포 | 배포 기록상 판이 origin/main에서 1커밋 이상 뒤 — 단 배포가 지금 돌거나(herdr-sync `deploying` 표식의 pid가 살아 있음), 착지 뒤 배포 차례(herdr-sync를 부르는 on-land 이름의 pending·running)가 남았거나, 마지막 착지(그 이름의 착지마다 기준 `onland/<이름>.head`가 바뀐 때·범용 저장소 클론이 origin/main의 지금 끝을 처음 본 때(reflog 맨 위 줄, 없으면 참조 파일 고친 때) 가운데 늦은 것 — 커밋 시각은 착지 시각이 아니라 보지 않는다: 감사를 거친 커밋은 착지 때 이미 오래돼 착지 몇 초 뒤 거짓 사건이 났다, 보류 글에 쓴 값의 출처를 적는다) 뒤 `deploy_grace`분 안이면 **새** 밀림은 아직 치지 않는다(착지 뒤 배포가 도는 1~2분에 거짓 사건이 났다). 보류는 기계 구분 없이 첫 알림만 미룬다 — 이미 사건으로 알린 밀림(같은 열쇠)은 보류 동안에도 남아, 보류가 풀릴 때 같은 사건이 되풀이되지 않는다 | `herdr-sync --status <기계>` · `herdr-sync <기계>` | 병합 줄이 모두 비었으면 확실, 아니면 판단 필요 |
| `watch` | 감시 안 돎 | 지휘 터미널이 `hc ls`에 있고 착지·판정 전 열린 줄(떠 있음·주차)이 있는데 그 지휘의 감시 터미널이 없다. 상태 한 장 기본 출력이 숨긴 「안 도는 지휘 흔적」도 본다(숨긴 뒤 상태로 판정해 이 항목이 나오지 않았다). 지휘가 사라진 흔적·착지한 줄뿐인 지휘는 내지 않는다 — 사라진 지휘의 사건은 다른 살아 있는 지휘의 감시가 받고([watch](../hc-lane/watch.md)), 착지한 줄의 감시는 한가로 끝나는 것이 맞다 | `hc-lane coord --watch <지휘>` | 확실 |
| `resident` | 옛 판 상주 | hc-sweep 상주 판 점검 결과 줄 | 없음 — 다시 띄우는 명령(`kill`·`hc kill`·`launchctl kickstart -k`)은 프로세스를 끄고, 결과 줄의 pid는 확인한 때의 것이라 근거에만 남긴다 | 사람이 정한다 |
| `machine` | 기계 끊김 | 기계 연결 안 됨 | `hc machine ls` | 판단 필요 |
| `skew` | 부하 치우침 | 코어당 부하 `state_hot` 이상 기계와 `state_cool` 이하 기계가 함께이고, 자리 남는 후보가 모두 바쁜 기계인 띄울 차례 대기 줄이 있음(없으면 상태 한 장에만) | `hc-fill machine` | 판단 필요 |
| `unknown` | 판정 못 함 | 재료(바퀴 기록·hc·배포 기록)·병합기·기계 연결·감시를 못 읽음 | 없음 | 사람이 정한다 |

- `<주소>`·`<기계>` 같은 자리표시는 이 표에만 있다 — 출력에는 실제 레인·기계·주소가 들어간다. 터미널 주소를 모르면 명령을 내지 않고 사람이 정한다.
- 한 레인에는 항목 하나(위 표의 차례로 먼저 걸리는 것). 사슬 가운데 줄(대기 줄을 기다리는 줄)은 사슬 항목이 맡고 따로 내지 않는다.
- 남은 예상(선행·사슬이 끝나는 시각)은 잴 기록이 없어 「모름」이다.
- 아직 안 찾는 것: 반송됐는데 다시 내는 레인이 없음(병합기 반송 참조를 원격으로 읽어야 한다 — 찾게 되면 검증 실패 반송의 다음 명령은 `hc-fill requeue <레인> --why …`, [다시 넣기](../hc-fill/requeue.md)), 기계 건강(잠자기·키체인 — 상태 한 장의 `health`가 아직 비어 있다), 화면·턴이 N분째 그대로(화면을 읽는 원격 호출).

## 문턱(손잡이)

`hc-fill knob set <이름> <값> --why …`([손잡이](knobs.md)). 0이면 그 항목은 끈다.

| 손잡이 | 쓰는 곳 |
|---|---|
| `idle`(분, 기본 10) | 풀 수 있는 대기·사슬 — 대기 줄이 이만큼 넘게 기다렸을 때(놀고 있음 알림과 같은 손잡이). 0이면 두 항목을 내지 않는다(전에는 「문턱 0」이라 모든 대기 줄이 바로 항목이 됐다) |
| `advise_wait`(분, 기본 15) | 굶는 감사·병합 줄이 안 움직임 |
| `advise_merge_slow`(분, 기본 30) | 병합 줄이 느림 — 병합기의 지금 착지가 이만큼 넘으면 |
| `state_stage`(분, 기본 90) | 같은 단계에 오래 |
| `state_hot`·`state_cool`(%, 기본 200·50) | 부하 치우침 |
| `advise_every`(분, 기본 5) | 아래 사건 — 바퀴가 손댈 것을 다시 보는 간격(0이면 사건 끔) |
| `deploy_grace`(분, 기본 5) | 밀린 배포 — 마지막 착지 뒤 이만큼은 치지 않음(0이면 착지 시각은 안 보고, 도는 배포·착지 뒤 명령 차례만 본다) |

## 사건

- hc-fill `run` 바퀴가 `advise_every`분마다 목록을 다시 보고, 새 항목(열쇠 `key`가 지난번 목록에 없던 것)이 생기면 운영 사건 [hc-fill-advise](events.md) 한 번 — 「손댈 것: <요약 한 줄>(외 N)」.
- 같은 항목에는 되풀이하지 않는다(열쇠는 숫자 없는 꼴 — 기다린 분이 늘어도 같다). 사라졌다 다시 생기면 새 항목이다.
- 판정 못 함(`unknown`)은 사건으로 내지 않는다(재료를 한 번 못 읽을 때마다 오가면 사건이 시끄럽다) — 목록에는 나온다.
- 재료를 못 읽은 바퀴에는 그 재료로 찾는 지난 열쇠를 지우지 않고, 그 재료에 딸린 새 항목도 사건으로 보내지 않고 미룬다(다음에 읽힌 바퀴에도 있으면 그때 한 번).
  지우는 것은 읽었고 항목이 없을 때뿐이다 — 전에는 `hc ls` 한 번 못 읽은 바퀴에 열쇠가 지워져 회복한 바퀴에 같은 사건이 다시 나갔고, 단계 「모름」 레인이 `lane-long`으로 새로 나갔다.
  재료와 열쇠: 병합기 모름 → 그 프로젝트의 `merger`·`merge-stall`·`merge-slow`, 배포 모름 → 그 기계 `deploy`(재료 `deploy` 모름이면 모든 `deploy`), 감시 모름 → 그 지휘 `watch`, 상주 판 모름 → `resident`, `hc`·바퀴 기록·기계 연결 모름과 모르는 꼴 → 전부(자리·레인 판정이 모두 기댄다). 일지(`journal`)는 손댈 것의 재료가 아니다.
- 비용: 바퀴는 `advise_every`분마다 상태 한 장과 같은 재료를 새로 읽는다 — 이 기계 코어에 묻는 `hc ls --json`·`hc machine ls --json` 한 번씩과 배포 판마다 `git rev-list` 한 번(바퀴가 앞에서 읽은 터미널 목록을 넘겨 받지는 않는다). 줄이려면 `advise_every`를 늘린다.
- 지난 목록의 열쇠는 `<DATA>/advise.tsv`(첫 줄 마지막으로 본 초, 그다음 줄마다 열쇠). 보내기를 실패하면 그 열쇠를 적지 않아 다음에 다시 보낸다.

## json 칸

| 칸 | 뜻 |
|---|---|
| `schema` | 꼴 판(정수) |
| `at` | 만든 시각(RFC3339) |
| `fingerprint` | 상태 지문(상태 한 장과 같은 값) |
| `items` | 손댈 것(없으면 `[]`) |
| `items[].key` | 항목 열쇠(숫자 없는 꼴 — 사건 되풀이를 막는다) |
| `items[].kind` | 종류(위 「항목」 표) |
| `items[].what` | 무엇(상황 한 줄) |
| `items[].evidence` | 근거(잰 값) |
| `items[].cost` | 놓치면 드는 것(예상 기다림·풀 때의 비용) |
| `items[].next` | 다음 명령(그대로 칠 줄, 차례로). 없으면 `[]` |
| `items[].sure` | 확신 `확실` · `판단 필요` · `사람이 정한다` |
