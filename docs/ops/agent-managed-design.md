# herdr-tools를 「에이전트가 판단·관리하는 방식」으로 — 설계안

## 방향 (2026-11-24, 이 문서보다 앞선다)

- 사용자: 「전체 허더 툴을 가능하면 에이전트 식으로 에이전트가 관리하는 방향으로」, 「ai 로 자동 판단 관리 하는 에이전트 방식으로 하고 싶은거야」, 그리고 범위를 바로잡아 「수동으로 지시도 가능해야 하지만 허더 툴로, ai 에이전트가 사용하여 관리하고 도움이 될수 있는 툴로 진화를 원하는거야」.
- 즉 따로 떨어진 자동 관리자를 세우는 것이 아니라 **herdr-tools 자체가 AI 에이전트가 쓰기 좋은 관리 도구**가 된다. 사람이 손으로 지시하는 길은 그대로이고, 사람과 에이전트가 같은 명령을 쓴다.
- 도구는 **재는 것**(상태를 한 명령으로) · **손잡이**(실행 중에 바로 먹는 조정 — [손잡이](knobs.md)) · **알림**(판단이 필요한 때 지휘에게 사건 한 번)을 주고, 판단은 지휘 에이전트가 한다. 정책 값을 코드에 고정으로 박지 않는다. 기본값은 놓치지 않기·굶지 않기 같은 안전 하한만.
- 아래 「상주 관리 에이전트」를 다룬 장(2 관리 에이전트의 꼴 · 3 권한의 경계 · 5 단계, 그리고 6의 ops-manager-loop·selfcheck-as-sensor 줄)은 **보관 — 지금은 만들지 않는다.** 1장(고정으로 박힌 판단 조사)과 4장의 눈·손·알림 사양은 지휘 에이전트가 쓰는 도구로 그대로 쓴다.

---

- 대상: 범용 저장소 `origin/main` = `e57a22f`(fetch 없이 그대로 읽은 사본). 대기열(`hc-fill ls`)과 그때 대기 중이던 레인 지시문 14개를 읽었다.
- 표기: **[확인]** = 코드·문서·지침에서 직접 확인, **[추론]** = 설계 판단·추정.
- 기계 이름은 역할로 적는다: 지휘 기계(hc-fill·herdr-sync가 도는 맥), 루프 기계(문의·오류·자가 점검 루프), 워커 기계들, 병합기 기계.

## 0. 한 장 요약

1. **추천 꼴 = (다) 섞음**: 지휘 기계에 **상주 운영 관리자(ops-manager) 하나**를 hc-job-server로 띄워 「기계 전체·도구 전체」 판단(배분·배포 시점·되돌리기·병합기/감시 살리기·막힌 줄 풀기·흔들림 처리 요청)을 맡기고, 사람이 띄운 **지휘 세션은 자기 레인의 판단(지시문·감사 결과·착지 판단)**만 한다. 둘이 같은 손잡이를 다투지 않게 손잡이마다 「누가·언제까지」를 적고, **지휘가 고정(pin)한 값은 관리자가 뒤집지 않는다.**
2. 관리자가 지휘 기계에 있어야 하는 까닭 **[확인]**: 대기열 상태(`~/.local/share/hc-fill/`)·hc-fill·herdr-sync가 모두 지휘 기계에만 있고, 루프 기계의 hc는 지휘 기계를 모른다(운영 지침의 기계 표). 루프 기계에 두면 눈과 손이 닿지 않는다.
3. 도구에 박힌 정책 값은 **약 130개**(환경 변수 약 45 · 개인 설정 키 약 55 · 코드 상수 약 30, 기술적 시간 상한 약 60개는 따로). 이 가운데 **㉮ 안전 불변 약 25 · ㉯ 손잡이 약 75 · ㉰ 에이전트 판단 약 30**으로 본다(표 1).
4. 가장 큰 구조 문제 셋 **[확인]**:
   - **손잡이를 실행 중에 바꿀 곳이 없다.** hc-fill은 바퀴마다 `hc-fill.tsv`를 새로 읽어(`cmd/hc-fill/runcmd.go:68` 바퀴마다 `hc-fill run` 새 프로세스) 사실상 실행 중에 먹지만, 그 파일은 **개인 git 저장소 안**이라 고치는 순간 저장소가 더러워지고 herdr-sync가 멈춘다(`cmd/herdr-sync/repo.go:590` 「커밋하지 않은 변경이 있다」). 병합기 값은 프로세스 시작 때의 환경 변수라 다시 띄워야 바뀐다(`cmd/hc-merger/main.go:310` 등). 워커 기계에는 개인 설정이 없다(`docs/hc-lane/merger.md:24`).
   - **운영 사건이 레인 사건에 섞여 지휘 대화로 간다.** 병합기·hc-sweep·hc-fill은 가짜 레인 이름(`merger`·`hc-fill-idle`·`hc-disk-low`·`hc-tailscale`)으로 `hc-lane report`를 쓰고, 주인이 없으면 살아 있는 **모든 지휘**가 받는다(`docs/hc-lane/watch.md`). 관리자에게만 보낼 길이 없다.
   - **배포 = 공개.** herdr-sync는 바이너리를 공개 저장소 릴리스에 올리고(CONTRACT 「바이너리 줄」) 끝에 `herdr-tools-publish`를 부른다(`cmd/herdr-sync/machines.go:447`). 「스스로 배포」를 켜면 공개도 스스로 하게 되므로 사용자 규칙(승인 밖 공개는 묻는다)과 부딪힌다 — 떼어야 한다.
5. 자가 점검 루프는 **AI가 아니다 [확인]**: 루프 기계의 자가 점검 launchd 작업은 「셸만 — Claude 없음」으로 서명을 묶어 판정한다(개인 운영 문서). 관리자의 **센서**로 쓰고, 고칠지(요청 여부)는 관리자가 정하게 옮기는 것이 결에 맞다.
6. 대기 레인 14개가 눈·손·알림의 상당 부분을 만든다. **빠진 것은 「공통 바닥」 다섯**: 손잡이 저장(누가·왜·언제까지, 실행 중 적용, 원격 기계까지) · 상태 한 장 · 운영 사건 갈래 · 결정 일지 · 관리자 루프 자체. 대기 레인들이 손잡이를 **제각각 다른 자리에** 만들 위험이 있어(fill-load-steer는 「상태 폴더」, deploy-log-rollback은 「실행 중 명령」, merger-alive·fill-auto-submit은 「손잡이로 켜고 끄기」, flaky-retry는 환경 변수), 공통 손잡이 저장 레인을 그 앞에 두거나 지시문에 약속 한 줄을 덧붙이는 것이 첫 할 일이다.

## 1. 고정으로 박힌 판단 전수 조사

조사 방법 **[확인]**: `os.Getenv("HC_|HERDR_…")` 전수(시험 전용 빼고 약 45개), 개인 설정 키(`config.example/config` 약 30, `config.example/hc-fill.tsv` 약 30), `N*time.Second|Minute|Hour` 상수 90줄 가운데 정책 성격인 것, 문서의 「기본 N」 문장. 시험 전용(`HC_FILL_TEST_*`·`HERDR_HOOKS_TEST_*`·`HC_LANE_TC_*`)과 순수 기술 상한(git·hc·ps 한 번의 시간 상한, 신호 유예 등 약 60개)은 표에서 뺐다 — 이것들은 전부 ㉮(에이전트가 만질 값이 아님).

분류: **㉮ 안전 불변**(고정 — 까닭) · **㉯ 손잡이**(실행 중 조정 + 기본값은 안전 하한) · **㉰ 에이전트 판단**(상태·알림을 주고 맡김 — 기본 규칙은 판단이 없을 때의 대비로 남음).
「바꾸는 법」: 코드 / 설정(`hc-fill.tsv` — 개인 git 저장소) / 개인 설정(`config` — 개인 git 저장소) / 환경(프로세스 시작 때) / 원격 참조 / 명령.
「레인」: 이미 대기 중인 레인이 다루는가.

## 2. 관리 에이전트의 꼴 — 세 안 견주기

> **보관 — 지금은 만들지 않는다**(2026-11-24 방향: 따로 떨어진 관리자가 아니라 지휘 에이전트가 쓰는 도구로).

### (가) 지휘 세션이 관리자 (지금 구조의 연장)

- 판단: 전부 — 배포 시점·되돌리기, 기계 배분, 막힌 줄, 병합기·감시 살리기, 설정, 흔들림, 수정 레인.
- 깨어남: 지금처럼 `hc-lane watch`가 지휘 입력에 사건을 밀어 줌. 비용은 지휘 모델(Opus 5.5 xhigh) 턴 하나 — **지휘 턴 비용으로 운영 잡일을 처리**한다.
- 지휘들과의 관계: 지휘가 여럿(저장소마다)이면 주인 없는 운영 사건이 **모든 지휘에게** 가서 둘이 같은 일을 하거나 서로 뒤집는다 [확인: watch.md 「놓치는 것보다 겹치는 게 낫다」].
- 실패 꼴: 지휘 세션이 없으면(밤·사용자 부재) 아무도 판단하지 않음 — 지금 `hc-fill-idle`·병합기 멈춤이 몇 시간 방치된 원인. 지휘 대화가 운영 사건으로 차 주 작업 맥락이 밀림. 두 지휘가 같은 손잡이를 반대로 돌림.
- 장점: 새로 띄울 것 없음, 사용자 대화와 같은 자리.

### (나) 상주 관리 에이전트만 (자가 점검 루프의 확장)

- 판단: 전부, 지휘 세션은 레인 내용만.
- 깨어남: 사건(운영 사건만 받음) + 주기(30~60분 심장 박동). 셸 거름이 「상태가 바뀌었나」를 먼저 보고 바뀐 때만 모델을 부른다.
- 한 번 비용 [추론]: 상태 한 장(JSON 수 KB ~ 수십 KB) + 일지 꼬리 + 사건 몇 줄 ≈ 입력 2~4만 토큰, 출력 수천. Opus 5.5 high 기준 하루 48번 상한이면 지휘 세션 하나의 몇 시간 분량.
- 지휘들과의 관계: 관리자가 지휘가 정한 값(예: 지휘가 일부러 멈춘 기계)을 「치우침」으로 보고 되돌리는 일이 생김 — 고정(pin) 개념이 꼭 필요.
- 실패 꼴: 틀린 판단의 연쇄(배분을 계속 흔듦), 되풀이(같은 사건에 같은 처치), 비용 폭주(사건 폭풍마다 깨어남), 관리자 자체가 멈춤(누가 관리자를 보나 — hc-job-server가 본다).
- 자리: **루프 기계는 안 된다** — 루프 기계 hc는 지휘 기계를 몰라 대기열·herdr-sync에 닿지 못한다 [확인: 전역 지침]. 그래서 상주 관리자는 지휘 기계에 둔다.

### (다) 섞음 — **추천**

- **상주 운영 관리자 하나(지휘 기계)**: 「기계·도구 전체」 판단 — 기계 배분·자리 조정, 병합기·감시·루프 살리기, 막힌 대기 줄 풀기(거절 재시도·다른 기계로 보내기), 배포 시점·되돌리기(단계 3부터), 흔들리는 시험 격리 요청, 운영 수정 레인 요청(자가 점검 센서 받아서), 손잡이 값 조정.
- **지휘 세션들**: 자기 레인의 판단 — 지시문·감사 결과 판단·착지/반송·사용자 대화. 운영 사건은 받지 않는다(관리자가 살아 있을 때). 관리자가 없거나 판단을 넘기면 지금처럼 지휘가 받는다(대비 길).
- 깨어남: ① 운영 사건(관리자 주소로만 가는 갈래) ② 심장 박동 30분 — 앞에 **셸 거름**: 상태 한 장의 「요약 지문」(기계별 자리·대기 수·병합 줄 나이·밀린 배포 커밋 수·새 사건 수)이 지난 깨움과 같고 새 운영 사건이 없으면 모델을 부르지 않는다 ③ 일지의 「결과 확인 시각」이 된 결정.
- 관계 규칙(관리자가 둘이 되어 뒤집지 않게):
  1. 손잡이 값마다 `by`(관리자 / 지휘 주소 / 사람) · `why` · `until`을 적는다.
  2. **지휘·사람이 쓴 값은 고정(pin)** — 관리자는 바꾸지 않고 「풀어도 되나」 사건만 보낸다. 고정도 `until`이 있으면 그때 풀린다.
  3. 관리자는 하나 — 지휘 기계 잠금(`~/.local/state/herdr-ops/manager.lock`) + hc 이름 하나. 두 번째는 뜨지 않는다.
  4. 관리자가 한 일은 일지 + 그 레인·프로젝트 주인 지휘에 한 줄 알림(사건) — 지휘가 보고 뒤집을 수 있다. 지휘가 뒤집으면 그 값은 고정이 되고 관리자는 그 판단을 일지에 「뒤집힘」으로 남겨 같은 처치를 되풀이하지 않는다.
- 실패 꼴과 막는 장치:

| 실패 꼴 | 막는 장치 |
|---|---|
| 틀린 판단 | 단계적 권한(판정만 → 되돌릴 수 있는 것 → 넓히기), 손잡이마다 `until` 자동 만료, 결정마다 「결과 확인 시각」과 되돌리는 명령을 일지에 미리 적음 |
| 같은 처치 되풀이 | 일지의 (계기 지문, 처치) 쌍 중복 막기 — 같은 쌍은 창(기본 2시간) 안에 다시 하지 않고, 두 번 효과 없으면 사람에게 넘김 |
| 흔들기(배분을 계속 바꿈) | 손잡이별 최소 유지 시간(예: 자리 조정 30분), 한 바퀴에 바꾸는 손잡이 수 상한 |
| 비용 폭주 | 셸 거름, 하루 깨움 상한(손잡이), 사건 폭풍은 묶어 한 번(지금 idle 묶음과 같은 꼴), 상한에 닿으면 「판정만」으로 내려가고 지휘에 알림 |
| 관리자 멈춤 | hc-job-server가 지킴(멈춘 루프 5400초 → 다시 띄움 — 지금 루프와 같은 길). 관리자가 없으면 운영 사건이 지휘로 돌아감(대비 길) |
| 관리자 꺼도 값이 남음 | 관리자가 쓴 값은 모두 `until`이 있어 저절로 설정 값으로 돌아감. `mode off`면 관리자가 쓴 값 전부 즉시 무효 |
| 질문 창으로 멈춤 | 이름에 `loop`(예: `ops-loop`) — 전역 훅 `loop-no-question`이 질문 창을 막음 [확인: 전역 지침] |

- 깨어날 때 모델 [추론]: 판단 = Opus 5.5 high(전역 표 「판단이 필요한 조사·실측·원인 추적」). 셸 거름은 모델 없이. 상태 훑기만 하는 깨움(「바뀐 것 없음」 확인)을 모델로 하지 않는 것이 비용의 대부분을 줄인다.

## 3. 권한의 경계

> **보관 — 지금은 만들지 않는다**(상주 관리자의 권한 경계. 고정(pin)·기한(until)은 [손잡이](knobs.md)가 이미 쓴다).

기준: 되돌릴 수 있는가 · 영향 범위(기계 한 대 / 전 기계 / 저장소 기본 가지 / 바깥) · 틀렸을 때의 값. 사용자 규칙(되돌릴 수 없는 일·승인 밖 공개·배포는 묻는다, 권한·승인·훅을 우회하지 않는다, 찾아낸 프로세스를 죽이지 않는다, 로그인·계정 파일을 기계끼리 복사하지 않는다)은 모든 단계에서 위에 선다.

### 3-1. 혼자 해도 되는 것 (일지에만 적고, 주인 지휘에 한 줄)

| 행동 | 영향 | 되돌리기 | 상한 |

### 3-3. 사람에게 물어야 하는 것

- **되돌릴 수 없는 것**: 가지·작업 트리·참조를 gc 규칙 밖에서 지우기, 큐 표식·반송 기록 지우기, 강제 push, `reset --hard`·`clean`, 백업 폴더 지우기, 기록 파일 지우기.
- **바깥에 닿는 것**: 공개 저장소 내보내기(`herdr-tools-publish`)·공개 릴리스 — 지금 배포에 묶여 있음, 메일·메시지 발송, 다른 저장소(제품 저장소)의 기본 가지에 레인 밖 길로 쓰기.
- **권한·안전 장치**: 훅 끄기·`disableAllHooks`·편집 가드 우회, pre-push 관문 바꾸기, 권한·승인 모드 바꾸기, `sweep.orphan_kill` 켜기, ㉮ 값 바꾸기.
- **프로세스·계정**: 자기가 띄우지 않은 프로세스 죽이기(찾아낸 pid), 로그인·계정·풀 파일 복사, 키체인 일.
- **넓게 바꾸는 것**: 「스스로 배포」 켜기, 관리자 단계 올리기, 기계를 망에서 빼거나 더하기, 사용자 지침(`CLAUDE.md`·`~/.claude/docs`) 고치기, 비용 상한 올리기, 루프(문의·오류) 켜고 끄기.
- **판단할 수 없는 것**: 두 번 처치해도 안 풀린 문제, 원인을 모르는 병합기 반복 사망, 충돌 푸는 방향이 사용자 뜻에 걸린 herdr-sync 충돌.

### 4-3. 사건 종류 (알림)

지금 [확인]: 사건은 기계마다 `events.tsv` 한 줄(시각·기계·터미널·레인·상태·sha·한 줄·turn·받을 지휘·키), 상태 = 중간·완료·착지·막힘·판정·제출(+ 도구가 적는 정리됨·멈춤). 운영 사건은 가짜 레인 이름으로 섞인다.

### 4-4. 결정 일지

[추론 — **ops-journal**] 지휘 기계 `~/.local/state/herdr-ops/decisions.tsv`(+ 사람이 읽는 `decisions.md` 같은 내용) 한 줄 = 결정 하나:

| 칸 | 뜻 |
|---|---|
| id · 시각 | `d<초 36진>` |
| 누가 | `manager` / 지휘 주소 / `human` |
| 모드 | shadow(했을 것) / act |
| 계기 | 사건 키들 · 상태 지문 |
| 본 것 | 판단 근거 한두 줄(수치) |
| 처치 | 실제 명령 한 줄(그대로 다시 칠 수 있게) |
| 되돌리는 명령 | 한 줄 |
| 기대 효과 · 확인 시각 | 「30분 뒤 대기 0」 같은 잴 수 있는 꼴 |
| 결과 | 확인 때 채움: 효과 있음 / 없음 / 뒤집힘(누가) / 되돌림 |
| 쌍 지문 | (계기 종류·대상, 처치 종류) — 되풀이 막기 열쇠 |

명령: `hc-fill decide add …`(관리자가 씀) · `decide ls [--due]` · `decide revert <id>`(되돌리는 명령을 실행하고 「되돌림」 적음) · `decide override <id> --why`(지휘·사람 — 뒤집힘 적고 해당 손잡이를 고정). 같은 쌍 지문이 창 안에 있으면 `add`가 거절(관리자가 되풀이 못 함), 「효과 없음」 두 번이면 그 쌍은 사람에게 넘기는 사건.

## 5. 단계

> **보관 — 지금은 만들지 않는다**(상주 관리자의 단계. 단계 0 「바닥」만 지금 방향과 같다).

| 단계 | 켜는 것 | 켜는 조건 | 끄는 스위치 |
|---|---|---|---|
| 0 바닥 | 눈(상태 한 장)·손(공통 손잡이)·알림 갈래·일지 — 관리자 없음. 지휘가 손잡이로 직접 조정 | 위 레인들 착지·배포 | 각 명령은 사람이 안 쓰면 그만 |
| 1 판정만 | 관리자 루프가 깨어나 「했을 처치」를 일지에 `shadow`로만. 운영 사건은 여전히 지휘에게도 감(겹쳐 봄) | 단계 0 끝 | `herdr-ops` 모드 파일 `off` |
| 2 되돌릴 수 있는 것 실행 | 3-1 목록만 실행(만료 있는 손잡이·retry·다시 띄우기). 운영 사건은 관리자에게만(지휘는 대비 길) | 판정만 3일 이상 · 지휘가 본 shadow 결정 가운데 「틀림」 표시 0~1 · 일지 되풀이 막기 작동 확인 · 하루 깨움 비용이 상한 안 | 모드 `shadow`로 내림(관리자가 쓴 손잡이는 `until`로 저절로 돌아옴, `off`면 즉시 무효) |
| 3 넓히기 A | 도구 배포·되돌리기(공개 뗀 길)·운영 수정 레인 넣기(위험 영역 밖, 하루 상한) | 단계 2를 1주 · **사용자 승인 「스스로 배포」** · deploy-publish-split 착지 · 되돌리기를 실제로 한 번 연습 | 스스로 배포 손잡이 끔 / 모드 `act-a` |
| 4 넓히기 B | 자가 점검 루프의 「요청할지」를 관리자에게(루프는 센서만) · 흔들림 격리 요청 · 코어 판 맞추기 · 다른 프로젝트(제품 저장소)의 기계 배분 | 단계 3을 1주, 사용자 확인 | 모드 `act-a` |

자가 점검 루프가 `dryrun` 파일 하나로 판정만 모드를 시작한 것과 같은 결로, 관리자도 `~/.local/state/herdr-ops/mode` 파일 한 줄이 단계를 정하고 지우면 `off`다.

## 6. 더 만들어야 하는 레인 (대기 레인 밖)

| 레인 | 하는 일 | 자리 | 크기 [추론] | 앞뒤 |
|---|---|---|---|---|
| **ops-knobs** | 공통 손잡이 저장(git 밖, by·why·until·pin), `hc-fill knob set/ls/unset`, hc-fill 바퀴가 `hc-fill.tsv` 위에 덮어 읽음, 원격 기계용 값은 `refs/herdr/knobs`로 옮김 | cmd/hc-fill 새 파일 + docs | 중(Go 400~600줄 + 시험) | **fill-load-steer·merger-alive·fill-auto-submit·deploy-log-rollback 앞**, 또는 그 지시문에 「손잡이는 ops-knobs 꼴로」 한 줄 |
| **ops-state** | `hc-fill state --json`: 위 4-1 칸을 모으고 상태 지문을 냄(부족한 칸은 각 레인 명령을 부름) | cmd/hc-fill 새 파일 | 중(400줄) | 위 눈 레인들 뒤 |
| **ops-events** | 사건 `kind=ops:<종류>` 칸, watch `--ops`, 관리자가 살아 있으면 지휘 watch는 운영 사건 건너뜀, 가짜 레인 이름 정리(읽는 쪽 호환) | cmd/hc-lane watch·report, hc-sweep·hc-merger·hc-fill의 사건 쓰는 자리 | 중(300줄, 여러 꾸러미 — watch 레인 둘 뒤) | watch-project-route·watch-idle-open 뒤 |
| **ops-journal** | 결정 일지 + `decide add/ls/revert/override`, 쌍 지문 되풀이 막기, 확인 시각 사건 | cmd/hc-fill 새 파일 | 소~중(250줄) | ops-knobs 뒤 |
| **merger-knobs-live** | 병합기가 바퀴마다 `refs/herdr/knobs`에서 묶음·추측 기다림·미리 줄 값·검증 기계 순서를 읽음(환경 변수는 기본값으로 남음) | cmd/hc-merger | 소(150줄) | ops-knobs·merger-alive 뒤 |
| **deploy-publish-split** | herdr-sync의 기계 배포와 공개(릴리스 올리기·`herdr-tools-publish`)를 떼어, 공개는 손잡이·명령 따로. 릴리스가 공개 저장소에만 있으면 바이너리 받을 자리를 비공개로 옮길지 정해야 함(아래 사용자 결정 2) | cmd/herdr-sync | 소~중(200줄) | deploy-log-rollback 뒤 |
| **sweep-knobs** | hc-sweep R1·R2·R3 문턱을 개인 설정 키로(기본값 그대로) | cmd/hc-sweep | 소(50줄) | worker-health-sweep 뒤 |
| **ops-manager-loop**(개인 저장소) | 관리자 지시문(권한 경계 3장 그대로) · hc-job-server launchd 등록(이름에 `loop`) · 셸 거름(상태 지문 같으면 모델 안 부름) · 모드 파일 · 하루 깨움 상한 · 결과 확인 시각 처리 | 개인 저장소 bin·launchd·지시문 | 중(셸·지시문, 지금 자가 점검 루프 틀 재사용) | 위 다섯 뒤, 단계 1로 시작 |

**지금 당장 할 일 [추론]**: 대기 중인 fill-load-steer·merger-alive·fill-auto-submit·deploy-log-rollback 지시문에 「실행 중 손잡이는 공통 저장(ops-knobs 꼴: 지휘 기계 `~/.local/state/herdr-ops/knobs.tsv`, by·why·until)에 두고, 없으면 그 약속대로 최소판을 만든다」를 덧붙이거나(대기 중이라 `hc-fill edit`로 가능), ops-knobs를 먼저 넣어 그 넷의 선행으로 건다. 안 하면 손잡이 자리가 넷으로 갈라져 관리자가 넷을 따로 읽어야 한다.

## 7. 사용자가 정할 것 (다섯)

1. **관리자의 꼴과 자리** — 추천: (다) 섞음, 상주 관리자 하나를 **지휘 기계**에(루프 기계는 hc가 지휘 기계를 몰라 안 됨). 다른 안: (가) 지금처럼 지휘 세션만.
2. **스스로 배포와 공개** — 배포가 지금 공개 저장소 릴리스·내보내기와 묶여 있다. 추천: 배포(기계에 깔기)와 공개(공개 저장소)를 떼고, 관리자는 단계 3부터 **배포만** 스스로(되돌리기 있음), 공개는 지금처럼 사람·지휘가. 다른 안: 배포도 늘 묻기 / 공개까지 스스로(승인 범위 확장).
3. **관리자 비용 상한과 모델** — 추천: 판단 깨움은 Opus 5.5 high, 바뀐 것이 없으면 모델을 부르지 않는 셸 거름, 하루 깨움 상한 48(손잡이). 다른 안: Sonnet 5.5 medium으로 싸게(판단 질 낮음) / 상한 없음.
4. **지휘와 관리자가 다를 때** — 추천: 지휘·사람이 정한 값은 고정(pin)이라 관리자가 못 바꾸고 「풀어도 되나」만 묻는다. 운영 사건은 관리자가 살아 있으면 관리자에게만(지휘에는 한 줄 결과). 다른 안: 관리자 판단이 앞섬 / 운영 사건을 지휘에게도 계속.
5. **판정만에서 실행으로 넘어가는 조건** — 추천: 판정만 3일 이상, 지휘가 본 shadow 결정에서 「틀림」 0~1, 비용 상한 안 → 단계 2(되돌릴 수 있는 것만). 단계 3(배포)은 그 뒤 1주와 사용자 확인. 다른 안: 판정만 1일 / 사람 확인 때마다.
