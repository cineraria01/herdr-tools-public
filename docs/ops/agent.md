# 운영 에이전트 (hc-fill agent)

- 손댈 것([hc-fill advise](advise.md))에 새 항목이 생기면 hc-fill 바퀴가 AI 에이전트를 **한 번** 띄워 판단·조치하게 하고, 끝나면 결과를 일지·사건으로 남긴다(2026-11-24 ops-agent).
- 왜: 사용자 「난 지금과 같은 판단 자체를 에이전트가 빠르게 최대한 해서 난 문제 없이 빠르게 모두 완료되도록 하는게 허더툴스의 기능이야」.
  워커 넷이 노는데 남은 레인이 한 줄 사슬이었고, 지휘는 사람이 물은 뒤에야 사슬을 풀었다. 재는 것(advise·state)·손(knob·edit·machine·nudge …)·기록(journal)은 있었지만 그것을 쓰는 주체는 사건을 받을 때만 움직이는 지휘 세션뿐이었다.
- 상주 대화가 아니라 일이 있을 때 한 번 뜨고 끝나는 실행이다(자동 감사 줄과 같은 꼴). 판단은 에이전트가, 켜고 끄기·문턱은 손잡이가 정한다. 사람의 손 지시는 그대로다(사람과 에이전트가 같은 명령).

## 켜는 법

1. 설정 `hc-fill.tsv`에 띄울 명령 한 줄 `ops_agent_launch <sh 명령>`(본보기 `config.example/hc-fill.tsv`). 범용 저장소는 에이전트 CLI를 모른다 — 개인 값이다.
   - `sh -c`로 부르고 환경을 준다: `HC_FILL_AGENT_RUN`(실행 표식) · `HC_FILL_AGENT_NAME`(`hc-fill-agent`) · `HC_FILL_AGENT_DIR`(작업 폴더 `<DATA>/ops-agent/work`) · `HC_FILL_AGENT_BRIEF`(지시문).
   - 60초 안에 돌아와야 하고, 표준 출력 첫 줄이 터미널 주소다(병합기 충돌 풀이의 `resolve_launch`와 같은 꼴).
   - **실행 표식을 에이전트 환경까지 넘긴다** — `hc run`은 부른 쪽 환경을 넘기지 않으니 `-- env HC_FILL_AGENT_RUN="$HC_FILL_AGENT_RUN" <에이전트 CLI> …`. 표식이 없어도 도는 실행의 터미널(`HC_TERMINAL_ID`)이면 관문이 알아본다 — 이 기계에 띄운 터미널(주소 `tN`)일 때만이다. 다른 기계에 띄웠으면(`기계/tN`) 터미널 ID가 기계마다 따로라 표식만 믿는다.
2. 틀 `<설정 폴더>/ops-agent.md`(본보기 `config.example/ops-agent.md` — 역할·쓸 명령·스스로 할 것과 넘길 것·끝낼 때 할 일).
3. 손잡이 `hc-fill knob set ops_agent 판단만 --why …`(처음에는 판단만으로 일지를 읽고, 맞으면 `조치`).

셋 가운데 하나라도 없으면 띄우지 않는다. `hc-fill agent status`가 무엇이 빠졌는지 보인다.

## 한 바퀴

- hc-fill `run` 바퀴가 `advise_every`분(0이면 바퀴마다)마다 손댈 것을 다시 본다. 판정 못 함(`unknown`)은 빼고, `ops_agent_scope`(프로젝트 목록) 밖 항목도 뺀다(프로젝트를 모르는 항목 — 배포·기계·감시 — 는 늘 든다).
- **새 항목**(이 운영 에이전트에 맡긴 적 없는 열쇠, 또는 지난번에 못 띄웠거나 시간을 넘긴 것)이 있으면 띄운다. 시간당 `ops_agent_max_hour`번까지(못 띄운 것도 센다 — 폭주 막기).
- 한 번에 하나다 — 도는 실행이 있으면 띄우지 않고, 바퀴와 `hc-fill agent run`은 같은 잠금(`<DATA>/ops-agent/lock`) 안에서 띄운다.
- 실행 폴더 `<DATA>/ops-agent/<실행 ID>/`: `items.json`(advise --json 꼴, 범위 안 항목 전부) · `state.json`(state --json 꼴) · `brief.md`(틀 + 「이번 바퀴」 절 — 실행 ID·방식·상한 시각·두 json 경로·맡긴 항목·결과 파일 경로) · `result`(에이전트가 씀).
- 띄우기 실패·지시문 못 씀은 바퀴를 막지 않는다 — 일지에 「실패」를 남기고 다음 바퀴에 다시.
  - 띄우기 실패의 「실패」 줄에는 까닭(띄울 명령의 표준 오류와, 종료 0이 아니면 주소 대신 온 표준 출력 첫 줄)을 앞 200자까지 붙인다 — 개인 값 무늬(`private-patterns.txt`)로 가린 뒤. 무늬를 못 읽으면 글은 안 붙이고 launch.err를 가리킨다.
  - 원문 전체(종료 코드·표준 출력·표준 오류)는 실행 폴더의 `launch.err`에 둔다.
  - 못 띄움은 같은 항목 상한(`ops_agent_tries` — 떠서 못 푼 것)으로 **세지 않는다**: 셌더니 띄울 명령이 고장 나면 모든 새 항목이 두 번 만에 「사람이 정한다」로 넘어갔다(2026-11-24 ops-agent-relaunch).
    대신 못 띄움이 `ops_agent_tries`번 이어지면 운영 사건 한 번 「운영 에이전트를 못 띄움 n번 이어짐 — <까닭 첫 줄>」 — 뜰 때까지 되풀이하지 않고, 뜨면 셈을 비운다.
- 바퀴의 띄우기는 run 잠금 안이다 — 띄울 명령이 돌아올 때까지(상한 60초) `add`·`edit`가 기다린다. 띄울 명령은 `hc run --bg`처럼 바로 돌아오게 둔다.
  띄울 명령이 돌아온 뒤 상태를 쓰기 전에 바퀴가 끊기면 그 실행을 기록하지 못해 다음 바퀴가 하나를 더 띄울 수 있다(창은 상태 파일 한 번 쓰는 동안 — 남은 차이).
- `advise_every`는 손댈 것 사건과 같이 쓴다. 0이면 사건은 끄지만 켜 둔 운영 에이전트는 바퀴마다 본다(재료를 바퀴마다 모은다).

## 끝 처리

- 끝 = 결과 파일이 생김 · 터미널이 끝남 · 띄운 지 2분 뒤 터미널 상태가 `done`·`idle`(대화형 CLI는 턴을 끝내도 터미널이 남는다 — 자동 감사와 같은 판정, 결과 없음) · `ops_agent_timeout`분 넘김(모름이면 상한까지 기다린다). 끝난 실행의 조치 명령은 관문이 거절한다.
- **끝난 실행의 터미널은 대기열이 닫는다**(손잡이 `ops_agent_close`, 기본 1 — 2026-11-24 ops-agent-relaunch).
  - 왜: 첫 실행의 터미널(`hc-fill-agent`, done)이 몇 시간 남아, 같은 이름으로 띄우는 다음 실행 다섯 번이 모두 `name_taken`으로 실패했다. hc-sweep은 레인 작업 트리가 아닌 이 터미널을 닫지 않았다.
  - 무엇을: 그 실행을 띄울 때 상태에 적은 **주소** 하나(이름으로 찾지 않는다). 다른 기계 주소(`기계/tN`)면 hc가 그 기계로 보낸다.
  - 그 주소의 터미널이 이미 끝났거나 없으면 할 일 없음. 지금 이름이 띄울 때 준 이름(`HC_FILL_AGENT_NAME`)과 다르면 그 실행 것이 아니라 안 닫고 일지 한 줄.
  - 언제: 끝 처리 직후. `hc get`이 모름이거나 `hc kill`이 실패하면 사건이 아니라 일지 `agent 닫기` 한 줄이고, 다음 띄우기 직전에 한 번 더 닫아 본다(그동안 `agent status`에 「못 닫은 앞 실행 터미널」).
  - 일하는 중(`working`)인 실행은 끝이 아니라 닫지 않는다(새로 띄우지도 않는다). 시간 넘김은 끝이라 일하는 중이어도 닫는다.
- 결과 파일: 첫 줄 = 한 줄 요약 · `사람이 정한다: …` 줄은 사건(`막힘`, 한 바퀴에 다섯까지) · `하려던 것: …` 줄은 일지(hc-fill 밖 명령을 판단만으로 둔 것).
- 사건 [hc-fill-agent](events.md) 「운영 에이전트 끝: <요약> (<끝 까닭>, <방식>, 손댈 것 n개, 일지 hc-fill journal --by <주소>)」와 일지 `agent 끝` 한 줄.
- 같은 항목이 그대로면:
  - 결과 파일까지 끝난 실행이 본 항목 — **다시 띄우지 않는다**(에이전트가 이미 판단했다. 못 한 것은 「사람이 정한다」로 넘겼어야 한다).
  - 떠서 시간 넘김·결과 없이 끝남으로 `ops_agent_tries`번 띄운 항목 — 더 띄우지 않고 「사람이 정한다: <항목> — n번 띄웠는데 못 풀림」 사건 한 번(못 띄움은 이 셈에 안 든다 — 위 「한 바퀴」).
  - 목록에서 사라진 항목은 잊는다(다시 생기면 새 항목 — advise와 같은 뜻). 목록을 읽었고 없을 때만이다 — 그 항목을 가릴 수 있는 「판정 못 함」이 그 바퀴에 있으면(재료 `hc` 못 읽음, 같은 기계·병합기·감시·배포의 모름 등) 모름이라 기록을 그대로 둔다(지웠더니 회복 뒤 처음인 것처럼 다시 띄워 `ops_agent_tries`가 안 먹었다, 2026-11-24 ops-gate-tighten). 재료 `deploy`의 모름은 배포 항목만 붙든다(이 기계에서 배포한 적 없으면 늘 모름이다).
- 실행 중에 띄울 명령이나 틀이 바뀌었으면(띄울 때 적은 지문과 다름) `ops_agent`를 `끔`으로 두고 「사람이 정한다」 사건 — 에이전트가 자기 권한을 넓히는 길을 막는다.

## 손잡이

| 손잡이 | 기본 | 뜻 |
|---|---|---|
| `ops_agent` | `끔` | `끔` · `판단만`(hc-fill 조치 명령을 일지에 「하려던 것」으로만 — 안 먹음) · `조치` |
| `ops_agent_max_hour` | 2 | 시간당 띄우는 상한(못 띄운 것도 셈) |
| `ops_agent_timeout` | 20분 | 한 바퀴 상한 — 넘으면 끝난 것으로 보고 그 실행의 조치 명령을 거절 |
| `ops_agent_tries` | 2 | 같은 항목으로 띄우는 상한(떠서 시간 넘김·결과 없이 끝남) — 넘으면 「사람이 정한다」 한 번. 못 띄움이 이만큼 이어지면 운영 사건 한 번 |
| `ops_agent_close` | 1 | 끝난 실행의 터미널을 그 주소로 닫음(0이면 안 닫음 — 같은 이름으로 다시 띄우면 실패) |
| `ops_agent_scope` | `-`(전부) | 볼 프로젝트(쉼표) |

- 이름이 `agent`가 아닌 까닭: hc-fill 설정 `agent`(에이전트 CLI 종류)가 이미 있고, 손잡이는 같은 이름의 설정 줄을 덮는다.
- 바꾸면 다음 바퀴부터 먹고 일지에 남는다([손잡이](knobs.md)). 끄기: `hc-fill knob set ops_agent 끔 --why …`(또는 `knob unset ops_agent`) — 도는 실행의 조치 명령도 그때부터 거절된다.

## 넘길 것의 선

틀(에이전트가 읽음)과 코드(관문) 양쪽에 있다. 관문은 `hc-fill` 명령에만 먹는다 — 다른 도구(`herdr-sync`·`hc`·`hc-lane`)는 틀이 정하고, 「판단만」이면 결과 파일의 「하려던 것」으로 적게 한다.
관문은 정직한 에이전트를 가정한다: 실행 표식과 터미널 ID를 지운 채(`env -u …`) 부르거나 설정 `hc-fill.tsv`의 `ops_agent*` 줄을 직접 고치는 것은 막지 못한다(띄울 명령·틀이 바뀐 것만 끝 처리의 지문이 알아챈다).

| | 무엇 |
|---|---|
| 스스로 | 되돌릴 수 있는 운영 조정 — 선행·겹침·우선(`edit`·`prio`), 기계 자리·쉬게 하기(`machine`), 손잡이(`ops_agent*` 말고), `nudge`·`note`·`retry`, 다시 내는 레인 넣기(`add`), 병합기 다시 띄우기(`merger restart`), 이미 승인된 길의 배포(`herdr-sync`) |
| 사람에게 | 레인 지우기, 남의 프로세스 끄기, 되돌릴 수 없는 일, 승인 범위 밖 공개, 권한·훅·보호 규칙 바꾸기, 자기 손잡이(`ops_agent*`)·띄울 명령·틀 바꾸기 |

관문(`hc-fill`이 하위 명령마다 앞에서 본다 — 운영 에이전트 실행이 부른 것만, 사람이 부른 것은 그대로):

- 읽는 꼴은 그대로 — `ls [--json]` · `status [--mine | --owner <주소>]` · `state [--json] [--all]` · `advise [--json]` · `journal [--json] [--by …] [--since …]` · `knob ls [--json]` · `machine`·`machines [--json]` · `agent status [--json]`.
  허용 목록이다: 이 꼴 밖의 인자가 하나라도 붙으면 쓰기로 본다(새 쓰기 인자가 생겨도 새지 않게 — 쓰기 인자 목록을 두었더니 `machine --rename`이 읽기로 샜다, 2026-11-24 ops-gate-tighten).
- 미리 보기(`--dry-run`을 실제로 받는 `prio`·`rm`·`knob`·`machine`·`run`)도 그대로. 다른 명령의 `--dry-run`은 그 명령이 값으로 읽어 본 동작을 하니 조치로 본다(`nudge <레인> --dry-run`도 판단만이면 「하려던 것」).
- 넘길 것 종류 — `rm`, `knob set|unset ops_agent*`, `--force`(`knob`·`machine` — 고정한 손잡이 덮기), `machine --rename`(기계 이름 바꾸기 — 되돌리기 어렵다), `agent run`, `run`·`watch`·속 명령(`_…`) — 는 어느 방식이든 거절(종료 1)하고 일지 `거절`·사건 「사람이 정한다: 운영 에이전트(<ID>)가 「<명령>」를 치려 함 — <까닭>」.
- 끝난 실행(실행 ID가 도는 실행과 다름 — 시간 넘김 뒤 등)·실행 상한 지남(상태의 상한 시각이 지났으면 바퀴가 아직 끝 처리를 안 했어도 — 바퀴가 멈춰도 새지 않게)·꺼짐이면 거절.
- `판단만`이면 그 명령을 하지 않고 일지에 `하려던 것`(대상 = 하위 명령, 왜 = `--why`, 상태 = 친 명령 줄) 한 줄, 종료 0.
- `조치`면 그대로 먹는다 — 일지의 「누가」는 에이전트 터미널 주소.

## 명령

- `hc-fill agent status [--json]` — 방식·띄울 명령/틀 있음·시간당 수/상한·상한 시간·같은 항목 상한·범위, 도는 실행(ID·주소·시각·맡긴 항목), 항목마다 띄운 수·끝까지 봄·사람에게 넘김, 최근 바퀴 10개.
  - json 칸: `mode` · `launch` · `template` · `run`(없으면 `null` — `id`·`addr`·`mode`·`dir`·`hash`·`by`·`started`·`deadline`·`keys`) · `hour_count` · `hour_max` · `timeout_min` · `tries_max` · `scope` · `keys`(열쇠 → `tries`·`done`·`asked`·`summary`) · `recent`(`id`·`start`·`end`·`result`·`summary`·`keys`) · `launch_fails`(못 띄움이 이어진 수) · `left`(못 닫은 앞 실행 터미널 주소, 없으면 `""`).
- `hc-fill agent run [--why <까닭>]` — 사람이 지금 한 바퀴. 시도 기록·시간당 상한과 상관없이 지금 범위 안 항목 전부를 맡긴다. 꺼져 있으면·도는 실행이 있으면·설정이 없으면 까닭과 종료 1, 항목이 없으면 「손댈 것 없음 — 안 띄움」 종료 0.
- 상태는 `<DATA>/ops-agent/state.json` 하나(손으로 고치지 않는다).

## 비용 가늠

- 꺼져 있으면 바퀴마다 손잡이 하나 읽기뿐이다.
- 켜면 `advise_every`분마다 상태 한 장과 같은 재료(`hc ls --json`·`hc machine ls --json` 한 번씩, 배포 판마다 `git rev-list` 한 번)를 한 번 더 읽는다. 도는 동안은 바퀴마다 `hc get` 한 번.
- 에이전트 한 바퀴의 값(모델 호출)은 띄울 명령의 CLI·모델이 정한다 — 시간당 `ops_agent_max_hour`번 × 한 바퀴 상한 `ops_agent_timeout`분이 위 끝이다. 같은 항목에는 다시 안 띄우니, 조용한 날은 0번이다.
