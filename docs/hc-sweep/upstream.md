# hc-sweep: 상대 판 확인 (Claude·hc 판이 바뀌면 실물로 다시 대조)

- **왜**(ht-upstream-contract, 2026-11-28 — 사용자 「문제점들 다 고치자」 → 「다섯 묶음 모두 (추천)」): herdr-tools는 에이전트 CLI(Claude)와 hc의 문서화되지 않은 동작(세션 파일·기록 자리·끝 표시·hc get 칸·화면 글자)에 기댄다.
  Claude는 스스로 올라가고(11-24·25 맥 아홉 대가 한꺼번에 새 판, 리눅스 두 대는 옛 판) 그것을 적거나 알리는 장치가 없었다 — hc 0.1.22의 not_found 출력이 표준 오류로 옮겨 가 병합기가 3일 막혔고, 2026-11-28 화면 끝 글자와 상태 done을 믿고 일하던 터미널을 닫았다.
- **방식**: 업계의 계약 시험(contract test) — 기대(쉼 판정이 맞는 답을 내는가)를 목록으로 두고, 상대 판이 바뀔 때마다 진짜 상대에게 돌려 본다. 가짜 자료로만 시험하면 상대가 바뀐 것을 모른다.

## 판 기록

- 판 묶음 = 세션의 Claude 판(세션 파일 `~/.claude/sessions/<pid>.json`의 `version` — 2026-11-29 실측 `2.1.332`) × 그 기계 hc 판(`hc --version`의 끝 칸). 이름은 `claude-<판>_hc-<판>`(사건 키 글자 밖은 `-`).
- 바퀴마다 [건강 점검](health.md)이 도는 김에(macOS, `HC_SWEEP_HEALTH=off`면 끔) 살아 있는 세션 파일들의 판과 hc 판을 읽어 `~/.local/state/hc-sweep/upstream.json`에 적는다(`internal/upstream` 한 곳 — 잠금 안에서 읽고 고쳐 씀).
- 기록이 없을 때 처음 본 묶음들은 **믿는 기준**이다(보류 없이 시작 — 지휘 정정 2, 어제 하루 실물로 맞춘 판). 세션이 하나도 없으면 기준을 아직 적지 않는다(나중 첫 세션을 「바뀜」으로 읽지 않게).
- 그 뒤 새로 보인 묶음은 **보류**(`pending`)이고 운영 사건 `hc-upstream` 소식 한 번 `에이전트 판 바뀜(<기계>): <옛 묶음> → <새 묶음> — …`(키 `hc-upstream:<기계>:<묶음>:new`, 알림 실패는 다음 바퀴에 같은 키로).
- 판을 못 읽으면(hc --version 실패·꼴이 다름) 모름 — 사건 없음·기록 그대로. 죽은 pid의 세션 파일은 안 본다(옛 판 파일을 새 판으로 읽지 않게).
- 묶음의 수명(감사 atp89b9 중간 1): 바퀴마다 살아 있는 세션의 묶음을 `live`로 적고, 「보류가 있는가」·「점검할 묶음」은 그것만 본다 — 세션이 다 끝난 판은 닫을 것이 없어 보류가 끝난다(묶음 기록은 남겨, 다시 보여도 사건을 되풀이하지 않는다).
  실물 점검은 그 기계 설치본으로 새 세션을 띄우니 **설치본 판**만 잰다: 맡은 묶음과 잰 판이 다르면(설치본과 다른 판으로 도는 옛 세션 — hc를 올릴 때·처음 깔림에 판 둘) 그 묶음은 「잴 수 없음」으로 다시 띄우지 않고, 그 세션이 사는 동안만 보류다.
- 보기: `hc-sweep --upstream`(읽기만 — 묶음마다 상태·마지막 점검 결과·점검 표, 종료 0 보류 없음 · 1 보류 있음 · 3 기록 없음). 손 점검·시험용 사본은 환경 `HERDR_UPSTREAM_FILE=<파일>`(XDG_STATE_HOME을 바꾸면 hc 소켓 자리까지 바뀐다).

## 보류: 확인 전에는 닫지 않는다

- 쉼 판정(`internal/rest` `Of` — [정말 쉬는가](busy-idle.md) 「한 문」)은 세션 파일을 찾으면 그 세션의 판 묶음을 기록에서 본다: 믿음이면 평소대로, 보류·틀림·기록에 없음이면 **모름**(까닭 `이 판은 아직 확인 안 됨(<묶음>)`·`이 판은 실물 점검에서 틀림(<묶음>)`), 세션 판이 비면 `판 모름(…)`, 기록이 깨지면 `판 기록 못 읽음`.
  닫는 길들은 이미 모름이면 닫지 않으니 닫는 길마다 따로 넣지 않았다. hc-sweep의 R3(상태가 r3만큼 그대로)는 지금 규칙대로 모름이어도 닫는다 — 보류가 영영 남지 않는다.
- 한 기계에 판이 둘(옛 세션이 옛 판으로 돎)이면 세션마다 그 세션의 판으로 판정한다. 세션 파일이 없는 셸·다른 CLI는 판과 상관없다(지금 규칙 그대로).
- 기록 파일이 없는 기계(아직 안 깔림·리눅스 — hc-sweep 건강 점검은 macOS만)는 보류 없이 지금 그대로다.
- 멈춘 레인의 Escape([멈춘 레인](../hc-fill/hang.md) (a))도 같은 보류를 따른다: 그 기계에 보류 묶음이 있으면(대기열 기록 `upstream.tsv` 상태 `hold`) 보내지 않고 알리기만 — 화면 글자에 기대는 조치다.
- 보류가 일에 미치는 것(지휘 정정 3 — 지금 모름 규칙 그대로, 덧대지 않았다):

  | 자리 | 보류(모름)일 때 |
  |---|---|
  | 자리 셈·새 레인·감사 띄우기(`machRoom`) | 그대로 — 쉼 판정을 안 본다(시험 `TestUpstreamTickOneAtATime`) |
  | 자동 제출(`autosubmit`) | 대신 제출하지 않고 판정은 전달(ht-autosubmit-busy-wake 그대로) |
  | hc-sweep R2 닫기·끝난 감사·주차·운영 에이전트 닫기·hc-lane clean·hc-job-server | 닫지 않고 다음 바퀴(R3는 닫음) |
  | 떠 있는 끝난 터미널 | 살아 있는 에이전트로 자리를 차지한다(`agentsOn`) — 점검이 몇 분 안에 통과하면 짧지만, 점검이 안 되면 R3(기본 6시간)까지 남는다. 주차 레인 이어 띄우기가 「같은 이름」으로 거절될 수 있다 |

## 실물 점검

- `hc-sweep --upstream-probe -- <에이전트 실행 명령…>`(`{probe}` 자리에 점검 지시가 든다) — 그 기계에서 돈다. 손으로는 예: `hc-sweep --upstream-probe -- example-agent --model cheap '{probe}'`. 종료 0 통과 · 1 틀림 · 3 모름.
- 점검용 세션: 임시 폴더에서 `hc-lane --read`로 띄운다(신뢰 질문·시작 확인). 지시는 「배경 셸 하나(`python3 -c "import time; time.sleep(45)"` — 전경 `sleep`은 Claude가 막는다)·턴을 끝낸 하위 에이전트 하나·턴 끝」, 이어 `hc send`로 전경 명령 하나. 끝나면 그 터미널만 닫는다(이 점검이 띄운 것 — `rest/gate_test.go` 목록에 까닭).
- 대조 목록(닫기·키 보내기로 이어지는 것부터, 판정의 답이 중심 — 지휘 정정 1):

  | 항목 | 맞음이려면 |
  |---|---|
  | 세션 파일 | 터미널 pid 나무에서 `<sessions>/<pid>.json`을 찾고 `sessionId`를 읽음(Claude인데 못 찾으면 틀림) |
  | 판 읽기 | 세션 파일에 `version` |
  | 대화 기록 자리 | `<projects>/*/<세션 id>.jsonl` |
  | 하위 에이전트 기록 · 끝 증거 | `<세션>/subagents/agent-*.meta.json`, 끝난 것은 meta `finished` 또는 자기 기록 끝 턴 |
  | ① 도는 배경 셸 | 턴을 끝낸 뒤 끝 표시 없고 프로세스가 쥔 출력 파일 — 판정 busy |
  | ② 끝난 배경 셸 | 끝 표시가 붙거나 쥔 프로세스가 없음 — 판정 quiet |
  | ③ 도는 전경 명령 | 새 출력 파일을 프로세스가 쥠 — 판정 busy |
  | ④ 죽은 전경 명령 뒤 | 점검이 그 파일을 쥔 파이썬 pid만 정확히 끈 뒤(상한에 걸려 죽은 꼴) 턴이 끝나면 — 판정 quiet(파일이 지워짐·끝 표시·끝 표시 없이 남음 셋 다 quiet여야) |
  | hc get 칸 | `hcjson.ParseGet`이 받는 꼴(상태 낱말이 아는 것 가운데 하나), pid·created_ms·status_ms |
  | (참고) 화면 배경 작업 글자 | 「shell still running」 — 통과에 안 묶음, 틀리면 보고에 |

- 결과: 틀림이 하나라도 있으면 **실패**, 못 봄만 있으면 **모름**, 모두 맞음이면 **통과**. 그 세션의 판 묶음 기록에 표와 함께 적는다.
  통과 → 믿음, 소식 `실물 점검 통과(<기계>): <묶음> — …`(키 `hc-upstream:<기계>:<묶음>:up`) 한 번. 실패 → 틀림(보류 이어짐), 막힘 `실물 점검 틀림(<기계>): <묶음> — 틀린 항목 … — 이 기계에서 이 판 터미널 닫기 보류 중 — 사람이 볼 것: …`(키 `hc-upstream:<기계>:<묶음>`) 한 번 — 같은 묶음에 되풀이 없음, 틀린 묶음은 다시 점검하지 않는다(그 판 세션이 다 끝나면 보류도 끝 — 새 판이 오거나 손으로). 모름 → 기록 그대로·사건 없음.
- 점검용 세션의 주소를 못 받으면(시작 확인 시간 넘김 등) 이번에 만든 임시 폴더를 쓰는 그 이름의 터미널만 찾아 닫는다(감사 atp89b9 낮음 1 — 남으면 다음 시도가 같은 이름으로 거절된다).
- 실측(2026-11-29, Claude Code 2.1.332 · hc 0.1.22, 이 기계 macOS): 모든 항목 맞음, 약 3분, Haiku 한 세션. 그 판의 꼴: 턴을 끝내도 배경 셸이 도는 동안 hc 상태는 `working`(글 「1 shell still running」)이고, 끝나면 Claude가 알림 턴을 한 번 더 돈다 · 전경 명령이 Bash 상한(기본 2분, 손으로 준 timeout)을 넘으면 죽지 않고 배경으로 넘어가 끝 표시가 붙는다 · 끈 전경 명령의 파일은 Claude가 지운다.

## 누가 언제 (대기열)

- 기계마다 hc-lane merger 점검 조각(격리 점검 [점검 항목](../hc-fill/cordon.md) — 2분)에 `probe upstream ok|hold <점검할 묶음|->` 한 줄(`na` 기록 없음, `unknown` 못 읽음). 점검할 묶음은 보류인 것 먼저, 없으면 아직 점검 안 한 기준.
- hc-fill `run`이 격리 점검 뒤 그 줄을 `DATA/upstream.tsv`에 적고, 점검할 묶음이 있는 기계에 **한 번에 한 대만** `hc run --bg --rm --no-parent --name upstream-probe [--on <기계>] -- zsh -lc 'exec hc-sweep --upstream-probe -- "$@"' _ <실행 명령>`을 띄운다(보류 기계 먼저, 그다음 이름순).
  실행 명령은 설정 `upstream_launch`(launch와 같은 틀 — 가장 싼 모델로 두기를 권함), 없으면 `launch` 틀.
- 띄운 점검이 결과를 내기까지(그 기계의 점검할 묶음이 바뀔 때까지, 상한 25분) 다른 기계에 띄우지 않는다 — 처음 깔릴 때 모든 기계의 기준 점검이 한 대씩 차례로 돈다. 같은 판에 두 번 띄우지 않는다.
- 띄우기 실패([띄우기](../hc-lane/launch.md) 「실패 종류」의 일시 — hc run 거절·같은 이름이 살아 있음)·결과 모름은 다음 기회에 다시, 한 묶음에 3번까지. 상한에 닿고 보류면 막힘 한 번 `실물 점검을 3번 띄웠는데 결과가 없다(…)`(키 `hc-upstream:<기계>:<묶음>:cap`). hc run 시간 넘김은 떴을 수 있어 기다린다.
- 띄우지 않는 기계: 연결 안 됨·격리, 그리고 풀 점검을 하는 설정(`worker.proxy`)에서 마지막 풀 판정이 좋음이 아닌 기계(같은 판정 `workermac.PoolUsable` 한 곳 — 에이전트가 못 뜨니 새로 닫을 것도 생기지 않는다. 이미 떠 있는 터미널은 닫지 않는 쪽).
- 토큰: 판이 바뀔 때(그리고 처음 깔릴 때 기계마다 한 번) 세션 하나 — 주기적으로 돌지 않는다.

- 리눅스 워커: hc-sweep 건강 점검이 macOS만이라 기록이 없다(보류 없음, 지금 그대로). 세션 파일·기록 자리는 이 레인에서 못 쟀다(이 워커의 hc에 리눅스 기계가 없다) — 지휘 맥에서 `hc exec --on <리눅스 기계> -- ls ~/.claude/sessions` 로 볼 것.

- 되돌리기: 기록을 지우면(`~/.local/state/hc-sweep/upstream.json`) 그 기계는 다음 바퀴에 지금 판들을 기준으로 다시 적는다(보류 풀림). 한 묶음만 믿게 하려면 손으로 `hc-sweep --upstream-probe`.
